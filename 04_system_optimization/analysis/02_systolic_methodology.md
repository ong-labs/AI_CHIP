# 02_systolic_methodology.md: Systolic Array RTL Analysis Methodology Report Based on the Two-Pass Technique and Seven-Step Pattern

본 보고서는 복잡한 도메인 특화 가속기(DSA) 및 시스톨릭 어레이(Systolic Array) 하드웨어 설계 자산을 처음 접할 때 아키텍트가 길을 잃지 않고 마이크로아키텍처 구조를 신속하게 리버스 엔지니어링할 수 있도록 돕는 표준 **RTL 분석 방법론(RTL Analysis Methodology)** 을 정립하기 위해 작성되었습니다. 대규모 디지털 회로 분석 시 빈번하게 발생하는 인지적 병목을 파괴하고, 시스템 토폴로지와 국소 컴포넌트 거동을 유기적으로 결합하는 공학적 가이드라인을 제공합니다.

---

## 1. RTL 코드 분석의 태생적 한계와 Two-Pass 접근법

처음 대면하는 복잡한 수만 라인의 RTL 코드를 단순 순차적(Sequential)인 탑다운 혹은 바텀업 단선형으로 읽어 내려갈 경우, 다음과 같은 치명적인 인지적 오류에 직면하게 됩니다.

* **무조건적인 Top-down 탐색의 병목**: 최상위 통합 모듈에서 시작해 코드를 한 줄씩 읽다가, 인스턴스화된 하위 컴포넌트 선언부를 만날 때마다 하위 계층 트리(Submodule Tree)로 제어권을 넘기며 무한 루프식 점프를 반복하게 됩니다. 결과적으로 전체 시스템의 데이터 흐름 지도를 유실하는 계층 미로에 빠집니다.
* **무조건적인 Bottom-up 탐색의 병목**: 의존성이 없는 리프 모듈(Leaf Module) 회로 회로부터 완벽하게 독파해 올라가려 시도할 경우, 개별 ALU나 제어 게이트의 동작 원리는 파악할 수 있으나 이 컴포넌트가 최상위 인프라 관점에서 "왜 이 타이밍에 가동되어야 하는지"에 대한 거시적 목적성(Context)을 상실하게 됩니다.

이를 해결하기 위해, 구조적 매핑을 전담하는 1차 패스(Top-down)와 기능적 수치 동작을 해체하는 2차 패스(Bottom-up)를 철저히 분리하여 가동하는 **'Two-Pass 분석 프레임워크'** 를 제안합니다.

## 2. Pass 1: 거시적 시스템 지도 수립 (Top-Down Structural Mapping)

### 2.1 Pass 1의 핵심 목표 및 동작 규칙
* **핵심 질문**: "어떤 물리 하드웨어 블록이, 구체적으로 어느 신호선을 타고 어디에 연결되어 있는가?"
* **최종 산술물**: 시스템 아키텍처 블록 다이어그램 및 전역 데이터플로우 평면도
* **RTL 필터링 규칙**: 각 소스 파일당 최대 30초 이내에 핵심 연결 인터페이스만 스캔 아카이브하며, 내부에 기술된 `always` 블록이나 조합 논리 연산식의 **본문(Body)은 절대로 읽지 않고 스킵**합니다.

### 2.2 고속 구조 필터링을 위한 스캔 가이드
1.  **모듈 명세 및 매개변수 (`module xxx #(...)`)**: 무엇이 하드웨어 파라미터화(DATA_WIDTH, ACC_WIDTH 등)되어 유연성을 확보했는지 파악합니다.
2.  **포트 리스트 (`input / output`)**: 데이터 버스, 제어선, 클럭/리셋 핀의 구성과 정밀도 비트 폭 스펙을 식별합니다.
3.  **하위 인스턴스 (`submodule u_block (...)`)**: 현재 모듈이 자식 계층으로서 어떤 하위 하드웨어 블록들을 품고 배치 제어하는지 인스턴스 명칭만 리스트업합니다.

### 2.3 현재 시스톨릭 어레이 코드베이스 계층도 매핑 적용
최상위 구동 엔진인 `systolic_top.v` 파일에서 Pass 1을 개시하면 다음과 같이 캡슐화된 하위 구조 토폴로지가 한눈에 정돈됩니다.

```text
systolic_top (최상위 가속기 인프라 패브릭)
 ├── weight_loader   : 외부 매트릭스 파라미터 적재 시퀀서
 ├── input_skew      : 시스톨릭 타이밍 정렬용 스큐 제어 셔플러
 ├── pe_array        : 2차원 연산 가속 그리드 패널
 │    └── mac_prod   : 가중치 고정형(WS) 하드웨어 연산 소자 (Leaf Cell)
 └── output_collect  : 완결된 출력 부분합 버스트 수집기
```

### 2.4 시스템 관점의 3대 전역 데이터 흐름 경로 (Dataflow Overview)

Pass 1 완료 기점에서 아키텍트는 저수준 회로 지식이 없더라도 하드웨어 시스템의 데이터 이동 파이프라인 경로를 다음과 같이 명밀하게 한 줄 요약 체계로 정의할 수 있어야 합니다.

* **가중치 공급 경로 (Weight Path)**:
`weight_matrix` $\rightarrow$ `weight_loader` $\rightarrow$ 가속 플랫 신호선 구동 (`load_weight_flat`)
* **액티베이션 입력 경로 (Activation Path)**:
원본 데이터 주입 (`act_in_flat`) $\rightarrow$ 시간 축 동기 격자 변환 (`input_skew`) $\rightarrow$ 시간 정렬된 스트리밍 버스 생성 (`act_skewed`)
* **컴퓨팅 가속 및 수집 경로 (Compute & Collect Path)**:
(`load_weight_flat` + `act_skewed`) 결합 $\rightarrow$ 이 차원 병렬 가속 연산 그리드 가동 (`pe_array: 4×4 mac_prod`) $\rightarrow$ 결과 레지스터 적재 (`output_collect`) $\rightarrow$ 최종 유효 행렬 출력 버스트 백엔드 반환 (`result_flat` + `valid_out`)

## 3. Pass 2: 하위 유닛 기능 해체 (Bottom-Up Functional Analysis)

### 3.1 왜 Bottom-Up 스케줄링인가?

Top 모듈부터 세부 구현을 파고들면 레퍼런스 참조 점프 오버헤드가 발생하여 지식이 뇌 내부에서 단편화됩니다. 반면 의존성이 없는 리프 셀(Leaf Cell)부터 거꾸로 조립해 올라가는 바텀업 방식을 사용하면, 하위 블록의 기능적 정합성을 100% 장악한 상태에서 상위 계층을 보기 때문에 복잡한 오케스트레이션 로직이 매우 단순한 블록 조립 과정으로 투명하게 이해됩니다.

### 3.2 의존성 트리에 기반한 최적의 순차 분석 시퀀스 명세

| 분석 순서 | 타겟 Verilog 소스 파일 | 마이크로아키텍처적 부품 정체성 | 순차 배치 선정에 대한 공학적 근거 |
| --- | --- | --- | --- |
| **1** | **`mac_prod.v`** | 가중치 고정형 시스톨릭 셀 | 하위 하드웨어 참조 의존성이 전혀 없는 최하단 원자 리프 컴포넌트 |
| **2** | **`input_skew.v`** | 타이밍 정렬용 Shift Register | 순수 직렬 플립플롭 체인 구조로 이뤄진 단순 지연 제어 유닛 |
| **3** | **`weight_loader.v`** | 로드 명령 제어 Sequencer | 카운터 연산을 기반으로 타일 경계를 통제하는 소형 유닛 |
| **4** | **`output_collect.v`** | 결과 데이터 버퍼 수집기 | 가속 어레이 하단 신호를 바이패스 적재하는 직관적 컴포넌트 |
| **5** | **`pe_array.v`** | 2차원 시스톨릭 가속 매트릭스 | 앞서 1단계에서 마스터한 `mac_prod.v` 코어 셀을 대규모 구조 복제 배치하는 중간 계층 |
| **6** | **`systolic_top.v`** | 최상위 시스템 가속기 통합 패브릭 | 모든 검증 완료된 독립 유닛들을 최종 엮어내는 전역 오케스트레이션 레이어 |

## 4. 단일 파일 해체를 위한 'Seven-Step Pattern' 프로토콜

모든 독립 Verilog RTL 소스 파일은 컴퓨터 구조학적 규칙에 의거하여 정형화된 **7단계 Seven-Step 패턴** 마진 레이아웃에 맞춰 정밀 분석을 집행합니다.

```text
┌────────────────────────────────────────────────────────────────────────────┐
│  Step 1: Header Comment     ───►  아키텍처적 설계 의도 식별                 
├────────────────────────────────────────────────────────────────────────────┤
│  Step 2: Parameter Setting  ───►  비트 대역 가변 마진 식별
├────────────────────────────────────────────────────────────────────────────┤
│  Step 3: Port Declarations  ───►  물리 핀 인터페이스 정렬 규격 획득
├────────────────────────────────────────────────────────────────────────────┤
│  Step 4: Wire / Reg Clues   ───►  내부 상태 저장 소자 및 신호 배선 추적
├────────────────────────────────────────────────────────────────────────────┤
│  Step 5: assign Statements  ───►  조합 논리 데이터 전이 관계 선행 마스터
├────────────────────────────────────────────────────────────────────────────┤
│  Step 6: always Blocks      ───►  시간 축(Clock Edge) 동기 순차 논리 장악
├────────────────────────────────────────────────────────────────────────────┤
│  Step 7: generate / initial ───►  구조 복제 토폴로지 및 가상 덤프 조건 확인
└────────────────────────────────────────────────────────────────────────────┘
```

### 💡 조합 논리(`assign`)를 순차 논리(`always`)보다 먼저 분석해야 하는 이유

조합 논리 회로(`assign`)는 지연 시간 마진을 제외하면 인가된 입력 신호 변동에 실시간 즉시 반응하는 정적(Static) 수학적 인과 관계 관계식입니다. 반면 `always` 동기식 순차 회로는 클럭 에지라는 시간 축(Time Domain)의 개념과 내부 과거 상태 변수 자산이 개입되어 동적 흐름이 형성됩니다. 따라서 정적인 데이터 전이 뼈대(`assign`)를 먼저 머릿속에 완벽히 매핑해 둔 후에, 클럭 주기 단위의 동적 시프트 상태 전이(`always`)를 추적하는 것이 인지 부하를 최소화하는 유일한 경로입니다.

## 5. 미시적 RTL 제어 흐름 분석 방법론 (Micro-level Tracing)

### 5.1 `always` 분기 구조 완벽 분석 규칙

동기식 순차 회로 블록을 분석할 때는 다음 4대 제어축을 기준으로 삼아 질문을 던지고 타이밍 윈도우를 확정합니다.

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        // rst_n = 0 기점: 비동기 초기화 브랜치 영역
    end else if (en) begin
        // en = 1 기점   : 정상 가동 및 레지스터 상태 업데이트 영역
    end
end
```

1. **감도 목록 (Sensitivity List)**: `posedge clk` 혹은 `negedge rst_n` 명세를 보고, 해당 하드웨어 블록이 언제 하이 레벨 전이 반응을 시작하는지 가동 타이밍 조건을 확정합니다.
2. **초기화 브랜치 (Reset Branch)**: `if (!rst_n)` 구문 내부를 정밀 스캔하여, 시스템 전원 인가 직후 누락 없이 모든 내부 상태 레지스터가 클린한 접지 상태(`0`)로 청소 초기화되는지 무결성을 체크합니다.
3. **활성 제어 브랜치 (Active Branch)**: 글로벌 인에이블 신호선 조건인 `else if (en)` 평면 하에서, 어떤 연산 결과 가중치가 실질적으로 선택 갱신 전이되는가 추적합니다.
4. **암묵적 상주 상태 (Implicit Hold State)**: `else` 구문 분기 명세가 부재하다는 구조적 특성의 본질을 짚어내야 합니다. 이는 `en = 0`인 스톨 타이밍 기점에서 하드웨어가 의도치 않은 래치(Latch)를 굽지 않고, 직전 클럭에 보관했던 물리 플립플롭 전하 자산을 한 치의 균열 없이 그대로 홀딩 유지하는 강력한 클럭 게이팅 상태에 상주함을 완벽히 인지하는 단계입니다.

### 5.2 블로킹(`=`) vs 넌블로킹(`<=`) 신호 업데이트의 하드웨어적 본질

* **블로킹 할당문 (`=`)**: 조합 논리 회로 서술 시 사용되며 소프트웨어적 순차 실행과 유사하게 우변 연산 결과가 그 즉시 좌변 선로 전위로 강제 대입 처리됩니다.
* **넌블로킹 할당문 (`<=`)**: 동기 순차 회로 서술에 강제되며, 우변 계산 상태 값들이 동일 클럭 상승 에지 시점에 임시 버퍼에 동시 캡처 보관된 후, 클럭 경계 타임 스텝이 마감 완결되는 시점에 레지스터 공간으로 일제히 병렬 업데이트됩니다.

```verilog
// 시스톨릭 데이터 동시 시프트 모사 예시
act_out    <= act_in;
weight_reg <= weight_in;
```

위 코드를 읽을 때 "첫 줄이 실행된 후 두 번째 줄이 실행된다"고 해석하는 것은 전형적인 소프트웨어적 실패입니다. 아키텍트는 "두 전송 이벤트가 완벽히 동일한 물리 클럭 에지 신호 한 박자에 트리거되어, 물리 평면 상에서 동시에 옆 칸과 아래 칸으로 데이터 전하가 물밀듯이 이동한다"라고 동시 병렬성(Concurrency) 관점으로 완벽히 트레이싱해야 합니다.

## 6. generate 공간적 배열 구조 복제 추적 방법론

2차원 컴퓨팅 평면 그리드를 형성하는 `generate` 루프 제어문 분석 시에는 평면을 평탄화(Flattening)하여 인덱싱 구조를 역산해 내야 합니다.

```verilog
generate
    for (i=0; i < ROWS; i=i+1) begin : ROW
        for (j=0; j < COLS; j=j+1) begin : COL
            mac_prod pe ( .clk(clk), ... );
        end
    end
end generate
```

### 🎯 시스톨릭 정복을 위한 '4-Corner PE 검증 규칙'

대규모 매트릭스 결합 구조의 모든 내형 PE 연결 관계를 하나하나 손으로 매핑하는 것은 불가능합니다. 공간 위상 기하학 구조상, 배열의 극단을 달리는 4개의 모서리 경계 프로세싱 엘리먼트(Corner PE)의 인터페이스 입출력 결합선 무결성만 확정해 내면 내부에 복제된 나머지 모든 연산기는 동일 토폴로지 패턴의 완벽한 반복임이 공학적으로 보장됩니다.

```text
                  [psum_in 0,1,2,3 외부 제로 버스 인가]
                                   │
                                   ▼
        ┌────────────────────────────────────────────────────────────┐
        │  [PE 0,0] 모서리 식별              [PE 0,COLS-1]           
──►     │   - act_in : 외부 실시간 주입       - act_out: 옆 셀 전달 
act_in  │   - psum_in: 0 (상단 경계선)        - psum_out: 아래 전달 
        │                                                            │
        │  [PE ROWS-1,0]                     [PE ROWS-1,COLS-1]   
        │   - act_in : 위 셀에서 하차          - act_out: 소멸 유실  
        │   - psum_out: 아래로 최종 출력 ──►  - psum_out: 최종 출력 
        └────────────────────────────────────────────────────────────┘
                                   │
                                   ▼
                     [최종 결과 행렬 수집단 포트 직결]
```

* **PE[0][0] (Top-Left)**: 외부 가속 패브릭 입력단 신호선에서 날것의 피처 맵 입력(`act_in`)을 수용하는 진입 기점이며, 부분합 입력(`psum_in`)선은 상단 경계선 조건에 의거하여 `0` 버스로 바인딩 처리되는 규칙을 확인합니다.
* **PE[0][COLS-1] (Top-Right)**: 액티베이션 데이터는 배열 내부 우측 경계를 넘어 옆 셀로 전달(`act_out`) 처리 시키고 부분합 데이터 체인은 아래 하단 소자로 토스하는 분기 규격을 검증합니다.
* **PE[ROWS-1][0] (Bottom-Left)**: 상단 어레이 평면을 타고 누산 연산이 내려온 중간 부분합 체인 결과물을 인가받고, 최종 종결 연산 시 가속 패브릭 수집단 포트로 데이터 하차 출력을 감행하는 경계면입니다.
* **PE[ROWS-1][COLS-1] (Bottom-Right)**: 시스톨릭 그리드의 최우측 최하단 마감 유닛으로서 가동 시 데이터 이동이 완결되는 최종 수집 싱크 포트 연결 상태를 스캔합니다.

## 7. 아키텍트 최종 하드웨어 무결성 체크리스트

모든 RTL 분석 루틴이 마감되었다면, 아키텍트는 설계 보고서 작성 전 본인 스스로에게 다음 4가지 핵심 질문 매트릭을 던져 거침없이 방어해 낼 수 있어야 합니다.

1. **구조 아키텍처 관점**: 대규모 워크로드 구동 시 물리 행렬 소스 데이터는 정확히 어떤 계층 파일의 어느 핀 주소로 인입되어 가속 완료 후 어느 포트 평면으로 나침반처럼 전출되는가?
2. **모듈 컴포넌트 관점**: 내부 서브 계층을 형성하는 `weight_loader`, `input_skew`, `pe_array`, `output_collect` 각 독립 부품 자산들의 고유 임무와 한계 기능 마진은 무엇인가?
3. **타이밍 시간 축 관점**: 시스템 전역 플립플롭 회로들의 내부 유한 상태 머신(FSM) 값과 부분합 가산 데이터 결과 레지스터 적재값은 정확히 어느 `always` 클럭 상승 에지 분기 조건식 하에서 다이내믹하게 전이 갱신되는가?
4. **배열 토폴로지 관점**: 가중치 고정형(WS) 가동 시나리오 하에서 액티베이션 데이터 물리 전하와 부분합 누산 체인 버스는 클럭 격자 주기마다 어떤 공간적 방향 축(X축 우향 / Y축 하향)을 타고 물밀듯이 이동 횡단하는가?
