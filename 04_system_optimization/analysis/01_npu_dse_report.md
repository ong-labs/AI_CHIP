# 01_npu_dse_report.md: Design Space Exploration (DSE) and Pareto Front Multi-Objective Optimization Analysis

본 보고서는 시스템 최적화 단계의 핵심 실습인 [01_npu_dse_bench.py](../lab/01_npu_dse_bench.py) 소스 코드와 시뮬레이션 측정 데이터를 기반으로 작성되었습니다. 도메인 특화 가속기(DSA) 설계 과정에서 상호 충돌하는 두 핵심 지표인 지연 시간(Latency)과 에너지 소모량(Energy Consumption)의 하드웨어 트레이드오프(Trade-off) 관계를 정량화하고, 디자인 공간 탐색(Design Space Exploration, DSE)을 통해 파레토 최적(Pareto Optimal)의 설계 집합을 도출하는 전체 파이프라인 분석을 목적으로 합니다.

---

## 1. 개요: 디자인 공간 탐색(DSE)의 본질

NPU 하드웨어 설계의 가장 원초적인 화두는 **"과연 어떠한 구조적 스펙을 가진 가속기가 타겟 워크로드에 가장 최적인가?"** 라는 질문입니다. 아키텍트가 추구하는 가장 이상적인 NPU는 다음과 같은 조건들을 동시에 만족하는 칩입니다.

* **연산 속도의 극대화**: 주어진 신경망 연산을 마치는 시간(Latency)이 극도로 짧아야 합니다.
* **소모 전력의 극소화**: 동일한 연산을 수행할 때 소비하는 하드웨어 에너지(Energy)가 적어야 합니다.

그러나 마이크로아키텍처 실리콘 레벨에서 **"빠른 칩은 일반적으로 전력을 많이 소모한다"** 는 물리적 대전제가 작용합니다. 연산 가속을 위해 PE 배열을 키우거나 고정밀 데이터 타입을 선택하면 사이클 수는 단축될 수 있으나, 온칩 스위칭 전류 및 메모리 트래픽의 급증으로 인해 전력 소모량이 동반 상승합니다.

따라서 모든 설계 지표를 완벽히 만족하는 '절대적 최적 설계점'은 현실적으로 거의 존재하지 않으며, 각 설계 변수 간의 **상호 대타적 한계선(Trade-off Frontier)** 이 필연적으로 형성됩니다. 이를 하드웨어 공학적으로 명밀히 탐색하고 판별해 내는 최적화 도구 체인이 바로 **Design Space Exploration(DSE)** 파이프라인입니다.

## 2. DSE 자동화 최적화 파이프라인 구조

본 실습 환경에서는 무작위 시도가 아닌, 하드웨어 사양 정의부터 시각화까지 유기적으로 직결되는 5단계 3-Tier 자동화 파이프라인을 구축하여 다차원 탐색을 이행합니다.

```text
 ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
 │    NPUConfig    │     │     NPU Run     │     │ Collect Metrics │
 │ (Clone Config)  ├────►│(Week3 Simulator)├────►│(Cycles/PJ Meas.)│
 └─────────────────┘     └─────────────────┘     └─────────────────┘
           ▲                                               │
           │              ┌─────────────────┐              ▼
           └──────────────│  Visualization  │     ┌─────────────────┐
             (Cartesian   │ Pareto Analysis │◄────┤ Pareto Optimal  │
              Product)    └─────────────────┘     │ Identification  │
                                                  └─────────────────┘
```

1. **Week3 NPU Simulator 자산 재사용**: 이전 개발 주차에서 정밀하게 빌드해 둔 가속기 명세 구조체(`NPUConfig`)와 마이크로아키텍처 가상 실행 엔진(`NPU`) 모듈을 임포트하여 골격을 그대로 계층적으로 활용합니다. 독자적인 새로운 시뮬레이터를 다시 만드는 병목 비용 없이, 검증된 하드웨어 수치 모델 위에서 수백 개의 NPU 변수를 고속으로 크로스 체크 비교하는 주차의 정체성을 가집니다.
2. **SRAM / PE / DType 조합 생성**: 탐색 범위에 포함된 온칩 메모리 용량 크기, 프로세싱 엘리먼트 배열 형상 비트 및 데이터 타입 정밀도를 수학적 데카르트 곱(Cartesian Product) 형태로 누락 없이 일괄 생성합니다.
3. **가상 가속기 실행 및 매트릭 수집**: 임베딩된 내부 타일 분할(Tile Split) 로직, 온칩 SRAM 버퍼링 연산, DRAM 트래픽 액세스 계산 및 제어 유닛의 하드웨어 시뮬레이션을 동시 실행하여 총 가동 클럭 사이클 수와 pJ 단위 소모 에너지를 정밀 실측 리포팅합니다.
4. **Pareto Optimal 다적격 판별**: 수집된 하드웨어 비용 지표 배열을 다목적 최적화 알고리즘에 통과시켜 타 설계안에 의해 지배(Dominated)당하지 않는 무결한 설계 조합들만 색출해 냅니다.
5. **로그 스케일 시각화**: 최적화 경계선인 **Pareto Front**와 참조 기준 아키텍처 (`Base Config`)의 위치를 2차원 평면상에 가시화하여 최종 아키텍처 의사결정을 지원합니다.

## 3. 탐색 설계 공간(Design Space) 및 워크로드 정의

### 3.1 독립 파라미터 변수 축 설정

controlled experiment(대조 실험) 기법을 엄격히 준수하기 위해 최상위 아키텍처 사양을 복제한 뒤, 아래 3가지 마이크로아키텍처 변수 후보군만을 다차원으로 가변 스윕(Sweep)합니다.

* **SRAM 온칩 버퍼 용량 후보군 (`SRAM_SIZES_KB`)**:
* `1,024 KB` (1 MB)
* `4,096 KB` (4 MB)
* `16,384 KB` (16 MB)
* `65,536 KB` (64 MB)


* **PE 어레이 2차원 형상 후보군 (`PE_SHAPES`)**:
* `(8, 8)` 어레이 (총 64개 PE)
* `(16, 16)` 어레이 (총 256개 PE)
* `(32, 32)` 어레이 (총 1024개 PE)
* `(64, 64)` 어레이 (총 4096개 PE)


* **데이터 타입 정밀도 후보군 (`DTYPES`)**:
* `int8` (1 Byte 정수형)
* `fp16` (2 Byte 반정밀도 부동소수점)
* `fp32` (4 Byte 단정밀도 부동소수점)


$$\text{총 탐색 아키텍처 개수} = 4\text{ (SRAM)} \times 4\text{ (PE)} \times 3\text{ (DType)} = 48\text{ Configs}$$

파이프라인 루프 구동 시 `itertools.product` 지시어를 통한 Cartesian Product 방식으로 48개의 가상 NPU 독립 칩 인스턴스를 동적으로 생성 및 평가합니다.

### 3.2 평가 타겟 워크로드 명세

가속기 코어 평면에 인가되는 연산 자극 세트는 대규모 정방형 행렬 연산 워크로드로 고정 정의합니다.

```python
SWEEP_WORKLOAD = (256, 4096, 4096)  # M × K × N 사양
```

* 피연산자 행렬 $A$의 차원: $256 \times 4096$ 정밀도 버퍼
* 피연산자 행렬 $B$의 차원: $4096 \times 4096$ 정밀도 버퍼
* 거대한 규모의 일반 행렬 곱셈(GEMM) 연산을 수행함으로써 온칩 버퍼 크기 제약에 따른 타일 분할 패널티와 PE 공간 이용률(Utilization)의 마이크로아키텍처적 마진 변화가 리포팅 지표에 다이내믹하게 반영되도록 유도합니다.

## 4. 핵심 산술 및 물리 비용 변환 메커니즘 (`measure`)

시뮬레이터 내부 커널에서 반환되는 로우(Raw) 데이터 값을 공학 표준 지표로 변환하는 핵심 가동 산술 공식입니다.

### 4.1 지연 시간(Latency) 변환 논리

가속기가 연산을 완료하는 데 소모한 물리적 '클럭 사이클 수(Cycles)'는 그 자체로 시간 단위를 대변할 수 없습니다. 하드웨어의 전역 동작 주파수(Clock Frequency)가 결합되어야 실질적인 시간 지표가 도출됩니다.

$$Latency\ (seconds) = \frac{Total\ Executed\ Cycles}{Clock\ Frequency\ (Hz)}$$

본 실습 모델에서는 기준 사양 주파수 대역인 `cfg.clock_ghz` 스케일($1\text{ GHz} = 10^9\text{ cycles/sec}$)을 분모에 매핑한 후, 분석 가독성을 위해 밀리초($\text{ms}, 10^{-3}\text{sec}$) 단위로 스케일 업하여 리포팅합니다.

* **공학적 예시**: 1.0 GHz 주파수로 구동되는 NPU 코어가 특정 타일 루프를 도는 동안 총 $10^6\text{ cycles}$를 소비했다면, 실질 지연 시간은 정확하게 $1\text{ ms}$로 연산 처리됩니다.

### 4.2 소모 에너지(Energy) 변환 논리

시뮬레이터 엔진이 가속기 내부의 스위칭 커패시턴스와 외부 DRAM 입출력 트래픽을 추적하여 계산해 낸 누적 에너지는 피코줄(pJ, $10^{-12}\text{J}$) 규격을 따릅니다. 시스템 수준의 가시성 확보를 위해 밀리줄(mJ, $10^{-3}\text{J}$) 단위로 정량 스케일링 변환을 수행합니다.

$$1\text{ mJ} = 10^9\text{ pJ}$$

따라서 수집된 `r.energy_pj` 로우 상수를 $10^9$ 단위로 나누어 줌으로써 마이크로 가속기 하드웨어 컴포넌트 단위 소비 에너지를 거시 전력 프로필 수치로 안전하게 변환합니다.

## 5. 파레토(Pareto) 최적화 수학적 판정 알고리즘

DSE 파이프라인의 핵심인 다적격 비지배 설계점 판정 논리입니다.

### 5.1 수학적 정의 및 조건식

임의의 설계 포인트 집합 $P$ 내에서 특정 아키텍처 구성안 $i$가 다른 아키텍처 구성안 $j$에 의해 '지배당한다(Dominated)'는 것은 아래의 조건을 동시에 만족함을 의미합니다.

$$\big(\,Latency(j) \le Latency(i)\,\big) \ \ \wedge \ \ \big(\,Energy(j) \le Energy(i)\,\big)$$

$$\text{and at least one inequality is strict } (<)$$

즉, 아키텍처 $j$가 $i$와 비교했을 때 속도도 더 빠르거나 같고, 전력도 더 적게 소모하면서 두 지표 중 최소 하나는 반드시 우위에 서 있는 경우를 뜻합니다. 이러한 상위 호환체 $j$가 단 하나라도 존재한다면 아키텍처 $i$는 공학적 가치가 상실된 비효율적 설계점으로 판정되어 `out[i] = False` 처리를 받으며 무대 바깥으로 제거됩니다.

이 필터링 그물망을 뚫고 끝까지 살아남아 **그 누구에게도 지배당하지 않는(Non-dominated) 최적의 아키텍처 독립 부분집합**들을 연결한 선을 **Pareto Front**라고 선언합니다.

### 5.2 파레토 적격 판정 예시 분석

이해를 돕기 위해 3개의 가상 가속기 설계 포인트를 기준으로 정합성을 확인해 보겠습니다.

| 설계 식별자 | 지연 시간 (Latency) | 소모 에너지 (Energy) | 파레토 적격 여부 및 판정 이유 |
| --- | --- | --- | --- |
| **A** | $1\text{ ms}$ | $10\text{ mJ}$ | **탈락 (Dominated)**: C안과 속도는 같으나 전력을 2배 더 소모함. |
| **B** | $2\text{ ms}$ | $5\text{ mJ}$ | **탈락 (Dominated)**: C안 대비 속도도 느리고 전력 소모량은 같음. |
| **C** | $1\text{ ms}$ | $5\text{ mJ}$ | **적격 (Pareto Optimal)**: A와 B를 모든 지표축에서 압도적으로 이김. |

결과적으로 최적의 효율을 증명한 설계 **C**가 공간 내에 생존해 있는 한, 상위 호환 패널티를 극복하지 못한 **A와 B는 설계 후보군에서 완전히 배제**되는 것이 공학적으로 타당합니다.

## 6. 시뮬레이션 결과분석 및 데이터 고찰

48개 아키텍처 스윕 루프를 완벽히 통과시켜 도출해 낸 실제 하드웨어 리포팅 데이터 결과 사양입니다.

### 6.1 파레토 프론트(Pareto Front) 실측 데이터

* **총 Swept 결과**: 48개의 복합 가속기 후보군 중 다목적 비지배 무결성을 만족하여 Pareto Front 최적 경계선 위에 안착한 칩 설계안은 단 1개(`1 / 48 configs`)뿐인 극단적인 수렴 결과가 실측되었습니다.

```text
--- Pareto-front configs (sorted by latency) ---
  sram64M_pe64x64_int8               1.050 ms       2.84 mJ
```

* **최적 설계 자산 스펙**: `sram64M_pe64x64_int8`
* 온칩 SRAM 크기: `64 MB` 극대화 구조
* PE 배열 사양: `64 × 64` 시스톨릭 그리드 평면 (총 4096개 계산 엔진)
* 연산 정밀도 속성: `int8` (1바이트 고속 양자화 정수 정밀도)
* 유효 성능 지표: 지연 시간 **`1.050 ms`**, 소모 에너지 `2.84 mJ`의 경이로운 고효율 수치를 기록하며 독점 적격을 획득했습니다.



### 6.2 참조 기준 아키텍처 (`Base Config`) 분석 및 비교

기존 주차에서 임의의 기준으로 세팅해 두었던 하이퍼파라미터 표준 사양인 `Base Config`의 물리 성적표를 추적하여 아키텍처적 경쟁력을 크로스 체크합니다.

* **실측 비용 지표**: 지연 시간 **`16.778 ms`**, 소모 에너지 **`30.92 mJ`**
* **파레토 프론트 포함 여부 (`Base on Pareto front`)**: **`False`**
* **아키텍처적 고찰**: 베이스 칩 스펙은 지연 시간 관점에서 파레토 최적 칩 대비 **약 16배 느리며**, 누적 소모 에너지 역시 **10.8배 이상 무겁게** 낭비하고 있음이 정량적으로 입증되었습니다. 즉, 현재의 베이스 라인은 설계 공간 상에서 완벽히 도미네이트(지배)당하고 있는 비효율적인 마이크로아키텍처 영역에 머무르고 있으므로 구조적 전면 개편이 시급함을 가리킵니다.

* **양 축의 로그 스케일(`Log Scale`) 채택 이유**:
* 실험 공간 내 NPU들의 성능 제원 스펙트럼은 지연 시간 기준 `0.1 ms ~ 100 ms+`, 에너지 기준 `1 mJ ~ 수백 mJ` 단위까지 수천 배 수준으로 극단적으로 넓게 분포되어 있습니다.
* 이를 선형(Linear) 축으로 시각화하면 고성능 영역의 점들이 원점 근처에 뭉개져 구분이 불가능해지므로, 광대역 데이터 분포의 미세 격자 변화를 직관적으로 판별하기 위해 `ax.set_xscale("log")` 고차원 로그 매핑을 적용했습니다.


* **데이터 타입(DType)별 마커 기하학 구조 고찰**:
* **○ (Circle 마커)**: `int8` 데이터 타입 매핑 칩
* **□ (Square 마커)**: `fp16` 데이터 타입 매핑 칩
* **▲ (Triangle 마커)**: `fp32` 데이터 타입 매핑 칩


* 플롯 결과를 보면, 가벼운 데이터 타입인 `int8` 코어들은 그래프의 가장 좌측 하단(속도가 빠르고 에너지가 적은 고효율 영역)을 지배하고 있는 반면, `fp32` 부동소수점 매커니즘을 채택한 가속기 칩들은 우측 상단(지연 시간이 길고 에너지 소모가 폭증하는 비용 영역)으로 쏠려 있어 정밀도 선택이 칩의 물리 비용에 미치는 가혹한 영향력을 시각적으로 즉각 방증합니다.
* **붉은 점선 (`Red Dashed Line`)**: 파레토 적격 판정을 통과한 점들을 시간 축 정렬 순서대로 엮어 만든 **Trade-off Frontier** 라인입니다. 이 붉은 경계선이 원점(좌하단)에 가까이 붙을 수록 전반적인 하드웨어 아키텍처 기술 수준의 우수성을 대변합니다.
* **푸른색 별 마커 (`★ Blue Star`)**: 현재 지배당하고 있는 기준 베이스 라인 아키텍처의 고립 좌표를 랜드마크로 찍어주어, 탐색 공간 내에서 현재 우리 설계 자산의 경쟁력 수준을 직관적으로 실측 파악할 수 있도록 도웁니다.

## 8. 아키텍처 설계 변수 가변에 따른 명밀한 트레이드오프 분석

DSE 분석을 통해 체득할 수 있는 가장 고도의 하드웨어 아키텍처 인사이트는 "칩 설계에 절대적인 정답(Silver Bullet)은 없으며, 모든 의사결정은 다차원적인 상호 비용 교환"이라는 본질입니다.

### 8.1 온칩 SRAM 버퍼 크기 확장 시의 명암

* **긍정적 효과 (Pros)**: 온칩 메모리 저장 대역이 커질 수록 거대한 피연산자 행렬을 내부에 한 번에 로드할 수 있어 가혹한 외부 DRAM 접근 횟수와 전하 이동 트래픽이 획기적으로 감쇄되며, 이에 따라 시스템 칩셋 전체의 전력 및 에너지 소모량이 수십 배 단위로 급격히 하락합니다.
* **부정적 효과 (Cons)**: 실제 물리 실리콘 칩 환경에서 거대한 SRAM 배치 공정은 회로 다이(Die) 면적의 폭발적인 팽창과 제조 원가(Cost) 및 누설 전류의 급격한 상승을 초래합니다. *(※ 단, 현재 소프트웨어 레벨 시뮬레이터 벤치마크 모델에는 실리콘 면적 비용 펑션 모델이 부재하여 64MB 스펙이 일방적인 적격을 획득하게 된 아키텍처적 한계 한계를 명밀히 인지해야 합니다.)*

### 8.2 PE 어레이 가속 그리드 크기 확장 시의 명암

* **긍정적 효과 (Pros)**: 공간적 병렬 연산 코어 수가 $8 \times 8 = 64$개에서 $64 \times 64 = 4,096$개로 대폭 증가함에 따라 단일 사이클 당 처리 가능한 MAC 하드웨어 연산 공급량(Compute Capability)이 기하급수적으로 증폭되어 연산 병목 구간이 완전히 청소됩니다.
* **부정적 효과 (Cons)**: 만약 인가되는 목표 알고리즘 워크로드의 스케일 크기가 하드웨어 평면보다 작거나 차원 매핑 격자가 맞지 않을 경우, 대다수의 PE가 유효 데이터를 공급받지 못하고 노는 **공간 이용률(Hardware Utilization) 폭락 현상**과 전력 낭비 병목이 연쇄 발생하게 됩니다.

### 8.3 데이터 타입 정밀도 선택 시의 명암

* **fp32 선택 시**: 인공지능 알고리즘의 소수점 수치 연산 무결성과 신경망의 추론 정확도(Accuracy)는 100% 완벽히 보장 및 증가할 수 있으나, 버스 인터페이스 데이터 전송 폭의 확대로 인해 메모리 대역폭 병목이 터지고 연산 하드웨어 에너지가 폭증하며 단위 시간당 처리량(Throughput)이 치명적으로 급감합니다.
* **int8 선택 시**: 메모리 풋프린트와 이동 비용이 4배 가까이 절감되어 압도적인 속도 가속화와 에너지 세이빙을 달성할 수 있는 반면, 양자화 손실로 인한 알고리즘 예측 정밀도 하락 마진을 아키텍트가 추가로 정밀 방어해야 하는 아키텍처적 전제 조건 조건이 요구됩니다.

## 9. 결론 (Conclusion)

$$\boxed{
\text{"NPU 설계 공간 전체를 자동 탐색해서, 좋은 설계 집합(Pareto front)을 찾는 시스템"}
}$$

본 DSE 탐색 실습을 통해 확립한 자동화 분석 방법론은 단순한 파이썬 스크립트 빌드업을 넘어, 복잡하게 얽혀 있는 독자 가속기 사양 파라미터 간의 물리적 충돌 메커니즘을 정량적 데이터로 발굴해 내는 아키텍처 설계의 정수입니다. 본 단원에서 확보한 다적격 설계 탐색 지표와 파레토 프론트 경계선 자산은 차후 신경망 다차원 루프 타일링 제어 및 컴파일러 아키텍처 매핑 최적화를 이뤄내기 위한 가장 정밀한 나침반 역할을 수행할 것입니다.
