# 01_dse_optimization.md: Design Space Exploration & Multi-Objective System Optimization

이 문서는 [01_npu_dse_report.md](../analysis/01_npu_dse_report.md)에서 다룬 다목적 가속기 최적화 기법과 [01_npu_dse_bench.py](../lab/01_npu_dse_bench.py) 실습을 통해 구현한 디자인 공간 탐색(Design Space Exploration, DSE) 파이프라인의 핵심 아키텍처 이론을 검증합니다. 상호 상충하는 하드웨어 비용 메트릭 간의 트레이드오프(Trade-off) 분석 역량과 파레토 프론트(Pareto Front) 식별 및 마이크로아키텍처 제원 변동에 따른 물리적 인과관계를 최종적으로 확인합니다.

---

## 📝 개념 확인 문제 (Quiz)

### 문제 1. 디자인 공간 탐색(DSE)의 본질적 목적
* **질문:** DSE(Design Space Exploration)의 목적을 가장 정확하게 설명한 것은?
* **정답: C. 여러 하드웨어 조합의 trade-off를 탐색하기 위함**
* **해설:** DSE는 가속기 하드웨어 사양을 구성하는 다양한 마이크로아키텍처 변수(SRAM, PE, DType 등)들의 수많은 조합을 자동 스윕(Sweep)하여, 지연 시간과 에너지 소모량 등 서로 상충하는 다목적 비용 지표 간의 정량적 균형 관계를 탐색하기 위해 수행됩니다.

### 문제 2. 파레토 최적(Pareto Optimal)의 하드웨어 공학적 정의
* **질문:** 아래 중 Pareto optimal 설계의 의미로 가장 적절한 것은?
* **정답: C. 어떤 다른 설계가 모든 metric에서 동시에 더 좋지 않은 설계**
* **해설:** 파레토 최적 설계점은 다목적 최적화 도메인에서 '비지배(Non-dominated) 설계'를 뜻합니다. 즉, 전체 탐색 공간 내에 이 설계보다 지연 시간도 더 짧으면서 동시에 에너지 소모량도 적은 상위 호환 설계안이 단 하나도 존재하지 않는 최적의 효율성 설계 집합입니다.

### 문제 3. 지배(Dominated) 설계의 필터링 조건
* **질문:** 다음 중 dominated 설계를 설명하는 것은?
* **정답: C. 어떤 다른 설계가 latency와 energy 모두 더 좋은 설계**
* **해설:** 특정 설계안 $i$에 대하여, 지연 시간도 더 짧거나 같고 에너지 소모량도 적으면서 최소한 하나의 메트릭은 완벽한 우위에 서 있는 상위 호환 아키텍처 $j$가 공간 내에 단 하나라도 존재한다면, 설계안 $i$는 지배당했다(Dominated)고 하며 공학적 선택 가치가 상실되어 탈락 처리됩니다.

### 문제 4. 파레토 프론트와 트레이드오프 경계선
* **질문:** 왜 Pareto front가 “trade-off frontier”라고 불리는가?
* **정답: B. latency와 energy가 서로 충돌하는 경우가 많기 때문**
* **해설:** 디지털 회로 물리 레벨에서 칩의 성능을 높이기 위해 하드웨어 자원을 대거 투입하면 일반적으로 스위칭 전류 및 메모리 트래픽 상승으로 전력 소모량이 동반 증가합니다. 이렇듯 하나를 얻으면 하나를 잃는 성능과 에너지의 상호 모순적 충돌로 인해 최적 설계의 한계 경계선(Frontier)이 형성됩니다.

### 문제 5. 다적격 경계선 상의 극단적 설계 배치
* **질문:** 다음 중 Pareto front에 포함될 가능성이 가장 높은 설계는?
* **정답: B. 가장 빠르지만 전력 소모가 큰 설계**
* **해설:** 파레토 프론트는 다차원 축의 최전선 경계면이므로, 에너지를 아주 많이 소모하더라도 속도 축에서 그 누구에게도 지배당하지 않는 '독보적으로 가장 빠른 설계안'의 경우 파레토 적격 설계안으로 생존할 가능성이 매우 높습니다.

### 문제 6. 모듈 동적 임포트 구문의 아키텍처적 목적
* **질문:** 아래 코드의 역할은?
  ```python
  _cfg_mod = _import_local(...)
  _sim_mod = _import_local(...)
  ```
* **정답: B. 기존 Week3 simulator 재사용**
* **해설:** 해당 지시어는 프로젝트 계층 트리 구조를 유기적으로 활용하여, 이전 주차에서 정밀하게 사양을 선언하고 하드웨어 제원 연산 유닛을 구현 완료한 명세 구조체(`NPUConfig`)와 가상 가속기 시뮬레이터(`NPU`) 모듈 자산을 그대로 호출하여 재사용하기 위한 바인딩 파트입니다.

### 문제 7. 탐색 변수의 데카르트 곱(Cartesian Product) 연산

* **질문:** 다음 코드의 의미는?
  ```python
  product(SRAM_SIZES_KB, PE_SHAPES, DTYPES)
  ```
* **정답: B. 모든 하드웨어 조합 생성**
* **해설:** `itertools.product` 함수는 인자로 인가된 복수의 가변 독립 변수 후보군 배열들 간의 수학적 데카르트 곱을 수행하여, 공백이나 누락 없이 공간 상에 존재 가능한 모든 다차원 하드웨어 아키텍처 명세 조합(4 × 4 × 3 = 총 48개 Config)을 일괄 생성하는 역할을 합니다.

### 문제 8. 통제된 대조 실험을 위한 객체 복사 규칙

* **질문:** 아래 코드의 목적은?
  ```python
  cfg = deepcopy(base)
  ```
* **정답: C. 기준 config를 유지한 채 일부 parameter만 변경**
* **해설:** 엄격한 controlled experiment(통제 대조 실험) 프로토콜을 수행하기 위해, 참조 기준점이 되는 하드웨어 사양 객체(`base`)를 메모리 독립적으로 깊은 복사(Deepcopy)한 후 변경 타겟이 되는 특정 변수 축(예: SRAM 용량만 수정)만 고립 가변하여 아키텍처 마진을 정확히 실측하기 위함입니다.

### 문제 9. 시뮬레이션 측정 함수 기능 범위 정의

* **질문:** 다음 중 measure() 함수 내부에서 실제로 수행되는 작업이 아닌 것은?
* **정답: D. RTL synthesis**
* **해설:** `measure()` 함수는 설정 객체를 바탕으로 가상 NPU 하드웨어 인스턴스를 메모리에 할당하고 타일 연산을 시뮬레이션하여 사이클 및 에너지를 뽑아낼 뿐, 게이트 수준의 물리 회로 합성(RTL Synthesis)을 실행하는 함수가 아닙니다.

### 문제 10. 주파수 스케일링 기반 타이밍 변환 산술 공식

* **질문:** 다음 코드의 의미는?
  ```python
  latency_s = r.cycles / (cfg.clock_ghz * 1e9)
  ```
* **정답: B. cycle → 실제 시간 변환**
* **해설:** 시뮬레이터 런타임 결과물인 총 물리 클럭 사이클 수(`r.cycles`)는 그 자체로 아키텍처 시간 단위를 대변하지 못하므로, 가속기 사양 주파수 대역인 `cfg.clock_ghz` 스케일($1\text{ GHz} = 10^9\text{ Hz} = 10^9\text{ cycles/sec}$)로 나누어 줌으로써 실질 물리 초(Seconds) 지표로 환산 변환합니다.

### 문제 11. 행렬 매핑 방향 타일 스케일 공식 분해

* **질문:** 다음 수식에서 의미하는 것은?
$$nt_m = \left\lceil \frac{M}{PE_R} \right\rceil$$
* **정답: B. M축 tile 개수**
* **해설:** 인가된 대규모 행렬곱 차원 중 $M$ 축의 전폭 크기를 공간 가속기 하드웨어 평면 배열의 물리적 행 개수($PE_R$) 단위로 나누어 준 뒤 올림 처리($\lceil\rceil$)한 수식으로, 전체 매핑 평면에서 $M$ 축 방향으로 쪼개진 총 타일 블록 파티션 개수를 의미합니다.

### 문제 12. 가속기 연산 그리드 파라미터 식별

* **질문:** 다음 중 PE_R의 의미는?
* **정답: B. systolic array의 row 방향 PE 개수**
* **해설:** `PE_R`은 2차원 공간 배치형 하드웨어 연산 평면(Systolic Array)을 마이크로아키텍처적으로 구조화할 때 행(Row) 방향 축으로 직적 집계된 가용 연산 프로세싱 엘리먼트(PE)의 개수를 정의하는 사양 변수입니다.

### 문제 13. 시스톨릭 아키텍처 파이프라인 지연 수학적 모델링

* **질문:** 다음 수식에서 마지막 항의 의미는?
$$compute\_cycles = nt_m \cdot nt_n \cdot nt_k \cdot PE_R + (PE_R + PE_C - 1)$$
* **정답: B. fill + drain overhead**
* **해설:** 우변의 마지막 항인 $(PE_R + PE_C - 1)$은 시스톨릭 어레이 하드웨어 특유의 파이프라인 지연 제어 비용입니다. 최초 연산 데이터가 그리드 내부에 가득 차기까지 걸리는 시간(Fill)과 모든 누산 마감이 끝나고 출력이 완전히 빠져나오는 시간(Drain)에 따른 물리 타이밍 오버헤드를 정확히 모사합니다.

### 문제 14. 하드웨어 더블 버퍼링 타임 오버랩 공식 해석

* **질문:** 다음 중 max(compute_cycles, dram_cycles)를 사용하는 이유는?
* **정답: B. compute와 memory가 overlap 가능하다고 가정하기 때문**
* **해설:** 가속기 하드웨어가 온칩 버퍼 메모리 평면 상에서 탁월한 더블 버퍼링(Double Buffering) 아키텍처 메커니즘을 지원한다고 가정한 수식입니다. 프로세서 코어가 연산(`compute_cycles`)을 이행하는 시간과 외장 DRAM 대역이 데이터를 버퍼로 실어 나르는 시간(`dram_cycles`)이 시간 축상에서 완전히 상호 중첩(Overlap) 구동되어 병목 중 큰 값 하나만 전체 지연 시간으로 수렴함을 모사합니다.

### 문제 15. PE 공간 이용률 가용 효율 산출 공식

* **질문:** 다음 수식의 의미는?
$$pe\_utilization = \frac{actual\_macs}{full\_pe\_macs}$$
* **정답: A. 실제 PE 사용 효율**
* **해설:** 특정 목표 알고리즘 워크로드를 하드웨어 코어 평면에 매핑하여 실행했을 때, 가속기가 물리적으로 제공할 수 있는 최대 가용 연산 공간 대역 대비 실제 유효한 산술 연산에 투입되어 유의미하게 구동된 프로세싱 엘리먼트들의 물리적 비율(Hardware Utilization)을 정의합니다.

### 문제 16. 가중치 고정 데이터플로우의 DRAM 트래픽 제어 목적

* **질문:** Weight Stationary dataflow에서 weight를 SRAM에 유지하려는 이유는?
* **정답: C. DRAM access 감소**
* **해설:** 변동 주기가 길고 재사용성이 높은 신경망의 가중치(Weight) 매트릭스 데이터를 온칩 SRAM 대역 내에 최대한 긴 시간 상주 및 고정(Stationary)시킴으로써, 물리 비용이 가장 무겁고 가혹한 전하 이동 패널티를 유발하는 외부 DRAM 메모리로의 불필요한 반복 액세스 트래픽을 원천 차단하기 위함입니다.

### 문제 17. 메모리 용량 임계점 돌파에 따른 버스트 패널티

* **질문:** 아래 상황에서 DRAM traffic이 가장 크게 증가하는 경우는?
* **정답: C. SRAM capacity 부족으로 tile 재로딩 발생**
* **해설:** 온칩 SRAM 메모리의 물리 용량이 인가된 타일 블록 크기보다 작아 데이터를 내부에 유지하지 못하고 밀려날 경우, 동일한 데이터 커널 레이어를 다음 연산 시점에 외부 DRAM 메모리 인터페이스로부터 다시 읽어와야 하는 가혹한 타일 재로딩(Tile Reloading) 패널티가 터져 트래픽이 기하급수적으로 폭증합니다.

### 문제 18. 온칩 대역과 외장 메모리 간 전하 이동 비용 격차 원인

* **질문:** 왜 DRAM energy가 SRAM energy보다 훨씬 큰가?
* **정답: A. DRAM은 off-chip access이기 때문**
* **해설:** 동일 실리콘 다이(Die) 내부에 긴밀히 집적된 SRAM 버퍼선과 달리, 외장 DRAM 액세스는 가속기 칩 바깥(Off-chip)의 패키지 와이어 및 PCB 보드 인쇄 회로선로를 직접 타고 넘어가는 대규모 데이터 물리 이동을 수반하므로, 선로 자체의 기생 커패시턴스 마진이 수백 배 이상 무거워 전하 제어 소모 에너지가 압도적으로 폭증합니다.

### 문제 19. 가속 코어 평면 비대화에 따른 에지 타일 패딩 패널티

* **질문:** PE array를 16×16 → 64×64로 크게 키웠더니 작은 workload에서 utilization이 급감했다. 가장 적절한 이유는?
* **정답: B. edge tile padding 증가**
* **해설:** 하드웨어 가속기 연산 평면은 거대하게 확장해 둔 반면, 인가되는 연산 타겟 행렬 워크로드 차원의 스케일이 작으면 PE 그리드 전폭을 채우지 못하고 남는 빈 공간이 대거 발생합니다. 이 영역은 산술 무결성을 위해 하드웨어 제어부가 전부 제로 패딩(Zero Padding) 에지 타일 처리로 메워야 하므로 유효 연산 효율성이 치명적으로 폭락하게 됩니다.

### 문제 20. 반도체 DSA 아키텍트의 최적화 설계 철학

* **질문:** 다음 중 이 DSE 시스템의 가장 핵심적인 철학은?
* **정답: C. 다차원 trade-off 속에서 의미 있는 설계 집합을 찾는 것**
* **해설:** 도메인 특화 반도체(DSA) 아키텍처 공학 설계에는 단 하나의 절대적인 단일 정답(Silver Bullet)이 존재하지 않습니다. 성능(Latency)을 취하면 비용(Energy/Area)이 가혹해지는 모순 관계 속에서, 타겟 워크로드의 사양 특성에 맞추어 가장 최적의 공학적 타당성을 리포팅해 주는 의미 있는 비지배 파레토 가속기 설계 집합(Pareto Front)의 한계선을 발굴하는 것이 핵심 철학입니다.

* **실습 소스 코드**: 사양 구조체(`NPUConfig`) 변수를 가변하고 다목적 비지배 판정 알고리즘을 이행하여 최적 프론트 라인을 도출하는 실제 구동 자산은 [01_npu_dse_bench.py](../lab/01_npu_dse_bench.py) 소스 코드를 통해 처리됩니다.

### 2. 다음 설계 최적화 단계로의 확장 (Compiler Mapping Horizon)

* 본 과제 및 퀴즈 분석을 통해 확립한 마이크로아키텍처 변수 변동별(SRAM 버퍼 용량 증가, PE 어레이 비대화, 정밀도 선택) 물리 트레이드오프 지식은 향후 대규모 신경망 모델 컴파일 시 최적의 가속 효율을 도출하기 위한 **'소프트웨어 루프 타일링(Loop Tiling) 및 데이터 스케줄링 매핑 최적화'** 단계의 핵심 하드웨어 가중치 인덱스로 연계 확장됩니다.
