# 03_mac_verification_assessment.md: Mastering MAC Unit Design & Hardware-Software Co-Verification

이 문서는 가속기 하드웨어의 핵심 산술 연산 장치인 MAC(Multiply-Accumulate) 유닛의 설계 원리와 부호 있는 정수 연산, 그리고 Python 골든 레퍼런스 모델과 Verilog RTL 간의 cocotb 기반 하드웨어-소프트웨어 교차 검증 방법론을 다룹니다. 서로 다른 추상화 수준에서의 정합성 검증 능력을 최종적으로 확인합니다.

---

## 📝 개념 확인 문제 (Quiz)

### 문제 1. MAC 연산의 수학적 정의
* **질문:** 다음 중 MAC(Multiply-Accumulate) 연산을 올바르게 표현한 것은?
* **정답: C. acc ← acc + (a × b)**
* **해설:** MAC(Multiply-Accumulate) 연산은 두 입력 데이터(일반적으로 피처 맵 입력과 가중치)를 곱한 후, 그 결과를 기존의 누적기(Accumulator Register) 값에 누적하여 더하는 연산입니다. 이는 인공지능 행렬 곱셈 및 컨볼루션 연산의 핵심 커널 연산입니다.

### 문제 2. MAC 커널 기반 워크로드 판정
* **질문:** 다음 중 MAC 연산이 반복되어 수행되는 대표적인 딥러닝 계산이 아닌 것은?
* **정답: D. Sorting**
* **해설:** 행렬 곱셈(GEMM), 컨볼루션(Convolution), 그리고 트랜스포머의 어텐션 메커니즘(Attention) 내 QK^T 및 ScoreV 계산은 모두 거대한 규모의 벡터 내적(Dot Product) 연산이며, 이는 방대한 MAC 연산들의 연속으로 구성됩니다. 반면 정렬(Sorting)은 데이터 간의 대소 비교 및 메모리 교환 위주의 제어 흐름 기반 연산입니다.

### 문제 3. 벡터 내적 연산 복잡도
* **질문:** 벡터 내적 $y = \sum_{i=1}^{N} a_i b_i$ 를 계산할 때 필요한 MAC 연산 횟수는?
* **정답: B. N회**
* **해설:** 길이 $N$인 두 정합 벡터 간의 요소별 곱셈 연산 $N$번และ 이들을 순차적으로 더해 나가는 누적 가산이 필요하므로, 단일 MAC 유닛 아키텍처 기준으로는 총 $N$번(N사이클)의 MAC 연산 처리를 거치게 됩니다.

### 문제 4. MAC 연산의 연산량(FLOP) 환산
* **질문:** 1 MAC은 일반적으로 몇 FLOP(Floating Point Operations)으로 간주되는가?
* **정답: B. 2 FLOP**
* **해설:** 하드웨어 가속기 및 컴퓨터 시스템의 FLOPS 또는 OPS 연산 성능 지표를 산출할 때, 1회의 MAC 연산은 내부적으로 곱셈(Multiplication) 1회와 덧셈(Addition) 1회를 물리적으로 동시 수행하므로 총 2 Operations(2 FLOP)로 정량 환산됩니다.

### 문제 5. 누산기 정밀도(Accumulator Precision) 확장의 이유
* **질문:** 입력보다 더 큰 accumulator precision이 필요한 가장 중요한 이유는?
* **정답: C. 누적 과정에서 값의 범위와 오차가 증가하기 때문**
* **해설:** 유한한 비트 폭을 가진 하드웨어 환경에서 다수의 데이터를 연속해서 누적할 경우, 계산 결과의 절댓값이 커지며 상위 비트가 잘려 나가는 오버플로우(Overflow) 현상이 발생합니다. 이를 원천 차단하고 산술적 수학 무결성을 보장하기 위해 누산기는 입력단보다 확장된 비트 폭을 갖추어야 합니다.

### 문제 6. 정수형 가속기의 표준 누산기 사양
* **질문:** 다음 중 일반적으로 권장되는 accumulator precision은?
* **정답: C. INT32**
* **해설:** 정수형 도메인 특화 가속기(DSA) 설계에서 입력 및 가중치 데이터 타입으로 INT8(8비트 정수)을 채택할 때, 수많은 행렬곱 요소를 연산하는 과정에서 정수 오버플로우를 완전히 방지하고 정밀도를 유지하기 위한 산업 표준 사양으로 32비트 정수형(INT32) 누산기가 널리 권장 및 채택됩니다.

### 문제 7. 혼합 정밀도(Mixed-Precision) 연산의 Accumulator
* **질문:** FP16 × FP16 mixed precision 학습에서 일반적인 accumulator는?
* **정답: C. FP32**
* **해설:** 혼합 정밀도(Mixed-Precision) 연산 프로토콜에서는 연산 가속을 위해 데이터 전송 및 가중치 곱셈은 반정밀도 부동소수점인 FP16(16비트)으로 처리하되, 작은 그라디언트 값이 소실되는 언더플로우나 정밀도 저하를 막기 위해 부분합 누산(Accumulation) 영역은 단정밀도 부동소수점인 FP32(32비트) 레지스터를 사용합니다.

### 문제 8. INT8 누산기의 아키텍처적 한계
* **질문:** INT8 accumulator를 사용했을 때 발생할 수 있는 문제는?
* **정답: B. 오버플로우가 발생한다**
* **해설:** 부호 있는 8비트 정수(INT8)의 표현 영역은 $-128 \sim 127$에 불과합니다. 예컨대 두 입력이 최대 부호값인 $10 \times 10 = 100$만 수행하더라도 단 2회 누적 시 바로 한계점을 초과하여 오버플로우가 터지게 되므로 하드웨어 레벨에서 정상적인 신경망 내적 계산이 불가능해집니다.

### 문제 9. 하드웨어 시뮬레이션의 사이클 단위 제어
* **질문:** 다음 중 mac.step(a, b) 호출이 의미하는 것은?
* **정답: B. 클럭 1사이클 동작**
* **해설:** 소프트웨어 레벨의 클럭 구동 시뮬레이션 및 추상화 하드웨어 모델에서 `step()` 메서드는 하드웨어 시스템의 전역 동기화 타이밍 신호인 클럭(Clock)의 '1 사이클 진행'을 모사합니다. 1 사이클 동안 입력을 받아 연산하고 내부 상태(레지스터)를 갱신하는 최소 단위 트리거입니다.

### 문제 10. 골든 레퍼런스 모델(Golden Reference Model)의 개념
* **질문:** Python + NumPy로 작성한 MACUnit은 무엇에 해당하는가?
* **정답: B. Golden Reference Model**
* **해설:** 물리적인 하드웨어 RTL(Verilog) 설계 및 컴파일 회로 합성을 진행하기 전, 개발 타겟 알고리즘의 수학적 연산 결과와 기능적 제어 흐름의 기준점(Ground Truth)을 정의하기 위해 고수준 소프트웨어 언어(Python 등)로 추상화하여 구현한 사양 표준 검증 모델을 '골든 레퍼런스 모델'이라고 명명합니다.

### 문제 11. 고수준 언어 모델 아키텍처 탐색의 효용성
* **질문:** RTL보다 Python 모델이 특히 유리한 작업은?
* **정답: C. 설계 파라미터 탐색**
* **해설:** 저수준 하드웨어 기술 언어(RTL)는 미세 신호선 연결 및 게이트 지연 타이밍 고려가 복잡하여 아키텍처 변경 비용이 매우 큽니다. 반면 파이썬 모델은 데이터 비트 폭, 연산 정밀도 구조, 버퍼 용량 크기 등의 핵심 아키텍처 매개변수(Hyperparameter)를 신속하게 변경·모사하여 최적의 스펙 조합을 탐색하는 데 압도적으로 유리합니다.

### 문제 12. 마이크로아키텍처 레지스터의 매핑 고찰
* **질문:** Python MACUnit에서 self._acc는 실제 하드웨어의 무엇에 대응되는가?
* **정답: C. 누적 레지스터**
* **해설:** 파이썬 모델 내에서 누적 상태 값을 유지하고 관리하는 인스턴스 변수 `self._acc`는 실제 디지털 회로 상에서 동기식 클럭 신호에 맞춰 매 사이클마다 연산된 중간 연산 결과를 안전하게 홀딩하고 저장하는 물리적 순차 논리 소자인 '누적 레지스터(Accumulator Register)'에 정확하게 1:1 매핑됩니다.

### 문제 13. Verilog 설계 모듈화의 정의
* **질문:** Verilog의 module은 무엇을 정의하는가?
* **정답: B. 하드웨어 회로 블록**
* **해설:** Verilog HDL(하드웨어 기술 언어)에서 `module`은 디지털 회로 시스템을 구성하는 가장 기본적이고 독립적인 추상화 캡슐화 단위입니다. 포트 디클레이션을 통해 입력과 출력을 정의하고 내부의 조합 논리 및 순차 논리를 기술하여 실제 실리콘 상에 구현될 물리적 '하드웨어 회로 블록'을 명세합니다.

### 문제 14. 순차 논리 회로와 동기 신호 제어
* **질문:** always @(posedge clk)는 무엇을 의미하는가?
* **정답: B. 클럭 상승 에지마다 실행된다**
* **해설:** `always @(posedge clk)` 구문은 시스템 전역 클럭 신호가 로우(0)에서 하이(1) 상태로 전이되는 상승 에지(Positive Edge) 이벤트를 감지하여 동작하는 동기식 구문입니다. 플립플롭(Flip-Flop)과 같은 하드웨어 순차 논리 회로(Sequential Logic)의 상호 전이 특성을 하드웨어적으로 기술하는 핵심 제어축입니다.

### 문제 15. 부호 있는 데이터 타입 표현 및 비트 사양
* **질문:** reg signed [31:0] acc에 대한 설명 중 올바른 것은?
* **정답: B. 32비트 signed 값을 저장하는 레지스터**
* **해설:** `reg` 키워드는 값을 유지 및 저장할 수 있는 레지스터 저장 소자를 의미하며, `signed` 식별자는 해당 레지스터가 2의 보수(2's complement) 구조 기반의 부호 있는 정수 연산을 수행하도록 컴파일러에 지시합니다. `[31:0]` 벡터 폭 선언에 따라 총 32비트의 유효 물리 대역을 점유함을 나타냅니다.

### 문제 16. Verilog 정수 리터럴 표기법
* **질문:** 32'sd0에 대해 올바른 해석은?
* **정답: A. 32비트 signed decimal 0**
* **해설:** Verilog 언어 스펙 정수 리터럴 표기법 규칙에 의거하여, 맨 앞의 `32`는 표현될 상수의 비트 전폭 크기, `'s`는 부호 속성(Signed), `d`는 기수법 기준인 10진수(Decimal), 마지막 `0`은 실제 값 자체를 매핑하므로 '32비트 부호 있는 10진수 상수 0'을 올바르게 정의한 것입니다.

### 문제 17. 검증 타겟 명세
* **질문:** DUT는 무엇의 약자가가?
* **정답: B. Device Under Test**
* **해설:** 디지털 시스템 검증 및 시뮬레이션 자동화 파이프라인 엔지니어링 표준 용어로, DUT(Device Under Test)는 현재 검증용 테스트벤치(Testbench) 소프트웨어 자극 시나리오에 의해 논리적 무결성 및 타이밍 적합성을 정밀하게 평가받고 있는 '테스트 대상 하드웨어 디자인 실체'를 의미합니다.

### 문제 18. 빌드 자동화 스크립트의 계층 트리 지정
* **질문:** TOPLEVEL = mac, Makefile에서 이 설정은 무엇을 지정하는가?
* **정답: B. 최상위 Verilog 모듈 이름**
* **해설:** cocotb 코시뮬레이션 검증 툴체인 제어 환경에서 `TOPLEVEL` 환경 변수는 컴파일러가 전체 하드웨어 HDL 소스 트리 구조를 파싱할 때, 테스트벤치 프레임워크 신호선이 가상 가동 포트로 직접 바인딩 및 결합될 '최상위 루트(Root) 하드웨어 모듈 명칭'을 강제 타겟팅하는 지시어입니다.

### 문제 19. 파이썬 기반 하드웨어 코시뮬레이션 환경
* **질문:** cocotb는 무엇을 가능하게 하는가?
* **정답: B. Python으로 RTL을 제어하고 검증**
* **해설:** cocotb(Coroutine-based Co-simulation Testbench)는 진입 장벽이 높은 기존의 하드웨어 전용 검증 언어(SystemVerilog, UVM 등)를 완전 우회하여, 강력한 파이썬 언어 인프라와 비동기 코루틴(async/await 패턴) 기술을 접목함으로써 파이썬 환경에서 저수준 RTL 시뮬레이터 내부 신호를 실시간 스케줄링하고 검증할 수 있도록 지원하는 프레임워크입니다.

### 문제 20. 하드웨어-소프트웨어 공동 검증(Co-Verification)의 의의
* **질문:** Python MACUnit과 Verilog mac.v를 비교하는 가장 중요한 이유는?
* **정답: C. 서로 다른 추상화 수준의 구현이 동일한 알고리즘을 수행함을 검증하기 위해**
* **해설:** 소프트웨어적 고수준 추상화(Python) 모델과 저수준의 실제 게이트 논리 회로 서술(Verilog)은 구현 언어 및 타이밍 해석 층위가 완전히 다릅니다. 이 두 독립적 모델에 동일한 무작위 자극 입력(Random Vector)을 인가하고 출력을 크로스체킹함으로써, 우리가 구워낸 하드웨어 회로가 최초 알고리즘 수학적 제원 명세 및 정합성을 한 치의 오차도 없이 무결하게 충족하는지 입증하는 고도의 디버깅 기법입니다.

### 2. 다음 설계 단계로의 확장 (Systolic Expansion)
* 본 퀴즈와 보고서를 통해 완성한 단일 곱셈-누산기(MAC)의 설계와 시뮬레이터 디버깅 노하우는 향후 다차원 행렬 병렬 연산 코어인 **`Systolic Array (시스톨릭 어레이)`** 구조체 조립을 위한 기본 설계 블록(PE, Processing Element)의 밑거름이 됩니다. 개별 셀 레벨에서의 데이터 흐름(Dataflow) 제어 및 오버플로우 방지가 어떻게 시스템 전반의 AI 연산 가속화 효율성으로 결실을 맺는지 구조적 확장 학습의 토대를 형성합니다.
