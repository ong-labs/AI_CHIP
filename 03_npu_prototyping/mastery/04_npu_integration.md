# 04_npu_integration.md: Mastering NPU System Integration & Analytical Performance Modeling

이 문서는 하드웨어 설정(Config), 독립 가속 부품(Component), 그리고 시스톨릭 구조(Architecture)를 시간 축 위에서 통합한 실행 가능한 NPU 시뮬레이터 디자인 방법론을 다룹니다. 임의의 대규모 행렬 곱셈 워크로드에 대한 기능적 정합성을 검증함과 동시에, 해석적 수식(Analytical Equation) 모델을 통해 사이클, 에너지, 오프칩 트래픽 및 계산 자원 효율성을 다차원으로 측정·평가하는 계측 역량을 최종 확인합니다.

## 📝 개념 확인 문제 (Quiz)

### 문제 1. NPU 설계 통합의 핵심 목표
* **질문:** 3-3 회차의 핵심 목표를 가장 잘 설명하는 것은?
* **정답: B. Config, Memory, SystolicArray를 하나의 실행 가능한 시스템으로 통합한다.**
* **해설:** 본 단원의 핵심은 독립적인 개별 컴퓨터 구조 구성 요소들(정적 데이터 객체 및 단편화 모델)을 유기적으로 엮어내어, 시간 축 위에서 동적으로 구동하고 하드웨어 물리 지표를 종합 산출하는 '오케스트레이션 레이어(Orchestration Layer)'를 구축하는 데 있습니다.

### 문제 2. 시뮬레이터 인터페이스의 추상화 의의
* **질문:** 다음 코드가 의미하는 것으로 가장 적절한 것은?
  ```python
  npu = NPU(config)
  result = npu.run(A, B)
  ```
* **정답: B. Config를 기반으로 가상 NPU를 생성하고, 행렬 곱의 정확성과 성능 지표를 동시에 계산**
* **해설:** 이 두 줄의 진입점 인터페이스는 단순한 소프트웨어 함수 호출이 아니라, 하드웨어 사양 해석, 메모리 계층 할당, 가속 제어 스케줄러 가동, 물리 비용 변환 메커니즘을 연쇄적으로 실행하여 최종 검증 매트릭을 반환하는 가상 가속기 시스템의 런타임 구동을 의미합니다.

### 문제 3. 시뮬레이션 추상화 수준(Abstraction Level) 포지셔닝

* **질문:** 본 시뮬레이터의 성격은?
* **정답: C. Functional + Analytical Performance Model**
* **해설:** 본 가속기 모델은 무겁고 느린 클럭 단위 에뮬레이션을 우회하여, 출력 결과 텐서는 NumPy 백엔드를 통해 소프트웨어 레벨에서 고속으로 실제 계산(Functional)하고, 하드웨어 타이밍 및 전력 비용은 정형화된 수학적 수식(Analytical)으로 추정하는 고효율 하이브리드 시뮬레이터입니다.

### 문제 4. 하이브리드 모델의 기능 시뮬레이션 축

* **질문:** 다음 중 실제로 NumPy를 사용해 계산되는 값은?
* **정답: C. C**
* **해설:** `RunResult` 계약 지표 중 결과 행렬인 `C`는 실제 데이터 타입 정밀도 및 누산기 확장 폭(Mixed-Precision)을 모사하여 NumPy 행렬곱 연산으로 실제 수행됩니다. 반면 `cycles`, `energy_pj`, `pe_utilization` 등은 데이터 흐름 분석을 통한 해석적 모델 공식으로 유도됩니다.

### 문제 5. 공간적 타일 분할(Tile Tiling) 수치 해석

* **질문:** PE가 16×16일 때, M=33이면 $nt_m = \left\lceil \frac{M}{PE_R} \right\rceil$의 값은?
* **정답: B. 3**
* **해설:** $33 / 16 = 2.0625$이며, 천장 함수(Ceiling, $\lceil\rceil$) 연산에 의거하여 올림 처리되므로 총 타일 분할 개수는 3이 됩니다. 이는 물리 가속기 코어 평면 스펙을 넘어서는 잔여 데이터 행렬을 공간적으로 쪼개어 할당하는 마이크로아키텍처 스케줄링을 모사합니다.

### 문제 6. 다차원 중첩 루프 타일 총량 산출

* **질문:** PE=16×16, M=64, N=64, K=64일 때 전체 타일 개수는?
* **정답: C. 64**
* **해설:** 각 축별 타일 개수는 $nt_m = 64/16 = 4$, $nt_n = 64/16 = 4$, $nt_k = 64/16 = 4$입니다. 데카르트 곱(Cartesian Product) 기반의 가중치 고정 3중 루프가 순차 전개되므로 총 가동 타일 수 시퀀스는 $4 \times 4 \times 4 = 64$개가 됩니다.

### 문제 7. 수학적 올림 함수 모델링의 하드웨어적 본질

* **질문:** 타일 분할에서 천장 함수(⌈ ⌉)를 사용하는 이유는?
* **정답: B. 마지막 부분 타일도 하나의 타일로 처리해야 하기 때문**
* **해설:** 하드웨어 가속기 구조상 정수 배로 나누어떨어지지 않고 남은 에지 영역(Edge case)의 미세 데이터 블록이라 하더라도, 제어부는 물리적 자원을 할당하고 zero-padding 등을 가산하여 독립적인 하나의 타일 연산 시퀀스로 온전히 처리해야 하기 때문입니다.

### 문제 8. Roofline 사상 기반의 전역 사이클 공식 해석

* **질문:** 총 사이클 수를 계산하는 핵심 식은 $total\_cycles = \max(compute\_cycles, dram\_cycles) + overhead$ 이다. 이 식의 의미로 가장 적절한 것은?
* **정답: B. 계산과 메모리가 overlap되며 더 느린 쪽이 병목이 됨**
* **해설:** 가속기 아키텍처 내부에 온칩 버퍼 메모리 평면 상의 탁월한 더블 버퍼링(Double Buffering) 매커니즘이 탑재되어 있음을 모사한 공식입니다. 계산 주기와 대역폭 전송 주기가 하드웨어 레벨에서 상호 중첩(Overlap) 구동되므로, 두 물리 비용 중 더 큰 값(더 느린 쪽)이 시스템 전역 병목(Bottleneck)을 결정짓게 됩니다.

### 문제 9. 물리 시스템 오버헤드 파라미터 계장

* **질문:** 호스트 디스패치 오버헤드의 의미는?
* **정답: B. CPU가 NPU에 작업을 전달하는 비용**
* **해설:** 실제 가속기 시스템 가동 시, 호스트 프로세서(CPU)가 PCI-e 버스 인프라 등을 통해 NPU의 내부 커맨드 프로세서 레지스터로 명령 드라이버를 전송 및 디스패치(Dispatch)하는 물리 지연 시간 하한 마진을 모사한 고정 상수 오버헤드입니다.

### 문제 10. 가중치 고정(Weight-Stationary) 데이터플로우 제어 원리

* **질문:** Weight Stationary의 핵심은?
* **정답: B. Weight를 가능한 오래 유지하여 재사용**
* **해설:** 가중치 고정(Weight Stationary) 데이터플로우는 변동 주기가 길고 재사용성이 높은 신경망의 파라미터(Weight) 데이터를 온칩 가속 그리드 평면 레지스터에 최대한 긴 시간 상주 유지(Stationary)시킴으로써 외부 DRAM 메모리로의 가혹한 접근 통신 트래픽을 원천 상쇄하는 스케줄링 기법입니다.

### 문제 11. 온칩 메모리 용량 버퍼 마진에 따른 트래픽 가변 특성

* **질문:** Weight 전체가 SRAM에 모두 들어가면 DRAM에서 weight는 몇 번 읽는가?
* **정답: B. 한 번만 읽음**
* **해설:** 레이어 전체의 가중치 데이터 용량이 온칩 SRAM 버퍼 크기 마진 내에 완전히 상주 가능한 구조라면, 최초 가동 시 단 1회만 DRAM에서 읽어와 SRAM에 적재해 두고 루프 루틴 내내 무결하게 재사용할 수 있으므로 추가적인 외부 트래픽이 발생하지 않습니다.

### 문제 12. 외부 입력 메모리 트래픽의 수치적 구성

* **질문:** 다음 값 중 dram_read_bytes에 포함되는 것은?
* **정답: A. Weight + Input**
* **해설:** 가속기 코어가 행렬곱 연산을 수행하기 위해 외부 오프칩 대역으로부터 공급받아야 하는 소스 타겟 데이터는 가중치 파라미터(`Weight`)와 피처 맵 입력 데이터(`Input`)의 총합선으로 묶입니다.

### 문제 13. 외부 출력 메모리 트래픽 정의

* **질문:** dram_write_bytes는 무엇을 의미하는가?
* **정답: C. 최종 Output 저장량**
* **해설:** 모든 중간 $K$축 타일 분할 축의 부분합(Partial Sum) 누산 동작이 완벽히 종결되어 최종 완결된 형태의 완성형 출력 데이터 텐서 블록을 외부 오프칩 메모리 영역으로 내보내어 하차 기록(`DRAM Write`)하는 총 바이트 용량을 뜻합니다.

### 문제 14. 하드웨어 활용률 공식 해체

* **질문:** PE Utilization의 정의는 $pe\_utilization = \frac{actual\_macs}{full\_pe\_macs}$ 이다. 올바른 해석은?
* **정답: A. 실제 연산량 ÷ 이상적 연산량**
* **해설:** 분자의 `actual_macs`는 알고리즘이 요구하는 순수 원소 연산량($M \times N \times K$)이며, 분모의 `full_pe_macs`는 분할된 타일 매핑 파티션 상에서 하드웨어 평면 배열 전체가 가동 기간 동안 물리적으로 채울 수 있는 최대 이론적 계산 한계 총량입니다.

### 문제 15. 에지 타일 패딩 패널티에 의한 가속 그리드 비효율화

* **질문:** PE=16×16, 워크로드가 8×8×8일 때 utilization이 크게 낮아지는 이유는?
* **정답: C. 많은 PE가 유휴 상태이기 때문**
* **해설:** 하드웨어 가속기가 제공하는 물리적 병렬 연산 공간 평면($16 \times 16$)보다 실제 알고리즘 워크로드의 차원 스케일($8 \times 8$)이 작을 경우, 연산 그리드의 상당수 프로세싱 엘리먼트(PE)가 유효 데이터를 할당받지 못하고 노는 '공간적 자원 유휴 현상(Underutilization)' 및 제로 패딩 에지 오버헤드가 발생하기 때문입니다.

### 문제 16. 다중 소스 기반 토탈 에너지 수식 해석

* **질문:** 총 에너지 계산식은 $E_{total} = E_{MAC} + E_{DRAM} + E_{SRAM}$ 이다. 올바른 범위는?
* **정답: C. MAC, DRAM, SRAM 모두 고려**
* **해설:** 가속기 시스템 전폭의 물리 전력 프로필을 계측하기 위해서는 연산 코어의 산술 스위칭 비용($E_{MAC}$)뿐만 아니라, 데이터 이동 트래픽이 통과하는 온칩 버퍼 메모리 비용($E_{SRAM}$) 및 외부 오프칩 패키지 와이어 전하 이동 패널티($E_{DRAM}$) 소스를 누락 없이 통합 합산해야 합니다.

### 문제 17. 컴퓨터 계층 구조별 단위 물리 전하 비용 격차

* **질문:** 일반적으로 byte당 에너지가 가장 큰 것은?
* **정답: C. DRAM**
* **해설:** 외장 `DRAM` 액세스는 동일 실리콘 다이(Die) 바깥 영역의 패키지 인터페이스 및 PCB 인쇄 회로 선로를 직접 타고 넘어가는 Off-chip 전송 구조체이므로, 배선 자체의 물리적 기생 커패시턴스 마진이 온칩 레지스터 및 SRAM 버퍼선에 비해 수백 배 이상 무거워 단위 데이터 이동당 소비 에너지가 압도적으로 가장 큽니다.

### 문제 18. 기능 정합성 검증 회귀 함수

* **질문:** np.allclose(r.C, expected_C)가 검증하는 것은?
* **정답: B. 정확성**
* **해설:** 가상 가속기 인프라 모델링 내부 루프를 통과하여 도출된 결과 텐서 객체(`r.C`)가 부동소수점 오차 마진 및 정밀도 비트 폭 내에서 골든 레퍼런스 알고리즘 기준 데이터(`expected_C`)와 수치적으로 완전히 일치하는지 기능적 정확성(Functional Correctness)을 검증하는 지표입니다.

### 문제 19. 수치 분석 테스트벤치 목적성 판정

* **질문:** Test 3 (8×8×8)의 주요 목적은?
* **정답: B. Underutilization 검증**
* **해설:** 하드웨어 가속기 평면 스펙($16 \times 16$)보다 가혹하게 작은 규모의 초소형 정방 행렬 워크로드를 의도적으로 주입하여, 시뮬레이터 제어부가 에지 타일 제로 패딩 오버헤드와 자원 유휴 상태에 따른 공간 활용 효율성 폭락 현상을 정량 데이터로 올바르게 식별 및 리포팅해 내는지 검증하기 위한 벤치마크 테스트입니다.

### 문제 20. 시스템 통합 모델링 기법의 본질 요약

* **질문:** 다음 중 3-3 회차를 가장 잘 요약한 것은?
* **정답: B. 부품을 조립해 성능을 측정 가능한 가상 NPU를 완성하는 단계**
* **해설:** 본 단원은 파편화된 개별 설계 명세 파라미터와 독립 부품 공식 모델들을 가상의 시간 축(Time scale) 및 스케줄링 루프 위에서 결합 유기적으로 연결함으로써, 가속기 구조 전체의 트레이드오프 관계를 정량 실측 계측해 낼 수 있는 무결한 가상 반도체 시스템(System Model)을 확립하는 아키텍처 통합의 핵심 단계입니다.
