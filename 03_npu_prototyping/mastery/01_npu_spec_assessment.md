이 문서는 [01_npu_architecture_report.md](../analysis/01_npu_architecture_report.md)와 [01_block_diagram_scrutiny.md](../analysis/01_block_diagram_scrutiny.md)에서 다룬 NPU 아키텍처 정의 및 블록 다이어그램 분석 내용과 [01_npu_architecture_bench.py](../lab/01_npu_architecture_bench.py) 실습을 통해 구현한 스펙 에스티메이터의 동작 원리를 검증합니다. ## 📝 개념 확인 문제 (Quiz)

### 문제 1. Target Workload의 정의
* **질문:** NPU 설계에서 Target Workload를 가장 잘 설명한 것은 무엇인가?
* **정답: B. 칩이 주로 해결할 문제 유형을 정의하는 단계**
* **해설:** 가속기 하드웨어가 시스템 레벨에서 해결하고자 하는 도메인(LLM 학습/추론, 온디바이스 AI 등)을 명확히 규정하는 설계의 최상위 시작점입니다.

### 문제 2. Defining Feature의 목적
* **질문:** Defining Feature의 목적은 무엇인가?
* **정답: A. 칩의 핵심 설계 철학을 한 문장으로 요약한다.**
* **해설:** 목표 데이터 타입, 온칩 버퍼 용량, PE 구조 등 가속기의 핵심 정체성을 한 문장으로 압축하여 향후 하드웨어 세부 설계의 나침반 역할을 수행하도록 합니다.

### 문제 3. INT8 정밀도의 주요 용도
* **질문:** INT8을 사용하는 가장 일반적인 목적은 무엇인가?
* **정답: B. AI 추론 최적화**
* **해설:** 양자화(Quantization)를 통해 데이터의 비트 폭을 줄임으로써 메모리 대역폭 소모량과 가속기 면적을 최소화하고, 추론 환경에서의 전성비를 극대화하기 위해 사용됩니다.

### 문제 4. FP32의 데이터 크기
* **질문:** FP32의 크기는 몇 Byte인가?
* **정답: C. 4 Byte**
* **해설:** 단정밀도 부동소수점(Single-Precision Floating Point)인 FP32는 하드웨어 물리 공간에서 32비트, 즉 4바이트의 영역을 점유합니다.

### 문제 5. PE(Processing Element)의 주된 역할
* **질문:** PE(Processing Element)의 주된 역할은 무엇인가?
* **정답: B. Multiply-Accumulate 수행**
* **해설:** PE는 인공지능 행렬 연산의 기본 단위인 곱셈 및 부분합 누산(MAC)을 유기적으로 수행하는 핵심 가속 엔진입니다.

### 문제 6. 2차원 시스톨릭 어레이의 확장 스케일
* **질문:** 16 × 16 Systolic Array의 총 PE 수는?
* **정답: D. 256**
* **해설:** 16개의 행(Rows)과 16개의 열(Columns)로 배치된 2차원 격자 아키텍처 구조이므로 총 $16 \times 16 = 256$개의 PE를 확보하게 됩니다.

### 문제 7. 데이터플로우(Dataflow)의 역할
* **질문:** Dataflow가 결정하는 것은 무엇인가?
* **정답: B. 어떤 데이터를 PE 내부에 유지하며 재사용할지**
* **해설:** 한정된 하드웨어 자원 하에서 가중치(WS), 출력(OS), 입력(IS) 중 어떤 데이터를 내부 레지스터에 고정하여 재사용 효율을 극대화할 것인지를 제어하는 전략입니다.

### 문제 8. Memory-bound 워크로드 최적화
* **질문:** Batch-1 GEMV와 같이 Memory-bound 성격이 강한 경우 일반적으로 유리한 데이터플로우는?
* **정답: C. IS**
* **해설:** 입력 데이터가 벡터 형태($M=1$)로 재사용성이 극도로 높을 때는 입력을 PE 레지스터에 고정하는 Input Stationary(IS) 방식이 DRAM 트래픽 절감에 가장 유리합니다.

### 문제 9. NPU 설계의 절대적 원칙
* **질문:** 다음 중 NPU 설계의 핵심 원칙은?
* **정답: B. Compute is cheap. Data movement is expensive.**
* **해설:** 하드웨어 물리 실리콘 레벨에서 단일 MAC 연산(pJ 수준)보다 외부 DRAM에 접근하여 데이터를 이동시키는 비용($\sim100\text{ pJ}$)이 수백 배 더 무겁다는 아키텍처적 대전제입니다.

### 문제 10. 클럭 주파수(Clock Frequency)의 아키텍처적 의미
* **질문:** 1.0 GHz는 무엇을 의미하는가?
* **정답: C. 초당 10억 번 동작**
* **해설:** 주파수 단위인 1 GHz는 전역 동기 클럭 신호가 하드웨어 내부에서 초당 $10^9$번(10억 번) 진동하며 시스템의 상태를 업데이트함을 뜻합니다.

### 문제 11. 이론적 가용 성능 공식
* **질문:** Peak Ops/s를 계산하는 공식은?
* **정답: A. $Peak\ Ops/s = N_{PE} \times 2 \times Clock$**
* **해설:** 하드웨어가 낼 수 있는 최대 연산 성능은 총 PE 개수에 단일 MAC 유닛이 1사이클에 수행하는 2 Operations(곱셈+덧셈)와 동작 주파수를 곱하여 도출됩니다.

### 문제 12. 피크 성능 산출 계산
* **질문:** 256개의 PE와 1 GHz 클럭일 때 Peak Compute는?
* **정답: B. 512 GOPS**
* **해설:** 이론적 가용 성능 공식에 대입하면 $256 \times 2 \times 1\text{ GHz} = 512\text{ GOPS}$ (초당 5120억 번 연산)가 산출되며, 이는 $0.512\text{ TOPS}$에 해당합니다.

### 문제 13. 온칩 메모리(SRAM)의 핵심 기능
* **질문:** 온칩 SRAM의 주된 목적은 무엇인가?
* **정답: A. DRAM 접근 감소**
* **해설:** 외부 DRAM 대비 속도가 빠르고 에너지가 수십 배 저렴한 칩 내부 SRAM 영역에 입력 및 가중치 데이터를 임시 버퍼링하여 대역폭 병목을 제어합니다.

### 문제 14. 메모리 단위 환산
* **질문:** 16,384 KB는 몇 MB인가?
* **정답: C. 16 MB**
* **해설:** 데이터 단위 장벽인 $1\text{ MB} = 1024\text{ KB}$의 기준에 따라, $16384 / 1024 = 16\text{ MB}$ 용량이 환산됩니다.

### 문제 15. DRAM Bandwidth의 정의
* **질문:** DRAM Bandwidth는 무엇을 의미하는가?
* **정답: B. 외부 메모리 데이터 공급 속도**
* **해설:** 가속기 칩 바깥에 존재하는 물리적 저장소(DRAM) 인터페이스에서 내부 하드웨어 코어로 초당 전달할 수 있는 최대 데이터의 전송 대역폭(Bytes/sec)입니다.

### 문제 16. 하드웨어 스펙 구조체 명세화
* **질문:** NPUConfig Dataclass의 목적은 무엇인가?
* **정답: B. 설계 파라미터를 하나의 구조체로 통합한다.**
* **해설:** 분산되어 있는 복잡한 시스템 마이크로아키텍처 변수(정밀도, PE 배열, 클럭, 메모리 등)를 하나의 객체로 명문화하여 아키텍처 사양을 논리적으로 확정 짓습니다.

### 문제 17. 루프라인 모델(Roofline Analysis)의 효용성
* **질문:** Roofline Analysis는 무엇을 분석하는가?
* **정답: B. 이론 성능과 병목 지점**
* **해설:** 특정 하드웨어 스펙 스펙시트 위에서 구동될 워크로드의 산술 강도(AI)를 기반으로 성능 한계를 도출하고, 해당 작업이 연산 병목인지 메모리 대역폭 병목인지 사전 판정합니다.

### 문제 18. 설계 철학 구체화 사례
* **질문:** 다음 중 Defining Feature의 예로 가장 적절한 것은?
* **정답: B. INT8 + 16MB SRAM, 16×16 Systolic for Batched Inference**
* **해설:** 타겟 데이터 정밀도(INT8), 온칩 버퍼 크기(16MB), 가속기 배열 사양($16 \times 16$) 및 타겟 워크로드의 형태를 단 한 문장으로 완벽히 표현하고 있습니다.

### 문제 19. 구조적 설계 개념도 분석
* **질문:** 블록 다이어그램은 무엇을 보여주는가?
* **정답: B. 설계 의사결정의 구조적 흐름**
* **해설:** 회로의 미시적인 세부 배선 대신 시스템 설계자가 '워크로드 사양 정의 $\rightarrow$ 아키텍처 하드웨어 변수 선택 $\rightarrow$ 이론적 가용 성능 분석'으로 나아가는 엔지니어링 사고 흐름을 명료화합니다.

### 문제 20. 하드웨어 아키텍트의 본질적 화두
* **질문:** 이번 실습 전체를 관통하는 가장 중요한 질문은 무엇인가?
* **정답: C. 이 칩은 무엇을 가장 잘 계산하도록 설계할 것인가?**
* **해설:** 도메인 특화 가속기(DSA) 설계의 본질은 주어진 특정 하드웨어 제약 조건 하에서 목표 알고리즘 연산을 비용 최적으로 해결해 내는 목적성에 귀결됩니다.
