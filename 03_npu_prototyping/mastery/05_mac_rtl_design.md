# 05_mac_rtl_design.md: Verilog HDL MAC Core & RTL Simulation Verification

이 문서는 가속기 하드웨어의 가장 핵심적인 산술 연산 장치인 MAC(Multiply-Accumulate) 유닛의 Verilog RTL 설계 원리와 부호 있는(Signed) 정수 연산 체계, 그리고 상용 시뮬레이션 환경에서의 동기식 제어 및 파형 디버깅 방법론을 다룹니다. `mac.v` 하드웨어 소스 코드를 기반으로 비트 폭 확장, 넌블로킹 할당문, 동기식 리셋 메커니즘의 무결성을 최종 검증합니다.

---

## 📝 개념 확인 문제 (Quiz)

### 문제 1. MAC 연산의 수학적 정의
* **질문:** 수업 중 만든 mac.v 모듈이 수행하는 연산은 무엇인가?
* **정답: C. acc = acc + (in_data * weight)**
* **해설:** MAC(Multiply-Accumulate) 유닛은 입력 데이터(`in_data`)와 가중치(`weight`)를 매 클럭 주기마다 곱하고, 그 결과를 누적기 레지스터(`acc`)에 지속적으로 더해 나가는 가속기의 핵심 산술 커널 연산을 수행합니다.

### 문제 2. 가속기 하드웨어 회로 속성 분류
* **질문:** mac.v의 모듈은 어떤 종류의 회로인가?
* **정답: B. 순차 회로**
* **해설:** `mac.v` 모듈은 내부적으로 과거의 누산 상태 값을 보관하는 기억 소자(레지스터)를 포함하며, 전역 클럭 신호에 동기화되어 상태가 전이되는 전형적인 동기식 순차 논리 회로(Sequential Logic Circuit)입니다.

### 문제 3. 산술 컴포넌트의 시스템 아키텍처적 정체성
* **질문:** 이 모듈의 주요 역할은 무엇인가?
* **정답: C. Multiply-Accumulate Unit**
* **해설:** 본 회로는 단독 곱셈기나 단순 버퍼 저장소가 아니며, 곱셈기(Multiplier)와 누산 가산기(Adder Core)가 하나의 동기식 파이프라인 평면으로 결합된 고성능 Multiply-Accumulate (MAC) 연산 장치입니다.

### 문제 4. 포트 디클레이션 및 부호 속성 명세
* **질문:** input wire signed [7:0] in_data의 의미는 무엇인가?
* **정답: B. 8비트 부호 있는 정수**
* **해설:** `[7:0]` 선언은 총 8비트(1바이트)의 물리적 데이터 버스 전폭을 점유함을 나타내며, `signed` 식별자는 해당 입력 신호선선이 2의 보수(2's complement) 체계를 따르는 부호 있는 정수 데이터임을 하드웨어 컴파일러에게 명시하는 역할을 합니다.

### 문제 5. 2의 보수 정밀도 표현 한계선
* **질문:** 8비트 signed 정수의 표현 범위는?
* **정답: C. -128 ~ 127**
* **해설:** 부호 비트(MSB)를 포함하는 8비트 2의 보수 부호 있는 정수 체계가 가질 수 있는 수학적 정수 표현 마진 영역은 최소 $-2^7$부터 최대 $2^7-1$까지이므로 정확히 $-128 \sim 127$ 범위에 수렴합니다.

### 문제 6. 하드웨어 신호 파형 수준 수치 해석
* **질문:** in_data = -3, weight = 5일 때 INT8 곱셈 결과는? (파형 관점 - 하드웨어 신호 관점에서 바라보기)
* **정답: C. F1**
* **해설:** $-3 \times 5 = -15$입니다. 이를 하드웨어 8비트 부호 있는 16진수(Hexadecimal) 비트 패턴으로 변환하면, $+15$의 2진수 값인 `0000_1111`을 반전한 후 1을 더한 `1111_0001`이 되므로 상위 4비트는 `F`, 하위 4비트는 `1`이 되어 파형 상에는 `F1` 신호로 관찰됩니다.

### 문제 7. 산술 곱셈 회로의 물리 비트 폭 팽창 규칙
* **질문:** 8비트 signed × 8비트 signed의 결과 비트 폭은?
* **정답: B. 16비트**
* **해설:** 디지털 하드웨어 산술 논리에서 두 부호 있는 $N$비트 정수를 곱했을 때, 정보 손실과 오버플로우 없이 수치 정합성을 온전히 방어하기 위해 자연적으로 도출되는 출력 버퍼의 비트 대역폭은 정확히 $2N$비트(8비트 × 2 = 16비트)가 됩니다.

### 문제 8. 혼합 정밀도 가산 시의 부호 확장 메커니즘
* **질문:** 16비트 곱셈 결과를 32비트 acc에 더할 때 자동으로 일어나는 것은?
* **정답: B. Sign Extension**
* **해설:** Verilog 소스 코드 내 피연산자들이 모두 `signed` 속성으로 올바르게 선언되어 있으므로, 16비트 곱셈 결과물을 더 큰 32비트 누산 평면 가산기에 인가할 때 최상위 부호 비트(MSB)의 전하 상태가 상위 16비트 빈 공간으로 자동으로 복제 채워지는 부호 확장(Sign Extension)이 발동합니다.

### 문제 9. 상수 부호 확장 리터럴의 16진수 변환
* **질문:** 16비트 값 16'sd-1이 32비트로 확장되면?
* **정답: B. 32'hFFFF_FFFF**
* **해설:** 부호 있는 정수 $-1$은 모든 비트가 `1`인 상태로 표현됩니다. 16비트의 `16'hFFFF` 상태에서 32비트 영역으로 Sign Extension이 수행되면 상위 16비트 역시 부호 비트인 `1`로 가득 채워지므로 `32'hFFFF_FFFF` 가 도출됩니다.

### 문제 10. 동기식 파이프라인 트리거링 시점 식별
* **질문:** always @(posedge clk)는 언제 실행되는가?
* **정답: C. clk 상승 에지에서**
* **해설:** `posedge` 지시어는 Positive Edge, 즉 전역 주파수 클럭 신호가 로우(0) 레벨에서 하이(1) 레벨로 천이 발산하는 '상승 에지 변곡점'을 의미하며, 순차 회로 플립플롭이 동기식으로 거동하는 타이밍 기점입니다.

### 문제 11. 리셋 트리거 발생 시의 내부 레지스터 상태 전이
* **질문:** rst = 1이면 다음 클록 상승 에지에서 acc는 어떻게 되는가? (mac.v 코드에서)
* **정답: C. 0으로 초기화**
* **해설:** `mac.v` 코드를 보면 `always @(posedge clk)` 구문 내부 최상단 분기 제어식에서 `if (rst)` 조건을 만족하는 즉시 누산기 공간에 부호 있는 32비트 10진수 상수인 `32'sd0`을 누산 대입하도록 강제하고 있으므로 무결하게 초기화됩니다.

### 문제 12. 감도 목록(Sensitivity List) 구성과 리셋 특성 연계
* **질문:** rst가 sensitivity list에 포함되지 않은 이유는?
* **정답: B. synchronous reset이기 때문**
* **해설:** 리셋 신호가 인가되더라도 즉시 초기화 회로가 도는 비동기 방식과 달리, 본 코어는 오직 클럭 상승 에지가 터지는 타이밍에만 `rst` 상태를 체크하여 초기화하는 동기식 리셋(Synchronous Reset) 방식을 채택했기 때문에 감도 목록에 오직 `posedge clk`만 명세합니다.

### 문제 13. 넌블로킹 할당문(Non-blocking Assignment)의 구동 이론
* **정답: C. 클록 종료 시점에 갱신 예약**
* **해설:** Verilog 순차 회로 전용 대입 연산자인 `<= (Non-blocking Assignment)`는 클럭 상승 에지 순간 우변의 조합 논리 계산 결과 상수를 임시 버퍼에 캡처해 둔 뒤, 해당 시뮬레이션 타임 스텝 및 클럭 경계가 완벽히 종결 마감되는 시점에 레지스터 공간으로 값을 일제히 업데이트 예약 갱신합니다.

### 문제 14. 동시 병렬성 하드웨어 모사 규칙
* **정답: B. 병렬적 레지스터 동작 모델링**
* **해설:** 실제 실리콘 반도체 평면 상의 수많은 플립플롭 레지스터들은 동일 클럭 박자에 맞춰 '동시 병렬적(Parallel)'으로 데이터를 상호 교환합니다. 소프트웨어의 순차적(Sequential)인 블로킹 할당문(`=`)을 순차 회로에 오용하면 신호 간 경쟁 조건(Race condition)이나 의도치 않은 래치(Latch) 병목 버그가 발생하기 때문에 반드시 넌블로킹 문법을 강제해야 합니다.

### 문제 15. 시뮬레이션 타임 트레이스 정량 추정
* **질문:** 초기 acc = 0이고, 3번의 클록 동안 (in_data, weight)가 각각 (2,3), (4,5), (-2,10)일 때 최종 acc 값은?
* **정답: A. 6**
* **해설:** 매 클럭 에지마다 인가되는 데이터 쌍의 곱셈 결과가 누적 레지스터에 순차 축적됩니다.
  * 사이클 1: $0 + (2 \times 3) = 6$
  * 사이클 2: $6 + (4 \times 5) = 26$
  * 사이클 3: $26 + (-2 \times 10) = 26 - 20 = 6$
  따라서 세 번째 클럭 마감 시점의 최종 레지스터 적재 상수는 정확하게 `6`이 리포팅됩니다.

### 문제 16. 정밀도 한계점 경계 연산 산출
* **질문:** in_data = -128, weight = 127일 때 곱셈 결과는?
* **정답: A. -16256**
* **해설:** 부호 있는 8비트 정수가 가질 수 있는 최극단 음수 한계치인 `-128`과 최극단 양수 한계치인 `127`을 곱하면 정직한 대수학 연산 결과에 의거하여 정확히 `-16,256`이 도출되며, 이 수치는 `INT16` 물리 폭 범위 내에 안전하게 매핑됩니다.

### 문제 17. 32비트 레지스터 저장 한계선 식별
* **질문:** 32비트 signed accumulator의 최대값은?
* **정답: A. 2³¹−1**
* **해설:** 부호 있는 32비트 정수 공간에서 최상위 1비트는 부호 판별선(MSB)으로 잠금 선언되므로, 양수 축으로 보장할 수 있는 실질 최대 표현 한계 데이터 공간 스케일은 $2^{31}-1$ (즉, $+2,147,483,647$)이 됩니다.

### 문제 18. 데이터 파괴 현상 매커니즘 고찰
* **질문:** acc가 최대값에서 양수를 더하면 일반적인 2의 보수 연산 결과는?
* **정답: B. Wrap-around (overflow)**
* **해설:** 포화 제어 회로(Saturation Logic)가 누락된 일반적인 기본 2의 보수 가산기 구조에서는 최대 양수 한계 한계점($2^{31}-1$) 상태에서 최하위 비트에 단 `1`이라도 추가 합산이 이뤄지면, 부호 비트선(MSB)이 `1`로 강제 반전되어 비정상적인 극단적 음수($-2,147,483,648$)로 값이 튕겨 넘치는 랩어라운드 오버플로우(Wrap-around Overflow) 현상이 발생합니다.

### 문제 19. 파일 입출력 시뮬레이션 지시어 식별
* **질문:** $dumpfile("dump.vcd");의 역할은?
* **정답: B. VCD 파일 생성 지정**
* **해설:** 시뮬레이션 테스트벤치 환경에서 구동되는 시스템 컴파일러에게 매 사이클 단위 미시적 신호 변동 레벨을 정밀하게 기록 및 추출해 낼 원본 VCD(Value Change Dump) 파일의 명칭과 물리 생성 경로를 명령 지정하는 특수 시스템 시지어입니다.

### 문제 20. 하드웨어 파형 디버깅 플랫폼 연계
* **질문:** 생성된 dump.vcd 파일을 주로 확인하는 프로그램은?
* **정답: A. GTKWave**
* **해설:** 추출 완료된 가상 칩 클럭 전하 파형 파일(`dump.vcd`)을 그래픽 레이아웃 상에 시각화하여 매 타이밍 격자 단위 비트 오동작과 신호 지연 마진을 명밀히 추적·디버깅할 때 사용하는 전용 오픈소스 Waveform 뷰어 툴입니다.
