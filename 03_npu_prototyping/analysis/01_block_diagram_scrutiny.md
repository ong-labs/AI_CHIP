# 01_block_diagram_scrutiny.md: NPU Architecture Design Flow & Block Diagram Analysis

본 문서는 NPU 마이크로아키텍처 설계의 초기 단계에서 수많은 설계 변수들을 구조화하고, 의사결정의 흐름을 시각적으로 명확히 하기 위한 블록 다이어그램 분석 가이드입니다.

---

## 1. 블록 다이어그램(Block Diagram)의 정의

블록 다이어그램(Block Diagram)은 시스템을 구성하는 주요 구성 요소를 상자(Block)로 표현하고, 각 구성 요소 사이의 관계와 데이터 흐름을 화살표(→)로 나타낸 구조도입니다.

회로의 세부 배선이나 구체적인 코드 구현을 복잡하게 보여주는 것이 아니라, 시스템이 어떤 핵심 요소들로 구성되어 있고 이 요소들이 어떤 순서와 관계로 연결되는지 한눈에 보여주는 개념도라고 이해하면 됩니다.

---

## 2. 왜 블록 다이어그램을 그리는가?

NPU 설계 프로세스에는 다음과 같이 하드웨어와 소프트웨어를 아우르는 수많은 설계 변수(Design Parameters)들이 복합적으로 존재합니다.

* 어떤 워크로드(Workload)를 목표로 하는가?
* 어떤 데이터 타입(Data Type)을 사용할 것인가?
* PE(Processing Element)를 몇 개 배치할 것인가?
* 어떤 데이터플로우(Dataflow)를 적용할 것인가?
* SRAM과 DRAM의 규격 및 용량은 얼마나 필요한가?

이 요소들을 개별적으로 파편화해서 보면 대단히 산만하지만, 구조적으로 연결하면 설계 의사결정의 흐름이 명확해집니다. 즉, 블록 다이어그램은 **각 설계 결정들이 어떻게 서로 유기적으로 영향을 주고받는지를 시각적으로 정리하는 도구**입니다.

---

## 3. NPU 설계 아키텍처 흐름도

본 실습 및 프로토타이핑 과정에서 정립한 하드웨어 설계 의사결정 파이프라인의 핵심 아키텍처 흐름입니다.

```text
Target Workload (해결하고자 하는 문제 정의)
      │
      ▼
Defining Feature (칩의 핵심 설계 철학 요약)
      │
      ▼
Data Type Selection (데이터 정밀도 타입 선택)
      │
      ▼
PE Array Shape (산술 연산 유닛의 배열 형태 및 개수 결정)
      │
      ▼
Dataflow Selection (온칩 데이터 재사용 및 유지 전략 선택)
      │
      ▼
Clock / SRAM / DRAM Bandwidth (성능 및 시스템 메모리 자원 정의)
      │
      ▼
NPUConfig Dataclass (설계 파라미터의 구조체 통합 명세화)
      │
      ▼
Peak TOPS / Roofline Analysis (이론적 최대 성능 산출 및 병목 분석)
```

---

## 4. 각 설계 블록의 아키텍처적 의미

### 4.1 Target Workload

* **의미**: 가속기 하드웨어가 칩 레벨에서 어떤 문제를 해결할 것인지 명확히 정의하는 시작점입니다.
* **도메인 예시**: `LLM Training`, `LLM Inference`, `Edge AI`, `Mobile AI`

### 4.2 Defining Feature

* **의미**: 칩의 핵심 설계 철학 및 목표 사양을 직관적으로 이해할 수 있도록 한 문장으로 요약합니다.
* **예시**: `INT8 + 16MB SRAM, 16×16 Systolic for Batched Inference` $\rightarrow$ **"적당히 정밀하면서 대역폭을 확보한 빠른 추론기"**

### 4.3 Data Type Selection

* **의미**: 연산 정밀도와 메모리 요구량의 균형점을 찾기 위해 하드웨어 데이터 타입을 선택합니다.
* **지원 정밀도 종류**: `INT8`, `BF16`, `FP16`

### 4.4 PE Array Shape

* **의미**: 하드웨어 연산 가동률을 극대화하기 위해 행렬 연산을 담당할 Processing Element의 개수와 2차원 배열 형태를 결정합니다.
* **스케일 예시**: `16×16 (256 PEs)`, `64×64`, `128×128`

### 4.5 Dataflow Selection

* **의미**: 온칩 데이터 통신 에너지를 줄이기 위해 어떤 데이터를 PE 내부에 유지(Stationary)하며 재사용할지 제어부 전략을 결정합니다.
* **전략 종류**: 가중치 고정형(`WS`), 출력 고정형(`OS`), 입력 고정형(`IS`)

### 4.6 Clock / SRAM / DRAM Bandwidth

* **의미**: 칩의 가동 주파수와 물리적인 메모리 자원 규모를 결정하여 실질적인 성능 한계를 정의합니다.
* **레퍼런스 스펙**: `1.0 GHz Clock`, `16 MB 온칩 SRAM`, `200 GB/s 외부 DRAM BW`

### 4.7 NPUConfig Dataclass

* **의미**: 위 단계들에서 개별적으로 결정된 하드웨어 설계 파라미터들을 유기적으로 관리하기 위해 하나의 하드웨어 기술 구조체(Python Dataclass)로 통합 명세화합니다.

### 4.8 Peak TOPS / Roofline Analysis

* **의미**: 구조체로 통합된 아키텍처 설계 결과를 기반으로, 수학적 모델링을 통해 이론적 최대 연산 성능을 산출하고 시스템의 물리적 병목 구간(Compute vs Memory Bound)을 사전 예측 분석합니다.

---

## 5. 요약 (Conclusion)

블록 다이어그램은 ‘워크로드 정의 $\rightarrow$ 아키텍처 결정 $\rightarrow$ 성능 분석’으로 유기적으로 이어지는 NPU 마이크로아키텍처 설계의 전체적인 사고 흐름(Design Thought Process)을 한눈에 보여주는 강력한 아키텍처 구조도입니다.

이 구조적 관계를 명확히 함으로써, 실제 실리콘 회로 설계로 진입하기 전 하드웨어 성능 사양 사조정 및 면적/전력에 대한 대략적인 물리적 비용을 정량적으로 산출해 볼 수 있는 든든한 기반이 됩니다.
