# 07_npu_mac_v2_report.md: Production-Ready Mass-Production Accelerator MAC RTL Design and Pipeline Verification Report

본 보고서는 하드웨어 컴포넌트 고도화 실습인 [mac_v2.v](../lab/07_ad_mac/mac_v2.v) 설계도와 [test_mac_v2.py](../lab/07_ad_mac/test_mac_v2.py) 코시뮬레이션 테스트벤치를 바탕으로 작성되었습니다. 기존의 개념 실증용 유닛([mac.v](../lab/03_mac_verilog/mac.v))이 가졌던 아키텍처적 한계를 극복하고, 실제 상용 실리콘 칩(Production Chip) 환경에서 요구되는 타이밍 마진, 전력 관리, 예외 처리 및 버스 인터페이스 핸드셰이크 프로토콜을 반영한 양산형 가속기 산술 연산 장치의 마이크로아키텍처 구조를 심층 분석하는 것을 목적으로 합니다.

## 1. 개요: 개념 실증형(mac.v)과 양산형(mac_v2.v)의 대조

디지털 회로 설계 자산(IP)을 구축할 때, 기본 산술 수식($acc \leftarrow acc + a \times b$)을 구동하는 것과 실제 반도체 칩 환경에 적합한 가동 코어를 빌드하는 것 사이에는 거대한 추상화 격차가 존재합니다. `mac_v2.v`는 하드웨어 파이프라인 지연을 도입하여 타이밍 병목을 파괴하고, 가변 스펙에 대응하기 위한 파라미터화를 적용하는 등 상용 DSA(Domain-Specific Accelerator) 아키텍처가 갖추어야 할 8가지 필수 엔지니어링 요소를 이식한 집약체입니다.

## 2. 8대 생산성 하드웨어 개선 사양 심층 분석 (Architectural Breakdown)

### 2.1 컴포넌트 재사용성을 위한 파라미터화 (Parameterization)
```verilog
module mac_v2 # (
    parameter DATA_WIDTH = 8,
    parameter ACC_WIDTH  = 32
) ( ... );
```

* **하드웨어적 본질**: 입력 데이터 폭과 내부 누산 레지스터 폭을 컴파일 타임 하드웨어 매크로 변수로 가변 제어합니다.
* **아키텍처적 도입 이유**: 신경망 가속기는 타겟 어플리케이션과 압축 양자화 알고리즘 정책에 따라 데이터 정밀도를 다이내믹하게 스위칭해야 합니다 (INT4 $\rightarrow$ INT8 $\rightarrow$ INT16). 만약 이 제원 정보가 하드코딩(Hard-coded)되어 있다면 정밀도가 바뀔 때마다 매번 새로운 RTL 모듈을 레이아웃 단계부터 다시 설계해야 하는 병목 비용이 터집니다. 본 고도화를 통해 최상위 컴파일러 옵션 설정에 따라 연산기 평면의 물리 비트 폭이 유연하게 가변 재사용됩니다.

### 2.2 전원 인가 노이즈 방어를 위한 Active-low Reset (`rst_n`)

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) ...
```

* **하드웨어적 본질**: 리셋 제어 신호선의 물리 전위 레벨이 `0(GND)`으로 떨어지는 순간 시스템 내부 플립플롭의 상태를 초기화(Reset) 구동합니다.
* **아키텍처적 도입 이유**: 반도체 공정 표준 및 산업계 표준(Industrial Standard) 규격입니다. 칩에 전원이 인가되는 전력 On 직후 시점에는 실리콘 전체 평면의 전위가 불안정하여 물리 노이즈(Glitch)가 급증합니다. Active-high 방식은 노이즈 전하에 의해 시스템이 오동작할 위험이 높은 반면, Active-low 리셋 메커니즘은 리셋 라인을 접지 상태로 유지하다가 안정화 기점에서 하이 레벨로 끌어올리므로 외부 전하 임베디드 노이즈로부터 아키텍처를 안전하게 보호합니다.

### 2.3 스톨 가동 및 전력 세이빙을 위한 글로벌 Enable 신호 (`en`)

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin ... end
    else if (en) begin ... end // en=0 일 시 직전 플립플롭 클럭 게이팅 효과 및 상주 유지
end
```

* **하드웨어적 본질**: 전역 활성화 제어선(`en`)의 논리 값이 하이 레벨일 때만 내부 파이프라인 레지스터의 상태 전이를 허용합니다.
* **아키텍처적 도입 이유**:
1. **Stall(구동 일시정지) 제어**: 상위 메모리 계층(SRAM/DRAM)의 뱅크 충돌이나 대역폭 패널티로 인해 연산기에 유효 데이터가 정시 인가되지 못했을 때, `en = 0` 신호를 주어 기존 파이프라인 내 연산 상태를 깨짐 없이 그대로 홀딩합니다.
2. **클럭 게이팅(Clock Gating) 기반 Power Saving**: 가속기가 미가동 상태일 때 데이터가 무조건 누적 갱신을 반복하면 불필요한 토글 전류(Garbage dynamic power)가 폭증합니다. `en` 제어를 통해 내부 스위칭 전류를 원천 차단하여 전력 효율성을 극대화합니다.



### 2.4 한 사이클 손실 방지를 위한 누산기 국소 클리어 (`clear_acc`)

```verilog
reg prod_clear;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) prod_clear <= 1'b0;
    else if (en) prod_clear <= clear_acc & in_valid;
end
assign acc_base = prod_clear ? {(ACC_WIDTH+1){1'b0}} : acc_ext;
assign acc_next_raw = acc_base + prod_ext;
```

* **하드웨어적 본질**: 전역 `rst_n` 하드웨어 핀을 건드리지 않고, 순수 조합 논리 멀티플렉서(MUX) 스위칭을 통해 이번 사이클에 인가된 곱셈 결과물 자체를 다음 누산의 베이스 기점으로 강제 매핑합니다.
* **아키텍처적 도입 이유**: 거대한 가속 행렬 구조에서 특정 벡터 내적(Dot Product) 시퀀스가 마감되고 새로운 행렬곱 채널 연산이 시작될 때 누산기를 `0`으로 비워주어야 합니다. 기존 모델은 이를 위해 칩 전체 리셋 신호를 때려야 했으며, 이는 플립플롭이 청소되는 동안 1 클럭 사이클의 제어 타이밍 손실을 유발하고 파이프라인 내 모든 상태 자산을 파괴하는 가혹한 아키텍처적 패널티를 낳았습니다. `clear_acc` 지시어는 연산 처리 속도 손실 없이 매끄럽게 새로운 부분합 데이터 누산을 개시하도록 돕습니다.

### 2.5 핸드셰이크 프로토콜 연계를 위한 유효 데이터 파이프라인 (`in_valid` $\rightarrow$ `acc_valid`)

```verilog
input  wire  in_valid,
output reg   acc_valid,
// 내부 제어선 파이프라인: in_valid -> prod_valid (Stage 1) -> acc_valid (Stage 2)
```

* **하드웨어적 본질**: 입력단 신호의 유효성 플래그 비트(`in_valid`)를 데이터 연산 파이프라인 지연과 완벽하게 정렬하여 한 비트씩 시프트(Shift) 레이턴시를 주어 출력단 레지스터(`acc_valid`)로 내보냅니다.
* **아키텍처적 도입 이유**: NPU의 최상위 컨트롤러와 글로벌 시스톨릭 어레이 제어 평면은 가속기 출력단에서 전출되는 데이터가 "진짜 의미 있는 값"인지 유효성(Validity)을 인지할 수 있어야 인터페이스 병목이 터지지 않습니다. 기존 모델은 출력이 매 순간 변동되어 외부 인터페이스가 데이터를 언제 가져가야 할지 타이밍 윈도우를 잡지 못했습니다. 본 구조는 향후 AXI-Stream이나 ready/valid 프로토콜 핸드셰이크 인프라와 완벽하게 직결되는 제어 토대를 제공합니다.

### 2.6 주파수 대역 장악을 위한 2단계 파이프라인 (2-stage Pipelining)

```verilog
// Stage 1: 조합 회로의 곱셈 결과물을 플립플롭 레지스터 버퍼에 격리 보관
always @(posedge clk or negedge rst_n) begin
    if (en && in_valid) prod_reg <= in_data * weight;
end

// Stage 2: 격리된 레지스터 상수를 가져와 누산 가산 회로 구동
always @(posedge clk or negedge rst_n) begin
    if (en && prod_valid) acc <= acc_next_raw[ACC_WIDTH-1:0];
end
```

* **하드웨어적 본질**: 곱셈 조합 회로(Mult)와 누산 가산 회로(Adder Core) 사이에 물리적 실리콘 플립플롭 장벽을 배치하여 단일 클럭 내의 크리티컬 패스(Critical Path) 지연을 이분할합니다.
* **아키텍처적 도입 이유**: 주파수 한계 돌파를 위한 필수 기법입니다. 기존 유닛은 단 1 클럭 박자 안에 곱셈(5ns소요)과 가산(3ns소요)을 통째로 이행해야 했으므로 크리티컬 패스가 $5+3 = 8\text{ns}$로 가혹하게 묶여 물리 구동 동작 주파수가 최대 **`125 MHz`** 한계선에 정지되어 있었습니다. 이를 파이프라인 구조로 반절 쪼개면 최대 물리 지연 마진이 $5\text{ns}$로 단축되므로 동작 주파수 대역을 **`200 MHz+`** 이상으로 급격히 증폭 가속화할 수 있습니다.
* **공학적 비용(Trade-off)**: 단일 연산 완료 기준 1 사이클의 레이턴시(Pipeline Latency) 지연이 추가로 증가하며, 최초 연산 가동 시 파이프라인 내부를 예열하는 파이프라인 웜업(Warmup) 구조 오버헤드가 동반됩니다.

### 2.7 사일런트 랩어라운드 방지를 위한 포화 연산 및 오버플로우 플래그 (Saturation Logic)

```verilog
wire signed [ACC_WIDTH:0] acc_next_raw = acc_base + prod_ext; // 33비트 확장 정밀도
wire overflow_detected = (acc_next_raw[ACC_WIDTH] != acc_next_raw[ACC_WIDTH-1]); // MSB 2비트 크로스 체크

if (overflow_detected) begin
    acc      <= acc_next_raw[ACC_WIDTH] ? ACC_MIN : ACC_MAX; // 부호비트 추적 후 포화값 강제 매핑
    overflow <= 1'b1;                                        // 외부 경고 플래그 선언
end
```

* **하드웨어적 본질**: 누산기 폭을 넘어서는 비트 반전 패널티를 방지하기 위해 가상 33비트 가산 결과를 추출한 뒤, 최상위 부호 확장 비트(bit 32)와 실질 표현 부호 비트(bit 31)의 불일치 정합성을 실시간 스캔 필터링합니다.
* **아키텍처적 도입 이유**: 거대한 연산 스케일이 누적되면 아무리 `INT32` 광대역 누산 장치라 하더라도 임계값을 돌파하는 오버플로우 한계에 직면할 수 있습니다. 기존 유닛은 비트 폭 한계 초과 시 부호가 뒤집혀 버리는 사일런트 랩어라운드(Silent Wrap-around) 현상($2147483647 + 1 \rightarrow -2147483648$)이 발생하여 알고리즘 정확도를 영구 파괴했습니다. 양산형 코어는 오버플로우 발생 즉시 수치 데이터 반전을 막기 위해 표현 가능한 최대 양수/최대 음수 포화 값(`ACC_MAX` / `ACC_MIN`)으로 강제 고정 처리를 이행하고, 외부 제어부에게 비정상 연산 경고 신호(`overflow <= 1`)를 쏘아 보내어 디버깅 가시성을 무결하게 방어합니다.

### 2.8 실제 합성 전용 코어 빌드를 위한 수뮬레이션 파일 제어 지시어 (`$dumpfile` 제거)

```verilog
// 양산형 mac_v2.v 내부에는 기존 mac.v 하단에 상주하던 initial 구문이 완벽하게 삭제 처리됨
```

* **하드웨어적 본질**: 하드웨어 합성기가 읽을 수 없는 미합성형 파일 입출력 시스템 태스크 커맨드를 RTL 정적 설계 영역에서 완전히 소거 제거했습니다.
* **아키텍처적 도입 이유**: `$dumpfile` 이나 `$dumpvars` 같은 `initial` 블록 커커맨드는 시뮬레이션 환경에서 가상 파형 데이터를 반환하기 위한 도구일 뿐, 실제 게이트 수준의 실리콘 셀로 변환 및 물리 합성(Synthesis)이 불가능한 원천적 결격 사양입니다. 상용 수준의 완벽한 순수 RTL 자산을 구축하기 위해서는 미합성 소스 코드를 내부에 남겨두지 않는 코어 정돈 규칙을 준수해야 합니다. 파형 덤프 임무는 외부 검증 프레임워크인 cocotb 자산 환경 혹은 파이썬 테스트벤치의 명령줄 변수(`WAVES=1`) 제어 지시어 평면으로 이관하는 것이 공학적으로 타당합니다.

## 3. cocotb 검증 프레임워크 시나리오 분석 (`test_mac_v2.py`)

양산형 가속기 연산 소자의 무결한 논리 동작 입증을 위해 구축된 비동기 코루틴 기반의 6단계 정밀 교차 검증 시나리오 스펙 사양입니다.

| 검증 테스트 식별자 | 내부 하드웨어 검증 범위 및 실측 원리 | 검증 아키텍처적 목적성 |
| --- | --- | --- |
| **`test_basic_accumulation`** | 3개의 무결한 정수 데이터 쌍곱($3 \times 5 + 2 \times 4 + 1 \times 6$)을 순차 인가하여 최종 레지스터 적재값 계측 | 2-stage 파이프라인 지연 환경 하에서의 산술 연산 기능적 정확성 검증 |
| **`test_enable_holds`** | 연산 스트리밍 가동 중 `en = 0` 하드웨어 신호를 강제 인가하여 사이클 클럭을 흘린 뒤 내부 보관 상수 변동 상태 스캔 | 메모리 스톨 타이밍 발생 시 내부 연산 데이터 상주 및 플립플롭 홀딩 제어 무결성 입증 |
