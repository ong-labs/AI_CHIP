## 1. Verilog MAC 구조 및 핵심 역할

NPU 프로토타이핑 과정의 핵심은 수학적 인공지능 알고리즘을 실질적인 디지털 회로 형태로 구현하는 것입니다. 본 실습에서는 가속기 연산 평면의 최소 빌딩 블록이 되는 아주 작은 하드웨어 회로를 정의합니다.

* **회로의 본질적 역할**: 두 개의 입력 데이터를 클럭 주기마다 곱하고, 그 연산 결과를 누산기에 지속적으로 더해 나가는 구조입니다.

$$acc \leftarrow acc + (in\_data \times weight)$$

이 단순한 곱셈 후 부분합 누산 연산이 하드웨어 평면 위에서 수십억에서 수조 번 이상 병렬로 밀도 높게 반복되면서, 현대 딥러닝 알고리즘을 지배하는 거대한 행렬곱(GEMM), 합성곱(Convolution), Attention 연산 등의 연산들을 물리적으로 해결하게 됩니다.

## 2. 전체 검증 구조 및 파일 구성

하드웨어 컴포넌트 프로토타이핑 실습은 회로를 설계하는 단계에서 끝나는 것이 아니라, **[회로 생성 → 시뮬레이션 실행 → 자동 검증]** 으로 이어지는 통합적인 3-Tier 구조 체인을 완벽히 파악해야 합니다.

```text
 ┌────────────────┐       ┌────────────────┐       ┌────────────────┐
 │     mac.v      │       │    Makefile    │       │  test_mac.py   │
 │ (Hardware RTL) ├──────►│ (Simulator CFG)├──────►│(Python cocotb) │
 └────────────────┘       └────────────────┘       └────────────────┘
   RTL 모듈 설계도         시뮬레이터 구동 설정       기능 자동 검증 수행
```

### 2.1 파일별 정체성 및 역할

* **`mac.v`**: 실제 하드웨어의 논리 회로 구조를 기술한 RTL 설계도입니다.
* **`Makefile`**: 컴파일러(Icarus Verilog 등) 및 시뮬레이션 도구 세트의 가동 환경을 정의하는 설정 파일입니다.
* **`test_mac.py`**: 파이썬 환경의 cocotb 프레임워크를 기반으로 가상 하드웨어 신호를 인가하고 출력을 판정하는 자동 검증 소스 코드입니다.

### 2.2 하드웨어 아키텍트의 6대 코드 분석 관점

각 모듈과 스크립트를 분석할 때는 단순히 문법을 읽는 수준을 넘어 다음 6가지 차원의 질문에 명확히 답할 수 있어야 학술적 무결성이 증명됩니다.

1. 이 파일이 시스템 전체에서 존재해야 하는 **궁극적인 이유**는 무엇인가?
2. 코드 내 기술된 **각 줄(Line)의 하드웨어적 의미**는 무엇인가?
3. 소프트웨어적 관성을 배제하고, **왜 하드웨어 구조를 이렇게 작성해야만 하는가**?
4. 실제 컴파일 후 시뮬레이션 실행 시 **물리 실리콘 레벨에서 어떤 현상**이 일어나는가?
5. 상위 소프트웨어 프로그램(Python)과 가속기 하드웨어(Verilog)는 **어떤 유기적 관계**를 맺는가?
6. 본 의사결정이 **NPU 전체 서브시스템 관점에서 무엇을 의미**하는가?

따라서 본 보고서는 [‘이 코드는 무엇인가?’ → ‘왜 필요한가?’ → ‘각 줄은 무엇을 하는가?’ → ‘실행하면 어떤 일이 일어나는가?’]의 순서로 마이크로아키텍처의 구조를 추적합니다.

## 3. 하드웨어 MAC RTL 소스 코드 명세 (`mac.v`)

```verilog
// Reference: signed INT8 × INT8 MAC with INT32 accumulator
//
// Single multiply-accumulate unit:
//   acc <- acc + (in_data * weight)   on every rising clock edge
//
// Width discipline:
//   - inputs are signed 8-bit  (-128..127)
//   - product is naturally signed 16-bit
//   - accumulator is signed 32-bit (auto sign-extension when added)

module mac (
    input  wire                clk,
    input  wire                rst,
    input  wire signed  [7:0]  in_data,
    input  wire signed  [7:0]  weight,
    output reg  signed  [31:0] acc
);
    always @(posedge clk) begin
        if (rst)
            acc <= 32'sd0;
        else
            acc <= acc + (in_data * weight);
    end

    // Waveform dump for GTKWave (`make WAVES=1` 또는 cocotb 환경변수)
    initial begin
        $dumpfile("dump.vcd");
        $dumpvars(0, mac);
    end
endmodule
```

## 4. 아키텍처적 핵심 개념 분석 (Core Concepts)

### 4.1 Verilog HDL과 Python의 본질적인 철학 차이

반도체 설계를 처음 접하는 초보자가 가장 많이 범하는 오류는 Verilog 코드를 파이썬처럼 순차적인 명령문으로 오해하는 것입니다. 두 언어는 연산을 대하는 패러다임이 완전히 다릅니다.

| 항목 | Python 소프트웨어 | Verilog 하드웨어 RTL |
| --- | --- | --- |
| **핵심 정체성** | 상위 알고리즘의 **계산 절차** 명시 | 물리 실리콘의 **하드웨어 회로 구조** 기술 |
| **동작 메커니즘** | 인터프리터에 의한 **순차적 실행 (Sequential)** | 클럭 및 신호 변화에 따른 **동시 병렬 동작 (Parallel)** |
| **구동 주체** | 범용 CPU 가 명령어를 해석하여 구동 | 회로 자체의 구리선 연결 구조가 물리적으로 작동 |
| **추상화 중심** | 연산자 및 명령(Instruction) 중심 구현 | 신호선(Wire)과 플립플롭 레지스터(Register) 연결 중심 |

* **예시 비교**:
* Python에서 `x = a + b`는 프로그램 카운터가 해당 라인을 지나갈 때 일시적으로 계산되는 **절차**입니다.
* Verilog에서 `assign x = a + b;`는 `a` 신호선과 `b` 신호선이 가산기 하드웨어 소자를 거쳐 `x`라는 결과선에 납땜처럼 **항상 물리적으로 연결된 구조**를 선언하는 것입니다.

### 4.2 주석(Comment) 명세와 데이터 폭 규칙 (Width Discipline)

소스 코드 최상단의 주석문은 회로의 설계 마진과 정밀도를 정의하는 하드웨어 제원 정보입니다.

```verilog
// Reference: signed INT8 × INT8 MAC with INT32 accumulator
```

* **입력 사양**: `signed INT8` 정밀도를 취하므로, 8비트 공간 내에서 부호 비트(MSB)를 고려하여 `-128 ~ 127`의 수치 범위를 처리합니다.
* **출력 및 누산 사양**: 중간 부분합을 저장하는 저장소는 `signed INT32` 크기를 확보하여 물리적으로 `약 -21억 ~ +21억`의 거대한 스케일을 안전하게 방어합니다.

### 4.3 왜 INT32 정밀도의 누산기(Accumulator)가 필수적인가?

수학적 정합성을 확인하기 위해 8비트 곱셈 회로의 출력단 스케일을 정량적으로 역산해 보아야 합니다.

1. `INT8` 가질 수 있는 최대 정수값의 곱셈:

$$127 \times 127 = 16,129$$

2. 16,129라는 수치는 이미 부호 있는 8비트 레지스터의 최대 한계 범위인 `+127`을 아득히 초과하므로 단순 곱셈만으로도 `INT16` 수준의 물리 대역 폭이 강제됩니다.
3. 이에 더해 대규모 행렬곱 가속을 위해 이 연산을 1,000번 반복 누적(`loop accumulation`)한다고 가정하면 자산 규모는 급격히 팽창합니다.

$$16,129 \times 1,000 = 16,129,000$$

즉, 누적 연산은 입력 데이터보다 훨씬 더 큰 표현 범위가 담보되어야 오버플로우와 데이터 파괴 현상을 원천 차단할 수 있습니다. 본 가속기 코스에서 **INT8 곱셈의 부분합 저장 공간을 INT32 스펙으로 통일**하는 핵심적인 물리적 이유가 바로 여기에 있습니다.

## 5. 마이크로아키텍처 인터페이스 및 제어 구문 분해

### 5.1 `module mac` 인터페이스 정의

```verilog
module mac ( ... );
```

Verilog의 `module` 지시어는 하나의 독립된 회로 블록 자산을 정의하는 단위입니다. 객체지향 소프트웨어(Python)의 `class` 개념과 궤를 같이하며, 외부 시스템과 데이터를 주고받는 통로(Port)를 기술합니다.

### 5.2 클럭(Clock) 신호와 리셋(Reset) 신호

* **`input wire clk`**: 디지털 회로의 전역 동기 박자 신호입니다. `0 → 1 → 0 → 1`로 규칙적으로 진동하는 사각파 신호이며 가속기 내부의 동기화 제어 타이밍을 관장합니다.
* **`input wire rst`**: 시스템 내부 레지스터의 누적 상태를 강제로 초기화하는 동기식 리셋 신호선입니다. `rst = 1` 신호가 인가되면 연산 회로는 청소 상태(초기화)가 되며, `rst = 0` 상태일 때 비로소 정상적인 MAC 누산 동작을 이행합니다.

### 5.3 입력 데이터 및 가중치 버퍼선

```verilog
input wire signed [7:0] in_data,
input wire signed [7:0] weight,
```

* **`[7:0]` 비트 폭 명세**: `7 6 5 4 3 2 1 0` 방향으로 나열된 총 8비트(1바이트) 폭의 하드웨어 버스 인터페이스를 의미합니다.
* **`signed` 부호 활성화**: 회로 합성기에게 해당 데이터 버스 신호가 2의 보수(2's complement) 기반의 부호 있는 정수임을 명시합니다. 이 키워드가 누락되면, `10000000` 비트 입력 시 음수 `-128`이 아닌 양수 `128`로 잘못 계산되어 신경망의 가중치 파라미터가 완전히 깨지는 치명적인 버그가 발생하므로 가속기 설계 시 필수적으로 지정해야 합니다.

### 5.4 `output reg signed [31:0] acc` 출력문 분석

* **`output`**: 연산이 완료된 부분합 데이터를 외부(SRAM 버퍼 또는 버스 인터페이스)로 내보내는 출력 포트입니다.
* **`reg` 데이터 기억 소자**: 초보 아키텍트가 가장 혼동하기 쉬운 지점입니다. Verilog에서 `reg` 선언은 단순히 변수를 만드는 것이 아니라, 과거의 상태 값을 기억할 수 있는 물리적인 하드웨어 저장소(플립플롭 레지스터 회로)를 실리콘 평면 위에 배치하라는 물리적 명령입니다.
* **왜 acc는 wire가 아닌 reg여야 하는가?**: 누산 연산 알고리즘($acc \leftarrow acc + x$)의 특성상, 이번 사이클의 결과값을 안전하게 보관하고 있다가 다음 사이클의 입력 데이터가 들어왔을 때 기존 값(이전 상태)을 피연산자로 다시 공급해 주어야 하기 때문입니다. 즉, **과거의 상태를 기억하는 메모리 속성**이 필수적이므로 반드시 `reg` 타입으로 구현되어야 합니다.

### 5.5 `always @(posedge clk)` 동기화 블록과 넌블로킹 할당

```verilog
always @(posedge clk) begin
```

하드웨어 제어부 설계의 핵심 구문입니다. 전역 클럭 신호가 `0`에서 `1`로 상승하는 변하는 순간, 즉 **Rising Edge(Positive Edge)** 기점이 발생하는 찰나의 순간에만 `begin ~ end` 내부의 회로 상태를 동기식으로 일제히 업데이트하겠다는 물리적 트리거링 메커니즘입니다.

```verilog
if (rst)
    acc <= 32'sd0;
```

리셋 신호가 인가되었을 때 실행되는 물리적 초기화 구문입니다. 여기서 `32'sd0` 문법은 다음 사양을 명시하는 정형화된 하드웨어 리터럴 표기법입니다.

* **`32`**: 32비트 물리적 공간 크기 확보
* **`s`**: 부호 있는(signed) 속성 부여
* **`d`**: 10진수(decimal) 포맷팅 형태 지정
* **`0`**: レ지스터에 채워 넣을 물리적인 상수 값 지정

```verilog
acc <= acc + (in_data * weight);
```

여기서 사용된 **`<=`** 기호는 소프트웨어의 비교 연산자가 아닌, Verilog의 넌블로킹 할당문(Non-blocking Assignment)입니다. 클럭의 라이징 에지 순간에 우변의 행렬 곱셈 연산 결과값을 하드웨어 조합 회로가 즉시 계산해 두고, 해당 클럭 사이클이 완벽히 마감되어 종료되는 타이밍에 레지스터 공간에 값이 최종 동기화 저장되는 특성을 가집니다.

## 6. 하드웨어 사이클 단위 실행 트레이스 (Execution Trace)

임의의 정수 입력 쌍 데이터 스트리밍이 가속기 내부 Port로 들어왔을 때, 매 클럭 사이클(Cycle)마다 `acc` 레지스터 회로가 물리적으로 연산을 누적해 나가는 실제 동작 변화 흐름 데이터입니다.

* **가상 입력 시나리오 세트**:
* $Sequence\ 1: (in\_data = 3,\ weight = 5)$
* $Sequence\ 2: (in\_data = 2,\ weight = 4)$
* $Sequence\ 3: (in\_data = 1,\ weight = 6)$

```text
  Clock Pulse  :  ──┐  ┌──┐  ┌──┐  ┌──┐  ┌──
                    └──┘  └──┘  └──┘  └──┘
  Cycle Count  :    [ Cycle 1 ] [ Cycle 2 ] [ Cycle 3 ]
  in_data/weight:      3 * 5       2 * 4       1 * 6
  acc Register :   0 ───────► 15 ───────► 23 ───────► 29 (정밀도 유지)
```

* **[Cycle 1]**: 첫 번째 클럭 변곡점이 발생하는 순간, 기존 누산기 값 `0`에 상측 입력 데이터의 곱셈 결과인 $3 \times 5 = 15$를 더하여 `acc` 레지스터 값을 `15`로 갱신합니다.
* **[Cycle 2]**: 두 번째 클럭 에지 도달 시, 레지스터가 보관 중이던 과거 데이터 `15`를 피연산자로 리드하여 가산기에 공급하고, 신규 입력 데이터 $2 \times 4 = 8$을 누산하여 레지스터 값을 `23`으로 업데이트합니다.
* **[Cycle 3]**: 세 번째 클럭 주기 기점에서, 직전 사이클 결과인 `23`에 마지막 스트리밍 입력 가중치 연산인 $1 \times 6 = 6$을 더해 최종 연산 마진 결과인 `29`를 도출해 냅니다.

## 7. 테스트벤치 파형 덤프 및 디버깅 가이드 (`initial`)

```verilog
initial begin
    $dumpfile("dump.vcd");
    $dumpvars(0, mac);
end
```

RTL 하드웨어 설계 흐름의 마지막은 시간축 기준의 파형 분석입니다. `initial` 구문은 하드웨어 실리콘 칩으로 합성되지는 않으며, 오직 시뮬레이션 환경이 시작되는 시점에 테스트벤치 도구 체인에게 디버깅 자산을 남기기 위해 딱 한 번 작동하는 특수 구문입니다.

* **`$dumpfile("dump.vcd")`**: 시뮬레이션 가동 중 발생하는 모든 미시적 신호 변화 데이터를 기록할 물리 파일의 이름(**VCD: Value Change Dump**)을 정의합니다.
* **`$dumpvars(0, mac)`**: 최상위 테스트 레이어 하위에 배치된 `mac` 모듈 내부의 모든 물리 신호선(`clk, rst, in_data, weight, acc`)의 실시간 비트 변화 레벨을 추적하여 기록 장치에 저장하도록 명령합니다.
* 이렇게 추출된 `dump.vcd` 소스 자산은 파형 분석 도구(Surfer, GTKWave 등)를 통해 미세한 게이트 지연 시간, 셋업/홀드 타이밍 마진, 그리고 다이내믹 전하 제어 상태를 눈으로 직접 확인하며 검증하는 핵심 디버깅 레퍼런스로 활용됩니다.

## 8. 결론 (Conclusion)

본 과제에서 기술한 Verilog 소스 코드는 인공지능 가속기 마이크로아키텍처 설계의 가장 기본이 되는 산술 소자입니다.

* 전역 시스템 클럭 박자에 정밀하게 동기화되어 움직이고,
* 과거의 부분합 연산 상수를 레지스터 기법으로 엄격히 기억하며,
* 입력 정밀도의 마진을 고려하여 오버플로우를 제어하는 `INT32` 누산 설계 사양을 정립했습니다.

이 컴포넌트의 논리적 무결성과 물리 파라미터 비용은 차후 진행될 NPU 매트릭스 가속 구조의 핵심 계산 소자인 **PE(Processing Element) 어레이 통합 시스템**을 정립하는 가장 단단한 아키텍처적 기반 자산이 됩니다.
