## 1. 학습 목표 및 설계 통합의 핵심 의의

본 단원의 궁극적인 공학적 목표는 하드웨어 사양 명세인 정적 정의 객체들을 시간의 흐름 속에서 상호작용하는 **"동적 가상 실행 시스템(Dynamic Executable System)"** 으로 승격시키는 것입니다.

```python
npu = NPU(config)
result = npu.run(A, B)
```

위의 두 줄은 단순한 소프트웨어 함수 호출을 넘어, 물리 실리콘 반도체 아키텍처의 구동 메커니즘을 그대로 모사하는 하드웨어 가동 파이프라인의 진입점 역할을 수행합니다. 이 단일 인터페이스 선언을 트리거로 삼아 하드웨어 제원 파싱, 계층형 메모리 서브시스템 구성, 시스톨릭 가속 그리드 초기화, 중첩 루프 기반 타일 데이터 스트리밍, 사이클 및 하드웨어 전력 실측 연산이 정밀하게 연쇄 실행됩니다.

## 2. 왜 통합(Integration)인가? (독립 부품의 시스템화)

이전 단계까지 빌드업된 산출물들은 의미 있는 추상화 모델이었으나, 상호 제어 로직이 부재하여 시간 축 위에서 동적으로 협력하지 못하는 정적 상태에 머물러 있었습니다. 시스템을 완성하기 위해 각 개별 자산들을 다음과 같은 구조로 긴밀히 캡슐화 조립합니다.

| 가속기 산출물 구성요소 | 시스템 구축을 위한 비유 및 정체성 |
| --- | --- |
| **`NPUConfig`** | **하드웨어 설계 도면**: 동작 클럭 주파수, PE 배열 형상, 데이터 타입 폭, 외부 메모리 전송 대역폭 제원 명세 |
| **`MACUnit`**, **`Memory`** | **부품 카탈로그**: 실제 연산 회로 소자 단위인 곱셈-누산기와 온칩 SRAM 버퍼, 외장 DRAM 물리 모델 |
| **`SystolicArray`** | **계산 엔진의 토폴로지**: 프로세싱 엘리먼트(PE) 간 데이터가 흐르는 하드웨어 물리 연결 방식 |
| **`NPU`** | **조립이 완료된 반도체 칩**: 위 독립 구성 요소들을 결합하여 실질적인 연산을 관장하는 가상 실행체 |

정적 정의 상태에서는 "DRAM 리드 타이밍", "PE 배열 가동 제어", "부분합 누산 시점", "소비 사이클 및 에너지 누적량"을 정량화할 수 없습니다. 본 최적화 파이프라인은 정적 부품들을 엮어 **1) 표준 인터페이스를 정의하고, 2) 하드웨어 실행 순서를 강제하며, 3) 가상 시간 축(Cycles)을 부여하고, 4) 거시적 측정 지표를 계산**해 냄으로써 비로소 완전한 시뮬레이션 시스템의 자격을 획득하게 됩니다.

## 3. 시뮬레이션 정확도 레벨 검토 및 Trace-Driven 기법의 가치

가속기 성능 예측 시뮬레이터 설계 시에는 모델의 정밀도(Accuracy)와 실행 속도(Simulation Speed) 간의 명확한 엔지니어링 트레이드오프를 고려해야 합니다.

| 시뮬레이션 추상화 레벨 | 시간 모델링 단위 | 가동 실행 비용 | 아키텍처적 주된 용도 | 본 실습 코스의 포지션 |
| --- | --- | --- | --- | --- |
| **Analytical (Roofline)** | 전체 알고리즘 연산 단위 | 즉시 산출 (Instant) | 하드웨어 성능의 상한선 고속 추정 | Week 1~4 도입부 |
| **Trace-Driven** | **타일(Tile) 블록 단위** | **수 초 내외 (Fast)** | **구조적 병목 및 활용률 정밀 분석** | **본 통합 실습 (`NPU.run`)** |
| **Cycle-Accurate** | 모든 개별 클럭 단위 | 수 분 ~ 수 시간 소요 | 마이크로아키텍처 세부 파이프라인 검증 | 선택적 심화 단계 |
| **RTL Simulation** | 게이트 신호(Gate Level) 단위 | 수 시간 ~ 수일 소요 | 합성 전 하드웨어 기능 및 물리 무결성 검증 | Unit 03 실습 일부 |

### 💡 Trace-Driven 아키텍처 채택 Rationale

1. **분석의 구체성 확보**: 거시적인 Roofline 분석과 달리, 실제 하드웨어 버퍼 내부의 타일 데이터 이동 경로와 재사용성(Reuse Ratio)을 정밀하게 추적합니다.
2. **구현 복잡도 최적화**: 모든 플립플롭과 먹스(MUX) 단위 신호를 모사하는 Cycle-Accurate 기법의 복잡한 오버헤드를 우회하여, 아키텍트가 핵심 제어 로직에 집중하여 단시간 내에 시스템 프로토타입을 빌드할 수 있는 최적의 추상화 마진을 제공합니다.
3. **핵심 인사이트 보존**: 가속기 평면 비대화에 따른 공간 활용률 저하 현상 및 온칩 용량 제약으로 야기되는 메모리 대역폭 병목 현상을 정확하게 관찰 및 진단할 수 있는 기능적 무결성을 유지합니다.

## 4. 통합 가속기 시스템 구조 (Microarchitecture Topology)

실행 엔진 객체인 `NPU` 클래스는 내부에 계층 구조 메모리와 계산 가속 그리드를 포함하는 오케스트레이터 구조로 구체화됩니다.

```text
NPU (NPUConfig 사양 명세 주입 수용)
 ├── PEArray         ← SystolicArray 마이크로아키텍처의 수치적 매핑 구현체
 ├── SRAM            ← 작고 빠른 온칩 로컬 버퍼 메모리 모델 (Memory 클래스 인스턴스)
 ├── DRAM            ← 크고 느린 대용량 외장 메모리 물리 모델 (Memory 클래스 인스턴)
 └── Stats (Internal)← 실행 마감 후 반환할 cycles, energy, dram_bytes 데이터 누적 계측기
```

* **NPU 오케스트레이터**: 자체적인 원소 산술 연산을 수행하지 않으며, 제어 명령 프로세서(Command Processor) 가동 펌웨어처럼 각 하드웨어 부품을 적절한 시간 순서대로 트리거하여 전체 토폴로지를 구동합니다.
* **PEArray & 계층 메모리**: `SRAM` 버퍼 메모리는 상위 정밀도 사양에 맞추어 할당되며, 외부 `DRAM` 메모리는 원본 데이터 소스 및 최종 적재 공간 역할을 가상으로 수행합니다.

## 5. `run(A, B)` 실행 파이프라인 7단계 산술 매커니즘 분해

시뮬레이터의 심장부인 `run()` 매서드는 인가된 입력 행렬 쌍에 대하여 정확하게 7단계의 하드웨어 스케줄링 흐름을 밟아 연산을 완료합니다.

### 1단계: 입력 데이터 검증 및 물리 배치 가정

* 피연산자 행렬 $A$의 차원 `(M, K)`와 행렬 $B$의 차원 `(K, N)` 간 내적 차원 호환성($K == K$)을 확인합니다.
* 시뮬레이션 시작 시점의 모든 피연산자 데이터는 외부 오프칩 대역인 `DRAM` 공간에 물리적으로 적재되어 있는 것으로 상정합니다.

### 2단계: 하드웨어 매핑 타일(Tile) 분할 계산

가속기가 가질 수 있는 물리적 프로세싱 엘리먼트 행 개수($PE_R$)와 열 개수($PE_C$)의 한계를 고려하여, 거대한 연산 평면을 최적의 서브 타일 블록 격자로 파티셔닝합니다. 올림 함수($\lceil\rceil$) 연산을 통해 에지 패딩 마진을 포함한 축별 총 타일 패널 개수를 도출합니다.

$$nt_m = \left\lceil \frac{M}{PE_R} \right\rceil, \quad nt_n = \left\lceil \frac{N}{PE_C} \right\rceil, \quad nt_k = \left\lceil \frac{K}{PE_R} \right\rceil$$

### 3단계: 가중치 고정(Weight-Stationary) 데이터플로우 타일 루프 실행

가속기 연산 효율을 결정짓는 핵심 제어부인 3중 가중치 고정 중첩 루프입니다. 재사용 주기가 긴 가중치 데이터를 내부 레지스터 평면에 최대한 고정(Stationary)하여 DRAM 액세스를 억제하는 스케줄링을 모사합니다.

```python
# Weight-Stationary 데이터 전송 및 누산 스케줄링 루프 구조
for m_tile in range(nt_m):
    for n_tile in range(nt_n):
        for k_tile in range(nt_k):
            # 1. 가중치 타일 온칩 적재 (DRAM -> SRAM -> PE 레지스터 고정)
            # 2. 입력 데이터 타일 스트리밍 (DRAM -> SRAM -> PE 어레이 입력선 구동)
            # 3. 공간적 병렬 연산 트리거 및 부분합(Partial Sum) 사이클 동기 누적
```

* **3×3×3 가상 타일 전개 시의 물리적 실행 추적(Trace) 시퀀스 명세**:
$M, N, K$ 축 타일 수가 각각 3개인 경우, 제어 프로세서 순서 제어 플로우에 의거하여 다음과 같이 총 $3 \times 3 \times 3 = 27$번의 독립적인 타일 연산 사이클 시퀀스가 시간 축 순서대로 엄격히 전개됩니다.
* `[0, 0, 0]`: 첫 가중치 고정, 입력 스트리밍 $\rightarrow$ 부분합 누산 상태 진입
* `[0, 0, 1]`: 가중치 유지, 연속 입력 대역 결합 $\rightarrow$ 부분합 누산 진행
* `[0, 0, 2]`: 가중치 유지, $K$축 마지막 누산 완결
* `[0, 1, 0]`: $N$축 이동에 따른 신규 가중치 적재, 입력 스트리밍
* `...`
* `[2, 2, 2]`: 가속기 전체 평면의 최종 마감 연산 이행 완료



### 4.단계: 출력 타일(Output Tile) 최종 저장 제어

* 특정 $M$축 및 $N$축 격자에 매핑된 모든 내부 $K$축 타일들의 순차 누적 연산이 완벽히 마감되면, 최종 계산이 완료된 완성형 결과 텐서 블록 데이터를 온칩 SRAM 버퍼를 거쳐 외장 DRAM 메모리 주소 영역에 기록(`DRAM Write`)합니다.

### 5단계: 공간적 PE Utilization(자원 활용률) 계산

하드웨어 아키텍처 평면 배열이 가진 총 가용 연산 대역폭 대비, 타겟 알고리즘 계산을 위해 실질적으로 유효 연산에 투입된 하드웨어 자원의 비율을 정량 산출합니다. 행렬 크기가 작아 에지 패딩(Zero Padding) 마진이 늘어날 경우 이 수치가 폭락하여 비효율을 리포팅하게 됩니다.

$$pe\_utilization = \frac{\text{Actual Required MACs } (M \times N \times K)}{\text{Full Hardware Capable MACs } (nt_m \times nt_n \times nt_k \times PE_R \times PE_C \times PE_R)}$$

### 6단계: 다중 계층 소소 에너지(Energy) 추정

NPU 칩셋 전체 전력 비용 성능을 산출하기 위해 하드웨어 작동 요소를 분해하여 누적 연산합니다.

* **연산 에너지**: 실제 유효 연산 수에 데이터 타입 및 누산기 정밀도별 상수가 매핑된 단일 `_mac_energy_pj` 수치를 곱해 연산 에너지를 구합니다.
* **메모리 에너지**: 온칩 버퍼선 트래픽에 전하 비용 상수를 곱한 `SRAM 에너지`와 off-chip 버스트 이동 패널티가 가산된 `DRAM 에너지`를 결합하여 피코줄(pJ) 스케일로 최종 통합 계측합니다.

### 7단계: `RunResult` 데이터 반환 및 가상 시간 비용 공식 결합

* 최종 연산 처리 결과 행렬($C$)과 계측된 모든 물리적 비용 매트릭 데이터를 하나의 통합 구조체 객체에 담아 신뢰성 있게 리턴합니다.

## 6. `RunResult` — 시뮬레이터의 출력 계약(Contract) 명세

시뮬레이터 가동 후 최종 반환되는 `RunResult` 데이터 구조는 사용자 인터페이스와 내부 가상 하드웨어 엔진 간의 명확한 데이터 계약 규격을 형성합니다.

```python
@dataclass
class RunResult:
    C: np.ndarray             # 하드웨어 최종 연산 결과 행렬 (정확성 검증용)
    cycles: int               # 전체 가동 소모 클럭 사이클 수 (지연 시간 분석용)
    energy_pj: float          # 전체 가속 파이프라인 누적 에너지 비용 (pJ 스케일)
    dram_read_bytes: int      # 외부 메모리로부터 읽어 들인 총 입력/가중치 데이터양
    dram_write_bytes: int     # 외부 메모리로 내보낸 최종 결과 데이터양
    pe_utilization: float     # 하드웨어 연산 소자 공간 이용 효율성 지표
```

이 계약 규격을 통해 아키텍트는 단순 기능 테스트를 넘어 **End-to-End Latency 분석, 에너지 소비 효율 정량 비교, 메모리 트래픽 병목 진단, 데이터플로우 제어 전략 평가**라는 고차원 의사결정을 실측 데이터 기반으로 전개할 수 있게 됩니다.

## 7. 소프트웨어 및 하드웨어 아키텍처 관점의 다층적 의미 고찰

### 7.1 소프트웨어 공학 관점: 오케스트레이션 레이어(Orchestration Layer)의 구현

본 실습의 시뮬레이터 아키텍처는 고수준 소프트웨어 공학의 전형적인 계층 구조(Layered Architecture) 패턴을 충족합니다.

| 아키텍처 계층 구조 | 프로젝트 매핑 실체 | 물리 계층 내에서의 명확한 역할 정의 |
| --- | --- | --- |
| **Data Layer** | `NPUConfig` | 시스템 컴파일 스펙 및 주파수, 버퍼 제원 데이터 홀딩 |
| **Component Layer** | `Memory`, `MACUnit` | 원자 단위의 물리 저장 공간 및 산술 회로 거동 규칙 명세 |
| **Architecture Layer** | `SystolicArray` | PE 간 신호선 결합 관계 및 데이터 가속 하드웨어 토폴로지 정의 |
| **Orchestration Layer** | **`NPU.run()`** | **독립 객체들의 기능을 타이밍 순서대로 조합 및 제어하여 통합 서비스 제공** |

`result = npu.run(A, B)`라는 고도로 추상화된 단 한 줄의 인터페이스 내부로 복잡한 하위 컴포넌트 상호작용을 숨김으로써, 운영체제의 `process.run()`, 데이터베이스의 `query()`, 현대 딥러닝 프레임워크의 `model(x)` 기법과 동일한 층위의 수준 높은 인터페이스 설계를 완수했습니다.

### 7.2 하드웨어 아키텍처 관점: 가속기 커맨드 프로세서(Command Processor) 모사

물리 반도체 실리콘 칩 역시 연산기(ALU)와 레지스터 파일, SRAM 버퍼, DMA 장치들을 독립적으로 배치해 둔다고 해서 스스로 연산하지 않습니다. 이들을 언제 깨우고 끌지 통제하는 제어 회로가 필수적입니다. `NPU.run()` 제어 로직은 하드웨어 수준에서 "DRAM에서 데이터를 퍼 올려 온칩 SRAM에 배치하고, 가중치를 시스톨릭 그리드 레지스터에 락(Lock)한 뒤, 입력을 클럭마다 스트리밍하여 연산을 유도하고 결과 레지스터를 수집해 DRAM으로 하차시키는 전체 스케줄링 제어기"를 소프트웨어로 고스란히 모사한 결과물입니다.

## 8. 시간 축(Time) 부여를 통한 가상 측정 시스템으로의 완전한 전환

정적 사양 명세에 불과했던 설계 도면이 참된 의미의 '시뮬레이터(Simulator)'로 변모하는 결정적인 기점은 **모든 물리적 이벤트에 시간 비용(Clock Cycles)을 엄격히 부여하는 순간**입니다.

* **DRAM 데이터 이동 시간 모델링**: 단순히 데이터 이동 크기만 가산하지 않고, 시스템 전폭 버스 인터페이스 대역폭과 주파수 스케일을 반영하여 전송 지연 시간 사이클을 산출합니다.
* **시스톨릭 가속 연산 시간 모델링**: 시스톨릭 그리드 특유의 구조적 파이프라인 지연 타이밍 비용인 `pipeline fill + steady state + drain` 공식($nt_m \cdot nt_n \cdot nt_k \cdot pe\_r + (pe\_r + pe\_c - 1)$)을 결합하여 가상 타임스탬프를 부여합니다.

이 연산 사이클과 메모리 지연 사이클 간의 상호 더블 버퍼링 오버랩 비용($\max(compute, dram)$)을 엄격히 누적 정량화함으로써, 단순한 파이썬 연산기 함수 집합을 "얼마나 오래 걸리는가?", "어느 하드웨어 자원이 병목(Bottleneck)인가?", "에너지는 어디서 낭비되는가?"에 정확히 답해 줄 수 있는 공학 시뮬레이션 시스템으로 변환시켰습니다.

## 9. 결론 및 모델링의 진정한 공학적 의의

본 단원의 시스템 설계 통합 과정은 개별 공식을 짜 맞추는 단편적 실습을 넘어, "복잡한 하드웨어 물리 대상을 소프트웨어적으로 추상화하고 작동 가능한 가상 시스템 모델로 구축하는 하드웨어 아키텍트의 정수"를 담고 있습니다.

여기서 정립한 '구성 요소 정의 $\rightarrow$ 동적 상호작용 설계 $\rightarrow$ 시간 축 부여 $\rightarrow$ 시스템 메트릭 산출' 방법론의 구조적 핵심 원리는 향후 CPU Simulator, GPU Performance Model, 대규모 분산 시스템 모델링 도구 설계 레이어로 한 치의 왜곡 없이 그대로 확장 연계되는 강력한 기초 자산이 됩니다.
