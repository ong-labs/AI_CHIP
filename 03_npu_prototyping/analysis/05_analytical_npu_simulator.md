# 05_analytical_npu_simulator.md: Analytical NPU Simulator Concept and Architecture Analysis Report Based on Hybrid Verification Techniques

본 보고서는 통합 가속기 시뮬레이터의 설계 철학과 하이브리드 성능 모델링 방법론을 분석하기 위해 작성되었습니다. 하드웨어 사양 명세(Config)를 기반으로 기능적 무결성을 직접 증명하면서, 물리 비용 성능 지표는 정밀한 해석적 수식(Analytical Equation)으로 실시간 고속 추정하는 시스템 수준 가상 가속기 모델링 기법의 구조적 원리를 고찰합니다.

---

## 1. 학습 목표 및 시뮬레이터의 한 줄 정의

* **학습 목표**: 설정(Config), 연산 및 메모리 부품(Component), 가속 가동 구조(Architecture)를 시간 축 위에서 유기적으로 조합하여 임의의 가상 행렬 곱셈 워크로드에 대한 기능적 정확성, 실행 클럭 사이클, 에너지 소모, 오프칩 트래픽, 공간 활용률을 동시에 측정할 수 있는 시스템 오케스트레이션 메커니즘을 마스터합니다.
* **한 줄 정의**: **`Analytical NPU Simulator (Functional + Analytical Performance Model)`**
  > 결과 행렬은 범용 수치 라이브러리(NumPy)를 통해 소프트웨어 레벨에서 정확하게 실제 계산해 내고, 하드웨어 물리 성능 지표는 정립된 해석적 수식으로 고속 추정하는 최적화 지향형 시스템 수준 시뮬레이터입니다.

본 시뮬레이터는 저수준 하드웨어 기술 언어(RTL)처럼 모든 논리 게이트 신호선과 플립플롭의 비트 반전 현상을 매 클럭 사이클 단위로 무겁게 재현하지 않고, 추상화된 두 가지 핵심 엔지니어링 축을 결합하여 가속 시스템을 가상 실행합니다.

## 2. 시뮬레이터를 지탱하는 두 가지 핵심 축 (Core Pillars)

해당 시스템은 연산 정합성을 증명하는 기능 시뮬레이션 축과 물리 자원을 프로파일링하는 성능 모델링 축이 독립적이면서도 동시에 구동되는 하이브리드 아키텍처를 가집니다.

### 2.1 Functional Simulation (계산 결과의 정확성 방어)
* **연산 메커니즘**: 인가된 입력 데이터 행렬 쌍에 대하여 실제 행렬 곱셈(Matmul, $C = A \cdot B$) 수치 연산을 백엔드에서 전면 이행합니다.
* **공학적 의의**: 하드웨어 가속 성능 및 병목 원인에 대한 정량적 분석 지표는 연산의 수치적 무결성(Functional Correctness)이 완벽히 입증되었을 때 비로소 신뢰성을 확보할 수 있습니다.
* **검증 프로토콜**: 계산이 완료된 출력 데이터 객체를 골든 레퍼런스 데이터와 `np.allclose()` 함수를 통해 크로스 체크함으로써 가상 칩 레벨의 정합성(Correctness)을 최종 보장합니다.

### 2.2 Analytical Modeling (하드웨어 성능 정량 추정)
* **연산 메커니즘**: 가속기 내부 구조를 한 클럭씩 무겁게 에뮬레이션하는 대신, 하드웨어 데이터플로우의 타일 제어 규칙과 계층 메모리 전송 지연 시간을 정형화된 수학적 함수 수식($f$)의 인자로 매핑하여 즉시 산출합니다.
* **수학적 모델링 대상**:
  * **실행 사이클 수 추정**: $cycles = f(compute\_cycles, dram\_cycles)$
  * **소모 에너지 추정**: $energy = f(mac\_count, dram\_bytes, sram\_bytes)$
  * **외부 트래픽 및 이용률**: DRAM 읽기/쓰기 바이트양 실측 및 하드웨어 공간적 PE 활용률 산출

## 3. 추상화 정확도 수준에서의 아키텍처적 포지셔닝

다양한 컴퓨터 아키텍처 시뮬레이션 기법들과 비교했을 때, 본 하이브리드 모델이 가지는 포지션과 교육/설계 공간 탐색(DSE) 측면에서의 적합성 명세입니다.

| 시뮬레이션 방식 | 시간 분석 단위 | 모델 정확도 | 가동 실행 속도 | 교육 적합성 | 파라미터 탐색 (DSE) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Analytical (Roofline)** | 전체 작업 레이어 | 낮음 (Upper Bound) | 매우 빠름 (Instant) | 높음 | 좋음 |
| **Analytical + Functional (본 모델)** | **타일 루프 수준** | **중간 (Moderate)** | **매우 빠름 (Fast)** | **최적 (Optimal)** | **최적 (Optimal)** |
| **Trace-Driven** | 마이크로 이벤트 수준 | 높음 | 보통 | 높음 | 좋음 |
| **Cycle-Accurate** | 모든 개별 Clock Cycle | 매우 높음 | 느림 | 고급 단계 | 비선호 (Heavy) |
| **RTL Simulation** | 게이트 신호 레벨 | 최고 (Silicon Exact) | 매우 느림 | 연구/산업 특화 | 비선호 (Heavy) |

본 시뮬레이터는 거시적 대역폭만 보는 Roofline 모델보다 구체적인 타일 데이터 이동 및 하드웨어 버퍼 재사용성을 추적할 수 있으며, 하드웨어 하위 신호선까지 모사하는 Cycle-Accurate 기법보다 구조가 단순하여 빠른 설계 실험과 직관적인 구조적 통찰을 동시에 제공하는 최적의 밸런스를 이뤄냅니다.

## 4. 시뮬레이터가 계산하는 6대 핵심 출력값 (Contract Metrics)

가속기가 가동을 마친 후 반환하는 `RunResult` 객체는 사용자와의 명확한 출력 계약(Contract)이며, 가속기 사양을 평가하는 정량 나침반이 됩니다.

| 출력 필드 식별자 | 공학적 데이터 의미 | 아키텍트가 던지는 핵심 시스템 질문 |
| :---: | :--- | :--- |
| **`C`** | 최종 계산 결과 행렬 | 소프트웨어 알고리즘과 수치 결과가 한 치의 오차도 없이 맞는가? |
| **`cycles`** | 가속 완료 소모 클럭 수 | 타겟 행렬 연산을 처리하는 데 얼마나 오랜 시간이 걸리는가? (Latency 분석) |
| **`energy_pj`** | 칩셋 내부 총 소모 에너지 | 해당 하드웨어 구성안이 얼마나 많은 전력을 소비하는가? (효율성 비교) |
| **`dram_read_bytes`**| 외장 메모리 총 읽기 트래픽 | 연산 구동을 위해 외부에서 데이터를 얼마나 많이 긁어오는가? |
| **`dram_write_bytes`**| 외장 메모리 총 쓰기 트래픽 | 최종 누산 완료된 결과를 외장 메모리에 얼마나 내보내는가? |
| **`pe_utilization`** | 가속 코어 평면 실제 활용률 | 주어진 하드웨어 연산 자원(Systolic Array)을 노려보지 않고 얼마나 잘 쓰는가? |

## 5. 수식 기반 마이크로아키텍처 비용 실제 구현 방식

시뮬레이터 백엔드 커널 내부에 계장된 수식들의 구체적인 컴퓨터 구조학적 매핑 원리입니다.

### 5.1 누산 정밀도(Accumulator Precision) 모사 메커니즘
실제 DSA 반도체 칩 내부 연산 시 발생하는 Mixed-Precision 전이 특성을 완벽히 모사하기 위해, NumPy 행렬곱 수행 전 비트 폭 확장 캐스팅을 선행 처리합니다.
* `int8` 입력 $\rightarrow$ 오버플로우 방지를 위해 `int32` 누산기 및 결과 도출
* `fp16` 입력 $\rightarrow$ 그라디언트 소실 제어를 위해 `fp32` 누산기 및 결과 도출

### 5.2 Roofline 사상을 계승한 전역 타이밍 사이클 산출 공식
가속 시스템 아키텍처 내부에 탁월한 데이터 더블 버퍼링 오버랩 매커니즘이 내장되어 있음을 전제하여 타이밍을 에스티메이션합니다.

$$total\_cycles = \max(compute\_cycles, dram\_cycles) + overhead$$

* 하드웨어가 실질 순수 연산을 이행하는 시간(`compute_cycles`)과 외장 대역이 데이터를 실어 나르는 시간(`dram_cycles`)이 완벽히 중첩 구동되므로, 두 하드웨어 자원 병목 중 **더 큰 물리적 시간 비용**이 전역 지연 시간을 결정짓는다는 Roofline 대전제를 그대로 추종합니다. 마지막 항의 오버헤드는 호스트 가속 명령 디스패치 지연 클럭을 정밀 가산한 것입니다.

### 5.3 다중 소스 기반 토탈 에너지 합산 논리
칩셋 전력 비용 산출을 위해 하드웨어 작동 컴포넌트 소스를 철저히 삼분할하여 추적 집계합니다.

$$total\_energy = mac\_energy + dram\_energy + sram\_energy$$

1. **`mac_energy`**: 타겟 행렬곱 수행에 투입된 총 유효 산술 횟수($M \cdot N \cdot K$)에 정밀도별 고유 상수 피코줄 비용을 곱해 연산 비용을 구합니다.
2. **`dram_energy` & `sram_energy`**: 오프칩 버스트 이동량 및 온칩 버퍼 메모리 데이터 액세스 트래픽 대역 통과 총 바이트 수에 단위 메모리당 물리 전하 제어 비용 상수를 가산하여 최종 누적합니다.

## 6. 하이브리드 시뮬레이션 모델이 가리키는 아키텍처적 핵심 통찰

본 시뮬레이터 DSE 환경을 구동함으로써 아키텍트는 아키텍처 설계 변수 가변에 따른 물리 성능의 인과관계를 정량적 데이터로 도출할 수 있습니다.

* **작은 워크로드 매핑 시의 통찰**: 가속 평면 그리드를 무작위로 키우면, 입력 행렬 차원 크기가 작을 때 대다수의 하드웨어 계산 소자가 유효 데이터를 인가받지 못하고 노는 제로 패딩 에지 마진이 증가하여 **공간 활용률(Utilization)이 급감**합니다. 즉, 무조건 큰 칩이 아키텍처적으로 효율적인 것이 아님을 방증합니다.
* **온칩 SRAM 대역 확장 시의 통찰**: 온칩 로컬 버퍼 용량을 과감히 확장 확보하면, 가중치 타일 데이터를 내부에 완전히 고정(Stationary) 상주시켜 가혹한 외부 DRAM 재로딩 패널티를 억제할 수 있으므로 **오프칩 트래픽 감쇄와 시스템 누적 소비 에너지의 수십 배 낙하**를 달성할 수 있습니다.
* **외부 메모리 대역폭(DRAM BW) 확장 시의 통찰**: 타겟 신경망 연산이 데이터 이동 비용에 종속된 전형적인 Memory-bound 상태일 때 외부 인터페이스 버스 폭을 늘려주면 시스템 병목 현상이 즉각 해소되어 **전체 하드웨어 End-to-End Latency가 정량 단축**됩니다.

## 7. 시뮬레이터의 태생적 한계 및 모델의 추상화 마진

모든 가상 성능 모델은 실리콘 현실의 효율적인 근사치(Approximation)입니다. 대규모 공간 탐색의 고속 연산 효율을 위해 본 시뮬레이터 모델에는 다음과 같은 마이크로아키텍처적 추상화 가정이 작용하고 있음을 명밀히 인지해야 합니다.

1. **오버랩 모델의 단순화**: 연산과 메모리 전송 간의 복잡한 물리 동기화 마진을 단순 `max()` 수식 펑션으로 이상적 오버랩 매핑 처리했습니다.
2. **SRAM 적재의 이진화**: 캐시 적재 적격 조건을 binary fit(온전히 다 들어가거나, 전혀 들어가지 못해 튕겨 나가거나) 모델로 추상화하여 미세 단편화 마진을 배제했습니다.
3. **네트워크 비용 미포함**: PE 가속 코어 간 하드웨어 상호 연결망인 NoC(Network-on-Chip)의 배선 지연 및 데이터 라우팅 타이밍 오버헤드가 산출 축에서 누락되어 있습니다.
4. **미시 병목 배제**: 물리 회로 레벨의 제어 파이프라인 실시간 스톨(Stall) 현상 및 SRAM 멀티 뱅크 충돌(Bank Conflict) 패널티를 고려하지 않는 수식 모델입니다.

따라서 본 도구는 나노초 단위의 하드웨어 물리 실측 절대치를 보장하기 위함이 아니라, **아키텍처 파라미터 가변 시 설계안 간의 우열을 가려내고 파레토 경계선을 식별해 내는 합리적인 시스템 수준 추정치**를 제공하는 도구로 정의됩니다.
