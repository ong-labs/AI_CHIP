# 02_memory_latency_assessment.md: Memory Hierarchy & Locality

이 문서는 메모리 계층 구조와 데이터 접근 패턴에 대한 이해도를 확인하기 위한 검증 문서입니다. [02_memory_subsystem.md](../analysis/02_memory_subsystem.md)에서 다룬 아키텍처 이론을 바탕으로 합니다.

## 개념 확인 문제 (Quiz)

### 문제 1. 최상위 메모리 계층
* **질문:** 메모리 계층에서 가장 빠르고 크기가 작은 것은?
* **정답: A. Register (레지스터)**
* **해설:** 레지스터는 CPU 코어 내부에 위치하여 프로세서 클럭과 동일한 속도로 접근 가능한 가장 빠른 저장 공간입니다.

### 문제 2. L1 캐시의 규모
* **질문:** L1 cache의 일반적인 크기 범위는?
* **정답: B. 32 KB ~ 64 KB**
* **해설:** L1 캐시는 속도를 위해 매우 작게 설계되며, 현대 CPU에서는 보통 코어당 32~64KB 수준의 용량을 가집니다.

### 문제 3. 데이터 전송 단위
* **질문:** 캐시 라인(cache line)의 일반적인 크기는?
* **정답: C. 64 byte**
* **해설:** CPU는 메모리에서 데이터를 가져올 때 효율성을 위해 64바이트 단위로 묶어서 가져오며, 이를 캐시 라인이라고 합니다.

### 문제 4. 공간 지역성 (Spatial Locality)
* **질문:** 공간 지역성의 의미로 옳은 것은?
* **정답: D. 인접한 메모리 주소의 데이터를 곧 사용할 가능성이 높다는 가정**
* **해설:** 특정 데이터에 접근했을 때 그 옆에 있는 데이터도 함께 캐시 라인에 실려 오기 때문에, 순차적 접근 시 성능이 향상됩니다.

### 문제 5. 시간 지역성 (Temporal Locality)
* **질문:** 시간 지역성의 의미로 옳은 것은?
* **정답: A. 최근 사용한 데이터를 곧 다시 사용할 가능성이 높다는 가정**
* **해설:** 한 번 접근한 데이터는 캐시에 머무르며, 가까운 미래에 다시 참조될 때 메모리까지 가지 않고 캐시에서 즉시 처리됩니다.

### 문제 6. NumPy의 메모리 배치
* **질문:** NumPy 배열의 기본 메모리 배치(C-contiguous)에서 연속적으로 저장되는 것은?
* **정답: B. 한 행(row)의 element들**
* **해설:** C-style(Row-major) 배치는 행 방향의 데이터들을 메모리상에 나란히 배치하여 행 단위 연산에 최적화되어 있습니다.

### 문제 7. 캐시 친화적 접근 패턴
* **질문:** C-contiguous 행렬에서 가장 캐시 친화적인(cache-friendly) 접근 패턴은?
* **정답: C. for i: for j: A[i, j] (행 우선)**
* **해설:** 메모리에 저장된 순서대로(행 방향) 데이터를 읽어야 캐시 적중률(Cache Hit Rate)이 높아지고 성능이 극대화됩니다.

### 문제 8. Pointer Chasing 실험의 의도
* **질문:** Pointer chasing 실험을 수행하는 목적은 무엇인가?
* **정답: D. prefetcher를 무력화하여 cache 위계의 순수 latency 측정**
* **해설:** 순차적 접근을 예측하여 미리 데이터를 가져오는 하드웨어 기능을 무력화함으로써, 각 캐시 단계의 실제 지연 시간을 정확히 측정할 수 있습니다.

### 문제 9. 캐시 미스(Cache Miss) 유발 패턴
* **질문:** 다음 중 Cache miss가 가장 자주 발생하는 접근 패턴은?
* **정답: A. 큰 stride로 띄엄띄엄 접근 (예: 매 1024번째 element)**
* **해설:** 캐시 라인 범위를 벗어나는 큰 간격으로 접근하면, 매번 새로운 데이터를 메모리에서 가져와야 하므로 성능이 급격히 저하됩니다.

### 문제 10. Python List vs NumPy Array
* **질문:** Python list of float이 NumPy ndarray보다 캐시 비친화적인 이유는?
* **정답: B. Python list는 객체 포인터의 배열이라 실제 데이터가 메모리에 흩어져 있음**
* **해설:** NumPy는 연속된 메모리 블록에 데이터를 저장하지만, Python 리스트는 각 원소가 메모리 곳곳에 흩어진 객체를 가리키는 포인터 구조여서 캐시 효율이 매우 낮습니다.
