# 01_performance.md: Fundamentals of Matrix Multiplication

이 문서는 [01_matmul_execution_report.md](../analysis/01_matmul_execution_report.md)에서 심층 분석한 행렬 곱셈(MatMul)의 실행 계층 이론과 성능 최적화 원리를 바탕으로 구성되었습니다. 실습을 통해 확인한 Python 루프와 NumPy 벡터화 연산의 성능 격차를 시스템 아키텍처 관점에서 재정리하고, 핵심 개념의 숙달도를 검증합니다.

## 개념 확인 문제 (Quiz)

### 문제 1. 시간 복잡도 vs 실제 성능
* **질문:** `matmul_loop`와 `A @ B`는 동일한 행렬 곱 연산이다. 다음 중 옳은 설명은?
* **정답: B. 두 방식 모두 시간 복잡도는 같지만 실행 계층이 달라 성능 차이가 난다**
* **해설:** 두 방식 모두 수학적으로는 $O(N^3)$의 복잡도를 가지지만, Python 루프는 인터프리터 레벨에서 느리게 실행됩니다. 반면 NumPy는 C 언어 기반의 벡터화 연산과 **SIMD**를 활용하여 하드웨어 자원을 극대화합니다.

### 문제 2. 병목의 위치
* **질문:** `matmul_loop`가 느린 가장 근본적인 이유는 무엇인가?
* **정답: C. 반복문이 Python 인터프리터 레벨에서 실행되기 때문**
* **해설:** Python 인터프리터는 코드를 한 줄씩 해석하며 동적 타입 체크를 수행하는 오버헤드가 큽니다. NumPy는 이를 컴파일된 기계어 레벨에서 처리하여 병목을 제거합니다.

### 문제 3. FLOPs 의미
* **질문:** 코드에서 `flops = 2 * N**3` 정의의 의미로 가장 적절한 것은?
* **정답: C. 이론적인 총 부동소수점 연산 수**
* **해설:** **FLOPs**는 Floating Point Operations의 약자로, 전체 연산량을 나타냅니다. 행렬 곱에서 각 원소는 곱셈과 덧셈을 한 쌍으로 수행하므로 $2 \times N^3$으로 계산합니다.

### 문제 4. GFLOPs 해석
* **질문:** 출력 결과가 `Loop: 0.5 GFLOPs`, `NumPy: 50 GFLOPs`로 나왔을 때, 이 결과의 의미로 가장 적절한 것은?
* **정답: B. NumPy가 동일한 연산을 훨씬 효율적으로 수행했다**
* **해설:** **GFLOPs**는 초당 처리하는 기가(10억) 단위의 연산량을 뜻하는 '처리량(Throughput)' 지표입니다. 위 결과는 NumPy가 하드웨어 연산 유닛을 Loop 방식보다 100배 더 효율적으로 활용하여 빠르게 작업을 끝냈음을 의미합니다.

### 문제 5. allclose의 역할
* **질문:** `np.allclose(C_loop, C_np, atol=1e-3)` 코드의 목적은?
* **정답: C. 두 결과가 수치적으로 유사한지 검증하기 위해**
* **해설:** 부동소수점 연산 시 하드웨어나 라이브러리 최적화 방식에 따라 미세한 오차가 발생할 수 있습니다. 이를 허용 오차(`atol`) 범위 내에서 비교하여 연산의 정확성을 확인합니다.

### 문제 6. 성능 개선 방향
* **질문:** 다음 중 성능을 더 개선하는 방향으로 옳은 것은?
* **정답: D. GPU 기반 라이브러리(PyTorch 등) 사용**
* **해설:** CPU의 SIMD보다 수천 개의 코어를 가진 GPU나 AI 전용 가속기인 **NPU**를 활용하는 것이 병렬 처리 효율 면에서 압도적입니다.
