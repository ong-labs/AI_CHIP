# 02_accelerator_mastery.md: Mastering Systolic Array & Weight-Stationary Dataflows

이 문서는 [02_systolic_array_trace.md](../analysis/02_systolic_array_trace.md)에서 다룬 하드웨어 매핑 논리와 [02_tpu_ws_systolic_bench.py](../lab/02_tpu_ws_systolic_bench.py) 실습을 통해 구현한 주기 정밀 시뮬레이터의 동작 원리를 검증합니다. 시스톨릭 어레이의 물리적 데이터 흐름을 코드로 해석하는 역량을 최종적으로 확인합니다.

## 📝 개념 확인 문제 (Quiz)

### 문제 1. `self.step(left)`의 가장 핵심적인 의미

* **질문:** `self.step(left)`이 시뮬레이션에서 담당하는 역할은 무엇인가?
* **정답: C. Systolic Array를 1 cycle 실행한다.**
* **해설:** `step()` 함수는 하드웨어의 한 클럭(Clock Cycle) 동안 발생하는 연산과 데이터 이동을 모델링하는 최소 단위입니다.

### 문제 2. `left` 변수의 역할

* **질문:** `left` 변수는 시뮬레이터 내부에서 무엇을 의미하는가?
* **정답: B. 이번 cycle에 왼쪽에서 주입할 입력 벡터**
* **해설:** 시스톨릭 어레이의 왼쪽 끝(PE[k, 0])으로 주입되는 입력 행렬 $A$의 요소들을 담은 열 벡터입니다.

### 문제 3. `bottom` 변수의 저장 내용

* **질문:** `bottom` 변수에는 어떤 정보가 담기는가?
* **정답: B. 맨 아래 행에서 출력된 결과 벡터**
* **해설:** 연산이 완료된 부분합(Partial Sum)이 어레이의 하단(PE[rows-1, n]) 밖으로 배출된 결과물입니다.

### 문제 4. `self`의 의미

* **질문:** 코드 내에서 `self`는 무엇을 지칭하는가?
* **정답: A. 현재 생성된 SystolicArray 객체 자신**
* **해설:** 파이썬 클래스 내에서 객체의 상태(weights, pe_input 등)에 접근하기 위한 인스턴스 참조 변수입니다.

### 문제 5. `step()` 함수의 시뮬레이션 범위

* **질문:** `step()` 함수 한 번 호출 시 몇 사이클이 진행되는가?
* **정답: B. 1 cycle**
* **해설:** 함수 내부의 `self.cycle += 1` 로직이 보여주듯, 단일 클럭 주기의 상태 변화를 시뮬레이션합니다.

### 문제 6. Weight-Stationary의 고정 데이터

* **질문:** Weight-Stationary 방식에서 PE 내부에 고정되어 재사용되는 데이터는?
* **정답: C. 가중치 행렬 B**
* **해설:** 가중치(Weight)를 레지스터에 고정하고 입력과 부분합을 흐르게 하여 메모리 읽기 비용을 줄이는 방식입니다.

### 문제 7. 입력 $A$의 이동 방향

* **질문:** 입력 데이터 $A$는 배열 내부에서 어느 방향으로 흐르는가?
* **정답: C. 왼쪽에서 오른쪽**
* **해설:** 입력 벡터는 매 사이클마다 `pe_input[:, 1:] = self.pe_input[:, :-1]` 로직에 의해 오른쪽 열로 시프트됩니다.

### 문제 8. Partial Sum의 이동 방향

* **질문:** 부분합(Partial Sum)은 어느 방향으로 전달되는가?
* **정답: B. 위에서 아래**
* **해설:** 계산된 결과 행렬은 `new_pe_ps_in[1:] = ps_out[:-1]` 로직을 통해 한 칸씩 아래 행으로 전달됩니다.

### 문제 9. PE의 기본 연산

* **질문:** 각 PE가 수행하는 가장 핵심적인 산술 연산은?
* **정답: C. 곱셈 후 부분합에 더하기 (MAC)**
* **해설:** 하드웨어의 MAC(Multiply-Accumulate) 유닛을 모사한 `ps_out = ps_in + in * weight` 연산입니다.

### 문제 10. PE에 고정되는 구체적 값

* **질문:** $4 \times 4$ 어레이에서 $PE(k, n)$에 고정되는 값은?
* **정답: A. B[k, n]**
* **해설:** 가중치 행렬 $B$의 원소들이 각 PE 위치에 일대일 매핑되어 고정(Stationary)됩니다.

### 문제 11. $4 \times 4$ 어레이의 PE 총수

* **질문:** $4 \times 4$ Systolic Array는 총 몇 개의 PE로 구성되는가?
* **정답: C. 16개**
* **해설:** 가로 4열, 세로 4행의 2차원 그리드 구조로 총 $4 \times 4 = 16$개의 연산기가 배치됩니다.

### 문제 12. `bottom` 출력의 시점별 의미

* **질문:** `bottom = self.step(left)` 실행 직후 반환되는 `bottom`의 의미는?
* **정답: A. 현재 cycle에 맨 아래 행에서 나온 출력 값들**
* **해설:** 해당 클럭 사이클에 파이프라인의 마지막 단계를 통과하여 배출된 부분합 벡터입니다.

### 문제 13. `self.cycle += 1`의 아키텍처적 의미

* **질문:** 이 코드 라인이 하드웨어적으로 의미하는 바는?
* **정답: B. Clock을 한 번 진행시킨다.**
* **해설:** 동기식 하드웨어에서 전역 클럭 신호가 한 번 발생하여 전체 시스템의 상태가 업데이트됨을 의미합니다.

### 문제 14. `np.zeros_like()`의 사용 목적

* **질문:** 코드에서 `np.zeros_like(self.pe_input)`를 사용하는 이유는?
* **정답: B. 기존 배열과 동일한 구조의 0 배열을 만든다.**
* **해설:** 데이터 시프트(Shift) 연산을 위해 다음 상태를 저장할 빈 버퍼를 원본과 동일한 Shape으로 생성하는 과정입니다.

### 문제 15. 초기 사이클에 유효 출력이 없는 이유

* **질문:** Cycle 0~3 구간에서 출력이 `0`인 이유는 무엇인가?
* **정답: C. 파이프라인이 아직 채워지지 않았기 때문 (Pipeline Fill)**
* **해설:** 입력 데이터가 PE 배열을 통과하여 하단에 도달하기까지 물리적인 시간이 필요하기 때문입니다.

### 문제 16. 파이프라인 안정화 이후의 현상

* **질문:** 파이프라인이 모두 채워진(Fill 완료) 후에는 어떤 현상이 발생하는가?
* **정답: B. 매 cycle마다 새로운 결과가 출력된다.**
* **해설:** 예열이 끝나면 매 사이클마다 새로운 결과 원소들이 배출되어 처리량(Throughput)이 극대화됩니다.

### 문제 17. `np.allclose()`의 검증 의미

* **질문:** `allclose(...) == True` 결과가 의미하는 바는?
* **정답: B. 결과가 NumPy와 거의 동일하다.**
* **해설:** 시스톨릭 어레이 시뮬레이터의 논리적 구현이 표준 행렬곱 연산 결과와 일치함을 증명합니다.

### 문제 18. 실제 하드웨어 사례

* **질문:** 시스톨릭 어레이 구조를 채택한 대표적인 상용 칩은?
* **정답: A. Google Tensor Processing Unit (TPU)**
* **해설:** Google의 TPU는 대규모 행렬 연산을 위해 시스톨릭 어레이 아키텍처를 성공적으로 상용화한 대표 사례입니다.

### 문제 19. `run()` 함수의 내부 동작

* **질문:** `run()` 함수는 전체 시뮬레이션을 위해 무엇을 반복적으로 호출하는가?
* **정답: B. `step()**`
* **해설:** 지정된 총 사이클($M+K+N$) 동안 `step()`을 반복 호출하여 시간에 따른 상태 변화를 완성합니다.

### 문제 20. 시스톨릭 어레이의 가장 적절한 비유

* **질문:** 시스톨릭 어레이의 동작 방식을 가장 잘 설명하는 비유는?
* **정답: B. 컨베이어 벨트를 한 칸 움직이는 것**
* **해설:** 데이터가 일정한 간격으로 인접 PE로 흐르며 작업을 수행하는 모습이 공장의 컨베이어 시스템과 유사합니다.

시스톨릭 어레이는 소프트웨어의 루프(Loop) 구조를 하드웨어의 평면(Plane)에 물리적으로 펼쳐 놓은 것입니다. 본 퀴즈를 통해 익힌 `step()` 단위의 사고방식은 이후 Verilog를 이용한 하드웨어 설계 단계에서 제어부(FSM)와 데이터 경로(Data Path)를 설계하는 데 가장 강력한 무기가 될 것입니다.
