# 04_performance_bottleneck.md: Mastering Hardware Performance & Roofline Analysis

이 문서는 실습을 통해 학습한 루프라인 모델(Roofline Model)과 메모리 비용 분석 결과를 바탕으로, AI 반도체 설계의 성능 병목 지점을 정량적으로 판단하는 역량을 검증합니다.

## 📝 개념 확인 문제 (Quiz)

### 문제 1. `matmul_loop`와 `A @ B`의 실행 차이
* **질문:** `matmul_loop`와 `A @ B`는 모두 행렬 곱셈을 수행합니다. 다음 중 옳은 설명은 무엇입니까?
* **정답: B. 두 방식 모두 시간 복잡도는 같지만 실행 계층이 다르다.**
* **해설:** 행렬곱의 알고리즘적 복잡도는 $O(N^3)$으로 동일하지만, NumPy의 `@` 연산은 C/C++ 레벨에서 SIMD 및 BLAS 라이브러리를 활용하여 실행되기에 Python 루프보다 압도적으로 빠릅니다.

### 문제 2. Python 인터프리터 오버헤드
* **질문:** Pure Python으로 작성한 삼중 반복문이 느린 가장 근본적인 이유는 무엇입니까?
* **정답: B. Python 인터프리터가 각 element를 해석하며 실행하기 때문**
* **해설:** Python은 동적 타이핑 언어로, 루프의 각 단계마다 객체의 타입을 확인하고 해석하는 과정에서 막대한 소프트웨어 오버헤드가 발생합니다.

### 문제 3. 이론적 연산량 계산
* **질문:** 다음 코드에서 `flops = 2 * N**3`이 의미하는 바는 무엇입니까?
* **정답: C. 이론적인 총 부동소수점 연산 수**
* **해설:** $N \times N$ 행렬곱에서 각 원소당 곱셈과 덧셈(2회 연산)이 $N^3$번 발생하므로, 전체 부동소수점 연산 횟수(FLOPs)를 나타냅니다.

### 문제 4. GFLOPs의 정의
* **질문:** GFLOPs(Giga-FLOPS)는 무엇을 나타내는 지표입니까?
* **정답: B. 초당 수행 가능한 부동소수점 연산 수**
* **해설:** 초당 $10^9$번의 부동소수점 연산을 수행하는 하드웨어의 '처리 능력' 혹은 '성능'을 의미합니다.

### 문제 5. 수치적 정합성 검증
* **질문:** `np.allclose(C_loop, C_np, atol=1e-3)` 코드의 목적은 무엇입니까?
* **정답: C. 두 결과가 수치적으로 거의 동일한지 검증**
* **해설:** 알고리즘 구현의 정확성을 확인하기 위해, 부동소수점 오차 범위(`atol`) 내에서 두 결과 행렬이 일치하는지 확인하는 과정입니다.

### 문제 6. 메모리 계층 구조의 속도
* **질문:** 다음 중 데이터 접근 속도가 가장 빠르고 저장 용량이 가장 작은 장치는 무엇입니까?
* **정답: A. Register**
* **해설:** CPU/NPU 코어 내부에 위치한 레지스터는 가장 빠른 접근 속도를 가지며, 용량당 비용이 가장 비싼 저장 장치입니다.

### 문제 7. 캐시 라인(Cache Line) 크기
* **질문:** 현대 CPU에서 일반적인 캐시 라인의 크기는 얼마입니까?
* **정답: C. 64 Byte**
* **해설:** 메모리에서 데이터를 가져올 때 효율성을 위해 한 번에 64바이트 단위로 묶어서 캐시로 전송합니다.

### 문제 8. 공간 지역성 (Spatial Locality)
* **질문:** 공간 지역성이 의미하는 하드웨어적 현상은 무엇입니까?
* **정답: B. 인접한 메모리 주소를 연속적으로 사용할 가능성이 높음**
* **해설:** 특정 주소에 접근했을 때 그 주변의 데이터도 곧 사용될 가능성이 높다는 원리로, 캐시 라인 효율의 근거가 됩니다.

### 문제 9. 시간 지역성 (Temporal Locality)
* **질문:** 시간 지역성이 의미하는 하드웨어적 현상은 무엇입니까?
* **정답: A. 최근 사용한 데이터를 곧 다시 사용할 가능성이 높음**
* **해설:** 한 번 사용한 데이터는 가까운 미래에 다시 참조될 가능성이 높으므로, 이를 캐시나 레지스터에 유지하여 성능을 높입니다.

### 문제 10. Cache-friendly 접근 방식
* **질문:** NumPy의 C-contiguous 배열(행 우선 저장)에서 가장 캐시 효율적인 접근 방식은?
* **정답: B. 행 우선 접근**
* **해설:** 메모리에 연속적으로 저장된 순서인 행(Row) 방향으로 데이터를 읽어야 캐시 미스(Miss)를 최소화할 수 있습니다.

### 문제 11. SIMD의 개념
* **질문:** SIMD(Single Instruction, Multiple Data)는 무엇을 의미합니까?
* **정답: B. 하나의 명령어로 여러 데이터를 동시에 처리**
* **해설:** CPU의 벡터 유닛을 사용하여 한 번의 명령어로 여러 부동소수점 데이터를 병렬로 연산하는 하드웨어 가속 기법입니다.

### 문제 12. FMA (Fused Multiply-Add)
* **질문:** FMA 연산이 2 FLOPs로 계산되는 이유는 무엇입니까?
* **정답: B. 곱셈과 덧셈을 동시에 수행하기 때문**
* **해설:** 곱셈 결과에 바로 누산하는 동작을 하나의 하드웨어 유닛에서 수행하여, 이론적으로 두 번의 연산을 한 번에 처리합니다.

### 문제 13. 산술 강도 (Arithmetic Intensity)
* **질문:** 산술 강도(AI)의 정의로 옳은 것은 무엇입니까? ($AI = FLOPs / Byte$)
* **정답: B. 데이터 1바이트당 수행되는 연산량**
* **해설:** 루프라인 모델의 X축에 해당하며, 하드웨어가 데이터를 한 번 읽어와서 얼마나 많은 연산을 수행하는지 나타내는 효율성 지표입니다.

### 문제 14. Memory Bound 작업
* **질문:** 다음 중 전형적인 메모리 병목(Memory Bound) 작업에 해당하는 것은?
* **정답: B. 배열 덧셈 (C = A + B)**
* **해설:** 연산량 대비 데이터 이동량이 매우 많아, CPU의 연산 속도보다 메모리 대역폭이 성능을 결정짓는 대표적인 케이스입니다.

### 문제 15. 루프라인 모델 (Roofline Model)
* **질문:** 루프라인 모델을 분석하는 가장 핵심적인 목적은 무엇입니까?
* **정답: B. 성능 병목이 계산인지 메모리인지 판단**
* **해설:** 특정 하드웨어에서 특정 워크로드를 실행할 때, 성능을 높이기 위해 연산기를 늘려야 할지 대역폭을 넓혀야 할지를 판단하는 가이드가 됩니다.

### 문제 16. Weight Stationary 데이터 고정
* **질문:** Weight Stationary 방식에서 PE 내부에 고정되어 재사용되는 데이터는 무엇입니까?
* **정답: B. 가중치 행렬 B**
* **해설:** 모델의 가중치를 PE 레지스터에 고정하고 입력 데이터만 흐르게 하여 가중치 로딩 비용을 최소화하는 전략입니다.

### 문제 17. Output Stationary 데이터 고정
* **질문:** Output Stationary 방식에서 PE 내부 레지스터에 유지되는 값은 무엇입니까?
* **정답: C. Partial Sum (부분합)**
* **해설:** 최종 결과값(부분합)을 PE 내부에서 누산하여 완성될 때까지 유지함으로써 결과값의 메모리 쓰기 횟수를 줄입니다.

### 문제 18. Input Stationary 데이터 고정
* **질문:** Input Stationary 방식에서 PE 내부에 고정되는 데이터는 무엇입니까?
* **정답: A. 입력 행렬 A**
* **해설:** 입력 데이터를 PE에 고정하고 가중치들을 흘려보내어, 동일 입력에 대해 다양한 결과를 얻어야 하는 GEMV 등의 연산에서 효율을 높입니다.

### 문제 19. PE의 핵심 산술 연산
* **질문:** 각 PE(Processing Element)가 수행하는 가장 기본적인 산술 연산은 무엇입니까?
* **정답: C. 곱셈 후 부분합에 누적 (MAC)**
* **해설:** 인공지능 연산의 본질인 MAC(Multiply-Accumulate) 연산으로, 행렬곱을 물리적으로 수행하는 단위입니다.

### 문제 20. Systolic Array 하드웨어 사례
* **질문:** 시스톨릭 어레이 구조를 성공적으로 채택한 대표적인 실제 하드웨어는 무엇입니까?
* **정답: D. Google Tensor Processing Unit (TPU)**
* **해설:** Google의 TPU는 시스톨릭 어레이 아키텍처를 기반으로 설계되어 대규모 행렬 연산에서 압도적인 가동 효율을 보여줍니다.
