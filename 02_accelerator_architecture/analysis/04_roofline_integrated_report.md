## 1. 전체 목적

본 분석 코드는 다음 세 가지 핵심 요소를 동시에 시뮬레이션합니다.

* 각 하드웨어의 이론적 성능 특성 정의

이를 통해 ‘워크로드의 크기와 특성에 따라 최적의 하드웨어가 어떻게 달라지는가?’를 정확히 예측하는 데 목적이 있습니다.

## 2. Roofline Model 복습

루프라인 모델의 핵심 식은 다음과 같이 정의됩니다.

$$T = \max\left(\frac{F}{P_{peak}}, \frac{B}{BW_{peak}}\right) + T_{overhead}$$

* **$F$**: 총 연산량 (FLOPs)
* **$P_{peak}$**: 하드웨어의 최대 연산 성능
* **$B$**: 실제 메모리 이동량 (Bytes)
* **$BW_{peak}$**: 하드웨어의 최대 메모리 대역폭
* **$T_{overhead}$**: 커널 실행 및 디스패치 오버헤드

| **overhead_us** | 커널 실행 오버헤드 (Microseconds) |

## 4. TPU v4 설정 및 워크로드 정의

### 4.1 TPU v4 상세 사양

TPU는 대규모 행렬 곱셈을 위해 설계된 전용 **Systolic Array** 구조를 사용합니다.

* **설정**: `HW("TPU v4 (BF16)", "bf16", 275e12, 1200e9, 128, 2, 20.0)`
* **의미**:
  * **275 TFLOPS**: BF16 기준 연산 성능
  * **1.2 TB/s**: 고대역폭 메모리(HBM) 성능
  * **높은 재사용률(128)**: 시스톨릭 구조의 특성 반영
  * **20 μs 오버헤드**: 대규모 연산에 최적화된 오버헤드 설정

### 4.2 분석용 워크로드 (Workloads)

작은 연산부터 초대형 언어 모델 워크로드까지 5가지 케이스를 분석합니다.

| 이름 | 형태 ($M \times K \times N$) | 의미 |
| --- | --- | --- |
| **W1 Tiny** | $32 \times 32 \times 32$ | 매우 작은 연산 (Edge case) |
| **W2 LLM single** | $1 \times 4096 \times 4096$ | 배치 1 추론 (GEMV 성격) |
| **W3 LLM batched** | $256 \times 4096 \times 4096$ | 대규모 GEMM 연산 |
| **W4 Large** | $4096^3$ | 초대형 밀집 행렬 연산 |
| **W5 Attention** | $1024 \times 128 \times 1024$ | K 차원이 작은 비정형 연산 |

## 5. 핵심 연산 로직 분석

### 5.1 연산량 ($F$) 및 실질 재사용률 (`Effective Reuse`)

* **FLOPs**: 행렬 곱셈 시 각 원소당 K번의 곱셈-덧셈(MAC)이 발생하므로 $F = 2MKN$으로 계산합니다.
* **Effective Reuse**: 작은 워크로드에서는 하드웨어 유닛을 충분히 채우지 못해 재사용 효율이 감소합니다.
* `eff = base_reuse * min(smallest_dim, 256) / 256` 로직을 통해 문제 크기가 작을수록 재사용 효과를 패널티로 부여합니다.

### 5.2 실제 메모리 이동량 및 병목 판정

* **Memory Traffic**: 재사용률이 높을수록 동일 데이터를 여러 번 활용하여 DRAM 트래픽이 감소합니다.
* `bytes_actual = (m*k + k*n + m*n) * dtype_bytes / reuse`

* **병목 판정 조건**:
* $t_c > t_m$: **Compute-bound** (연산 성능이 지배적)
* $t_m > t_c$: **Memory-bound** (대역폭이 지배적)
* $T_{overhead} \gg \max(t_c, t_m)$: **Overhead-bound** (실행 오버헤드가 지배적)

## 7. 핵심 통찰 및 분석 (Detailed Insights)

### 7.1 주요 성능 변곡점 분석

1. **Overhead의 지배 (W1 Tiny)**:
* W1 워크로드는 연산량이 매우 적어 모든 하드웨어에서 **Overhead-bound(o)** 특성을 보입니다.
* 커널 실행 오버헤드가 가장 낮은 CPU(0.5us)가 고성능 가속기들을 제치고 가장 빠른 성능을 보여줍니다. 이는 작은 규모의 연산에서는 가속기로 데이터를 전송하고 명령을 내리는 시간보다 CPU가 직접 계산하는 것이 유리함을 의미합니다.

2. **Memory Wall의 체감 (W2 LLM single)**:
* Batch=1인 GEMV 성격의 연산은 모든 기기에서 Memory-bound(m)로 나타납니다.
* 최대 대역폭(3,350 GB/s)을 가진 **H100**이 가장 빠르지만, 연산 위주의 대규모 워크로드에 비해 Speedup 폭(18.7x)은 상대적으로 제한적입니다.

3. **가속기의 압도적 성능 (W3, W4)**:
* 워크로드 규모가 커짐에 따라 **Compute-bound(c)** 영역으로 이동하며, 가속기들의 Peak 성능이 실질적인 처리량으로 연결됩니다.
* 특히 W4 Large 워크로드에서 **H100**은 CPU 대비 **311.7배**라는 경이로운 가속 성능을 보이며 전용 하드웨어의 가치를 증명합니다.

4. **비정형 연산의 특성 (W5 Attention)**:
* 연산량이 많지 않은 W5 케이스에서는 고성능 GPU들도 다시 **Overhead-bound**에 인접하거나 진입하는 경향을 보입니다.

### 7.2 결론 (Final Summary)

시뮬레이션 데이터는 "어떤 하드웨어가 최고인가?"라는 질문에 대한 답이 워크로드의 성격에 따라 극명하게 갈린다는 점을 수치로 보여줍니다.

* **초소형 연산**: 오버헤드가 적은 **CPU**가 효율적입니다.
* **추론(Inference)**: 메모리 대역폭이 우수한 **H100**이 유리하나 가동률은 떨어집니다.
* **대규모 학습/GEMM**: 압도적인 Peak FLOPS를 가진 **H100 및 TPU**가 최적의 선택입니다.

> H100은 순수 성능에서 압도적이나, TPU v4는 시스톨릭 어레이의 고효율성을 바탕으로 대규모 클러스터(Pod) 구성 시 가중치 재사용률을 극대화하여 **TCO(총 소유 비용) 관점**에서 최적의 가치를 제공합니다.

본 리포트의 Roofline Model 분석을 통해 워크로드의 특성($M, K, N$)에 맞춰 최적의 아키텍처를 선택하거나 설계할 수 있는 정량적 근거를 확보하였습니다.
