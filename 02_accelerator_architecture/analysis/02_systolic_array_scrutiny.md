# 02_systolic_array_scrutiny.md: Detailed Operational Breakdown of Systolic Array

본 문서는 [02_systolic_array_report.md](./02_systolic_array_report.md)에서 도출된 정량적 지표를 바탕으로, $4 \times 4$ **Systolic Array**의 내부 동작을 사이클 단위로 정밀 분석합니다. **리포트에서 확인된 타이밍 지표가 하드웨어 내부에서 어떻게 대각선 형태(Wavefront)로 구현되는지 규명함으로써, [02_systolic_array_trace.md](./02_systolic_array_trace.md)에서 다룰 실질적 설계 사양의 근거를 제시합니다.**

---

## 1. 연산 정의 및 기본 규칙

### 1.1 연산 모델

다음과 같은 $4 \times 4$ 행렬곱 식을 계산한다고 가정합니다.

$$C_{m,n} = \sum_{k=0}^{3} A_{m,k} B_{k,n}$$

### 1.2 데이터 흐름 규칙 (Weight-Stationary)

* **가중치 ($B[k,n]$)**: 각 PE(Processing Element) 내부에 고정되어 연산이 끝날 때까지 머무릅니다.
* **입력 ($A[m,k]$)**: 왼쪽에서 주입되어 매 사이클마다 오른쪽 PE로 이동합니다.
* **부분합 (Partial Sum)**: 위에서 아래 방향으로 이동하며, 각 PE를 통과할 때마다 $Input \times Weight$ 값이 누적됩니다.

> **💡 Architecture Note: Weight Setup Phase**
> 실제 WS(Weight-Stationary) 하드웨어 아키텍처에서는 본 연산 시작 전, 외부 메모리(DRAM/SRAM)로부터 가중치를 읽어와 각 PE 레지스터에 채우는 **Setup Phase(Pre-loading)** 사이클이 반드시 선행되어야 합니다. 본 시뮬레이션 코드(`load_weights`)는 알고리즘의 핵심 로직 분석을 위해 이 과정을 추상화하여 구현하였습니다.

---

## 2. 하드웨어 구조 및 PE 배치

$4 \times 4$ 배열 내에서 각 가중치 데이터는 다음과 같이 물리적으로 고정 배치됩니다.

|  | Col 0 | Col 1 | Col 2 | Col 3 |
| --- | --- | --- | --- | --- |
| **Row 0** | PE(0,0)=B[0,0] | PE(0,1)=B[0,1] | PE(0,2)=B[0,2] | PE(0,3)=B[0,3] |
| **Row 1** | PE(1,0)=B[1,0] | PE(1,1)=B[1,1] | PE(1,2)=B[1,2] | PE(1,3)=B[1,3] |
| **Row 2** | PE(2,0)=B[2,0] | PE(2,1)=B[2,1] | PE(2,2)=B[2,2] | PE(2,3)=B[2,3] |
| **Row 3** | PE(3,0)=B[3,0] | PE(3,1)=B[3,1] | PE(3,2)=B[3,2] | PE(3,3)=B[3,3] |

## 3. 사이클별 동작 상세 (Cycle-by-Cycle Breakdown)

데이터가 파이프라인에 채워지고(Fill), 연산이 수행되며, 비워지는(Drain) 과정을 사이클 단위로 추적합니다.

### 3.1 파이프라인 유입 및 연산 준비

* **Cycle 0**: 입력 $A[0,0]$ 주입 시작.
* **Cycle 1**: 입력 $A[1,0], A[0,1]$ 주입.
* **Cycle 2**: 입력 $A[2,0], A[1,1], A[0,2]$ 주입.
* **Cycle 3**: 입력 $A[3,0], A[2,1], A[1,2], A[0,3]$ 주입. (가장 많은 입력이 주입되는 구간)

### 3.2 유효 결과 생성 및 배출

* **Cycle 4**: **$C[0,0]$ 첫 출력 생성.** (입력 $A[3,1], A[2,2], A[1,3]$ 주입)
* **Cycle 5**: $C[1,0], C[0,1]$ 출력.
* **Cycle 6**: $C[2,0], C[1,1], C[0,2]$ 출력.
* **Cycle 7**: $C[3,0], C[2,1], C[1,2], C[0,3]$ 출력. (최대 출력 구간)

### 3.3 파이프라인 드레인 (Drain)

* **Cycle 8**: $C[3,1], C[2,2], C[1,3]$ 출력.
* **Cycle 9**: $C[3,2], C[2,3]$ 출력.
* **Cycle 10**: **$C[3,3]$ 마지막 결과 생성.**
* **Cycle 11**: 파이프라인 완전 비움 (Flush 완료).

---

## 4. 삼각형 형태의 데이터 전파 (Wavefront)

데이터는 배열을 직선으로 통과하는 것이 아니라 대각선 형태의 **Wavefront**를 형성하며 이동합니다.

* **입력 주입 패턴**: 1 → 2 → 3 → 4 → 3 → 2 → 1 (사이클별 주입 개수)
* **출력 생성 패턴**: 1 → 2 → 3 → 4 → 3 → 2 → 1 (사이클별 생성 개수)
* **의미**: 입력과 출력이 모두 삼각형 형태의 Wavefront를 그리며 배열을 통과하며, 이는 하드웨어 리소스를 단계적으로 활성화하여 전력 피크를 분산시키고 병렬성을 극대화하는 효과를 가집니다.

삼각형 형태의 Wavefront 주입은 하드웨어 리소스를 단계적으로 활성화합니다. 이는 모든 PE가 동시에 켜질 때 발생하는 급격한 전력 피크(dV/dt)를 방지하여 **Power Integrity**(전력 무결성)를 개선하는 중요한 물리적 이점을 제공합니다. 또한, Fill/Drain 단계의 낮은 효율을 극복하기 위해 실제 NPU 아키텍처에서는 **Tiling(타일링)** 기법을 적용하여 파이프라인 가동률을 극대화합니다.

## 5. 연산 주기 및 가동 효율 정량화 (Quantification of Execution Cycles & Operational Efficiency)

본 시뮬레이션 데이터를 바탕으로 Weight-Stationary 시스톨릭 어레이의 시간적 성능과 하드웨어 자원 활용도를 분석합니다.

### 5.1 총 Cycle 수 및 성능 분석

하드웨어 연산 시간을 결정하는 주요 지표는 다음과 같습니다.

1. **유효 결과 생성 기간**: $M + K + N - 1 = 11\ cycles$ ($4 \times 4 \times 4$ 행렬곱 기준 실제 연산이 수행되는 핵심 구간).
2. **전체 코드 실행 사이클**: **12 cycles** (연산 종료 후 내부 데이터를 완전히 비우는 마지막 Flush 사이클 포함).

### 5.2 실질 활용률(Effective Utilization) 및 확장성 분석

아키텍처의 가동 효율성은 전체 실행 시간 대비 유효 연산 시간의 비율로 결정됩니다.

* **시간 효율성**: 전체 12사이클 중 이론적으로 유효한 결과가 생성되는 11사이클을 고려할 때, 본 시스톨릭 어레이 연산의 시간 효율성은 약 91.6%로 계산됩니다.
* **아키텍처 스케일링 효율**: 행렬의 크기($M, K, N$)가 커질수록 전체 사이클에서 파이프라인 예열(Fill) 및 냉각(Drain) 시간이 차지하는 비중이 상대적으로 줄어듭니다. 이는 대규모 워크로드로 갈수록 **활용률이 점진적으로 100%에 수렴**함을 의미하며, 본 아키텍처가 거대 언어 모델(LLM)과 같은 대형 연산에서 압도적인 효율을 발휘하는 근거가 됩니다.

---

## 6. 요약 및 통찰

$4 \times 4$ Weight-Stationary 시스톨릭 어레이의 동작을 분석한 결과, **Cycle 4**에서 첫 결과 $C[0,0]$이 생성되기 시작하여 대각선 Wavefront 형태로 결과가 퍼져 나감을 확인하였습니다. 최종적으로 **Cycle 10**에서 마지막 결과 $C[3,3]$이 배출되며 연산이 종료됩니다.

이러한 정밀한 타이밍 분석은 향후 Verilog와 같은 하드웨어 기술 언어를 통해 실제 NPU를 설계할 때 **Control Logic**과 **Data Path**의 동기화를 맞추는 데 있어 결정적인 근거가 됩니다.

이 분석 데이터를 바탕으로 [02_tpu_ws_systolic_bench.py](../lab/02_tpu_ws_systolic_bench.py) 코드의 Trace 로그와 비교하여 시뮬레이션의 정합성을 최종 검증할 수 있습니다.

## 💡 참고 사항 (Notes)
* **메모리 벽(Memory Wall) 문제**: 본 시뮬레이션은 이상적인 데이터 공급을 가정하지만, 실제 SoC 환경에서는 **글로벌 버퍼(SRAM)의 대역폭**이 PE 연산 속도를 따라가지 못해 파이프라인이 멈추는(Stall) 상황이 빈번합니다. 따라서 고성능 NPU 설계 시에는 연산기 자체보다 데이터를 끊김 없이 공급하기 위한 **더블 버퍼링(Double Buffering)** 및 **뱅크 인터리빙(Bank Interleaving)** 설계가 더 높은 비중을 차지하게 됩니다.
* **Wavefront 전파**는 단순한 데이터 흐름이 아니라, 전력 피크를 분산시켜 칩의 안정성을 높이는 **Power Integrity** 설계의 핵심 전략입니다.
* 대규모 행렬 연산 시의 활용률 상승 지표는 본 아키텍처의 확장성(Scalability)을 증명하는 결정적 근거입니다.
